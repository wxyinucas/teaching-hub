# 通用备课系统：迁移入口

本页供新课程或新任务快速理解备课方法；具体课程内容不得从案例中直接继承。

## 核心共识

- 每门课程先声明自己的完整备课与放行单位；它可以是一次完整授课，也可以是一个教学周。单位内部的课次与课时只是可以临场调整的软检查点。
- 每个备课单位先确定一个根问题、最低出口和硬收口，再选择内容与材料。
- 台本 80% 用于课前规划与放行，20% 用作课中的决策指南针。
- 台本是内容源；Slides 与 Guide 是否需要、面向谁以及承担什么职责，由课程契约声明。Draft 只接住尚未进入台本的临时想法。
- 主线只安排可用时间的约 80%；担心内容不足时准备 Plan B，不继续向主线加料。

## 协作与冻结

1. 先写台本工作版；可在对应段落暂存 `to gpt`、待讨论问题和派生材料提示。
2. 主线、顺序和收口敲定后，再从台本生成所需的 Slides 与 Guide；内容变化先回写台本。
3. 派生材料完成后删除已消费的制作提示。课堂冻结版每一行只属于两类：真正的课前核验，或台上可直接使用的提示。
4. 一个推进段需要 Slides 时，第一张 Slide 与台本推进段使用同一标题；后续辅助页可以使用自己的标题。

## 课前放行

内容只问：**能否讲得出、做得出、收得住？** 文件只问：**是否每一行都拿得上台？** 任一答案是否定的，本备课单位不放行。

## 迁移方法

1. 阅读当前的[模板说明](../terms/2026-fall/templates/README.md)与[台本模板](../terms/2026-fall/templates/runbook-template.md)。
2. 先写目标课程的现实条件、备课单位与材料契约，再按“台本工作版 → 派生材料 → 清理台本 → 课堂冻结版”推进。
3. 案例只用于观察结构和完成度，不把其学科内容当作规则。

## 不自动迁移

备课单位、课时数量、学生起点、讲授与实践方式、材料职责、评价证据、风险和 Plan B 均须按新课程重新决定；WSL、Git、Agent、测试与量化等只是 AI Agents 课程的特例。

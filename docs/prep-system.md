# 通用备课系统：迁移入口

本页供新课程或新任务快速理解备课方法；具体课程内容不得从案例中直接继承。

## 核心共识

- 一次完整授课是严格备课单位；其中各课时只是可以临场调整的软检查点。
- 每次课先确定一个根问题、最低出口和硬收口，再选择内容与材料。
- 台本 80% 用于课前规划与放行，20% 用作课中的决策指南针。
- Slides 是课堂舞台，只展示全班必须共同观看的内容；Guide 承载学生需要独立执行、核验或课后接续的内容；Draft 只接住临时想法。
- 主线只安排可用时间的约 80%；担心内容不足时准备 Plan B，不继续向主线加料。

## 课前放行

只问三个问题：**我是否讲得清、做得出、收得住？** 任一答案是否定的，本次备课不放行。

## 迁移方法

1. 阅读当前的[模板说明](../terms/2026-fall/templates/README.md)与[台本模板](../terms/2026-fall/templates/runbook-template.md)。
2. 先写目标课程的现实条件，再写第一份台本；冻结台本后才制作 Slides 与 Guide。
3. 案例只用于观察结构和完成度，不把其学科内容当作规则。

## 不自动迁移

课时数量、学生起点、讲授与实践方式、评价证据、风险和 Plan B 均须按新课程重新决定；WSL、Git、Agent、测试与量化等只是 AI Agents 课程的特例。

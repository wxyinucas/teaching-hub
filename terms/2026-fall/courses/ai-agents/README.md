# AI Agents

本课程不以系统教授统计理论为目标，而是用量化程序提供一个会产生外部反馈的练习场。学生可以让 Agent 完成实现，但必须能够提出规格、设计证据、判断证据，并为最终产物的安全、合规与适用边界负责。

- `course-design/`：课程定位、16 周蓝图、学生证据契约与平台决策。
- [`template.md`](./template.md)：按 topic 整理 Agent 实验、问题与协作记录的交流模板；需要通过文件沟通时使用，不是周报告，也不要求上传。网站入口放在 W1 卡片，读取课程根目录的同一文件，全学期通用。
- [课程代码仓库](https://github.com/wxyinucas/ai-agents)：唯一的当前代码入口。`week-02/`～`week-09/` 分别保存独立周任务、环境、测试与参考；`project/` 留给后续持续演化的项目，内部结构随任务确定。根目录只作导航。
- 新克隆示例使用 `~/course/ai-agents`；已有 `~/course/w02-workbench` 可以继续使用，只替换材料中的仓库路径前缀。W2 的运行文件现位于 `week-02/`；已有签名和提交的迁移步骤见代码仓库 README。
- 旧 `ai-agents-project` 退出当前教学流程；可复用的历史材料整理在代码仓库 `legacy/market-lab/`，不作为当周任务或新项目基线。
- `weeks/`：按周冻结 `week.json`、`draft.md`、`runbook.md`、`slides.md` 与 `guide.md`；不再建立职责含混的 `resources/`。

当前以[16 周课程蓝图](./course-design/16-week-blueprint.md)为准：W1～W3 建立工作台与 Agent；W4～W8 通过编程实验与综合项目建立基础；W9 完成 Longbridge 接入、行情批次、校验与描述性分析；W10～W15 依次占位目标持仓、历史回放、模拟执行、核对维护、单因素修改与再次运行，W16 核验个人证据。约 30 名学生，其中不少是数学专业研究生；课程仍按无编程基础、无助教设计。Longbridge 交易接口与授权路线须在对应周次前实测。旧版[蓝图](./course-design/16-week-blueprint-v1.md)仅供追溯。

编程阶段的概念、语言边界和探索任务契约见[W4～W10 专项设计](./course-design/w4-w9-progressive-programming-system.md)。学生需要掌握 Python、了解 R 与 Bash；Rust 和 C 只在特定场景由教师展示，不要求学生安装工具链或本地编译执行。跨语言对照围绕同一概念，比较形式、实际行为、共同结构与设计取舍。教师提供简单可恢复的环境、少量 Agent Prompt 和明确验收条件，学生与 Agent 先写能拒绝错误的测试，再实现或操作、核验证据并解释结果。测试从 W4 贯穿，不再以逐周给同一行情程序增加功能作为固定课表；练习是否接续及持续系统何时启用，由各周任务明确。

`course.json.weekMap` 展示完整 16 周课程地图；地图条目不承担开放状态，也不登记资源。W1～W9 已有台本、Slides 与 Guide；W9 配套合成数据、公开测试与教师参考实现位于课程练习仓库 `week-09/`。W10～W15 只占位主题和产物，后续先敲定台本，再制作所需派生材料；不预先生成空目录。

学生证据随任务阶段递进：W1 是环境状态与命令输出；项目出现后加入可复现命令、测试、diff 与 Git 记录；后续再接入数据契约、平台对账、版本冻结与个人责任核验。每一层只在课程真正需要它时引入。

版本路线保持单一：W3 发布时保留当前 Git 历史，将教师 remote 保留为 `upstream`，个人 remote 设为 `origin`，上传包含 W2 与 W3 的同一仓库；不因这次目录调整重新 clone、建立学生编号目录或增加 PR 要求。持续项目仍在这份仓库的 `project/` 中维护，普通周更新个人 `origin/main`，不使用 `dev-week-*` 分支。branch／push 与 merge 可以在设计好的实验仓库中探索，push 使用模拟远端；这些实验不自动改变正式提交路线。具体汇总节点随各周任务设计确定。

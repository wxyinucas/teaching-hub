# AI 辅助编程与量化实践：16 周课程蓝图（v3）

> 状态：当前课程目录。2026-10-14 确认 W4～W10 的概念与自由探索框架，周次与语言边界按本版执行；各周实验接口、材料与课时细节继续在当周台本中编排。W1～W3 保持已成稿的教学任务，W11～W16 保持既有量化闭环与个人核验安排。W4 runbook 已围绕两次原始记录污染重排为工作版，现有 Slides／Guide 对应上一版，实际实验包待落实；W10 仍待按新框架细化。Longbridge 授课前须按平台现状复测。[v1 蓝图](./16-week-blueprint-v1.md)仅供追溯。
>
> 现实条件：16 周，每周 3 × 50 分钟；约 30 名学生，其中不少是数学专业研究生；不预设编程基础，无助教。Agent 可以编写代码，学生负责提出目标、预测行为、核验证据和接受结果。

## 1. 新课程终点

课程前半段建立程序运行与诊断的心智模型，后半段只完成一次小而完整的量化实践：

> 从网络取得有明确时间边界的数据 → 一个可替换的决策模型产生目标持仓 → 教师提供的公共设施执行风控并向 Longbridge 模拟账户提交受控订单 → 核对成交与账户变化 → 依据市场反馈只调整一个因素 → 再运行并比较两次证据。

这里的“模型”可以是简单的确定性规则，不要求机器学习、算法比较或收益优化。模拟盘的实际成交与持仓／资金变化是正常路线的预期结果；收到订单编号不等于成交，必须另查订单状态和账户。平台受阻时可用同构 replay 继续学习，但须如实标注，不能称为本人模拟账户成交。收益与亏损都不证明模型正确或错误。

学生无需手写大量代码，但须能沿具体输入追踪变量、函数、错误、测试和实际行动，并解释自己接受或拒绝 Agent 产物的理由。期末不以正式 presentation 或长时间讨论作为必修产物。

## 2. 周次结构

| 周次 | 阶段 | 阶段出口 |
| --- | --- | --- |
| W1～W3 | 工作台与 Agent | WSL、VS Code、Git、uv 与 API Agent 可用；在独立报告项目中完成实验、公开测试、PDF 与 Git 发布，并核对实际结果。 |
| W4～W9 | 概念与自由探索 | 每周围绕一个核心概念，通过小实验、跨语言对照和较大的自由探索，掌握 Python 基础并形成先测试、后实现、再核验解释的习惯。 |
| W10 | 编程基础与外部服务的衔接 | 理解外部接口与数据边界，从固定模拟响应接到真实只读数据，保留最小授权、真实响应、撤销与退出的证据。 |
| W11～W15 | 一次量化实践闭环 | 真实数据进入模型，模型经公共风控作用于模拟账户；观察反馈、只改一处并再次运行。 |
| W16 | 冻结与个人证据核验 | 固定最终版本和两轮证据，独立说明主张、实际结果、一次调整及未解决的问题；不安排正式展示。 |

## 3. W4～W10｜以概念为基石的编程入门

每周以一个核心概念为基石，用一个具体矛盾贯穿课堂：先预测并操作，让实际结果挑战预期；再用小实验、反例与跨语言对照区分解释、检验修复；最后把尚未兑现的承诺交给较大的自由探索。每个例子都要推动下一步，概念在解释问题时出场。名字与对象、容器、映射、函数、模块、失败与外部接口形成递进关系；分支、循环、文件读写等支撑知识按当周需要引入。

学生需要掌握 Python、了解 R 与 Bash。跨语言对照围绕同一概念，比较形式、实际行为、共同结构、不同语言强调的重点及其取舍；Rust 和 C 只在特定场景由教师展示，不要求学生安装工具链或本地编译执行。解释执行与编译执行只是一个具体知识点，当前放在 W4 的可选 C 展示中，不承担七周的组织主线。

教师提供简单可恢复的实验环境、少量用于提示 Agent 的 Prompt 和明确验收条件。学生与 Agent 先写能拒绝错误的测试，再实现或执行操作，核对实际产物并解释证据。测试从 W4 开始贯穿；Git 类题可以使用仓库状态检查脚本以及文件、提交历史与模拟远端的核验。

| 周次 | 核心概念与中心问题 | 自由探索题型 | 验收方向 |
| --- | --- | --- | --- |
| W4 | 名字、对象与可变性：赋值以后，究竟改了名字的指向、对象的内容，还是两者都改了？凭什么判断？ | 生成修改后的独立分析方案，保留原始记录，并在实验分支保存、push 到模拟远端。 | 修改结果符合规格；原始内容保持；需要隔离的容器身份不同；后续修改与两次结果互不干扰；分支和远端状态可核验。 |
| W5 | 容器与迭代：一组数据怎样存放、逐项取出？ | 编写序列摘要工具，比较容器与迭代器输入。 | 空集合、单条、多条都有明确结果；能解释遍历顺序与迭代器的消耗状态。 |
| W6 | 键值对与映射：怎样依据一个键找到、增加或更新信息？ | 编写记录查询与更新工具。 | 重复键、缺失键、更新已有键的规则明确；另一份符合规格的输入也通过检查。 |
| W7 | 函数与变量可见性：数据怎样进入函数，名字在哪里有效？ | 把已有程序拆成可独立测试的函数。 | 外部行为保持一致；参数与返回值清楚；多次调用没有意外干扰。 |
| W8 | 模块组织与加载：多个文件怎样共同组成程序？ | 将程序拆成模块，并 merge 两个分支的改动。 | 入口可运行；导入不会意外启动主任务；两边要求和原有测试都保留。 |
| W9 | 异常与失败边界：无法完成工作时，程序怎样表达失败？ | 修复一组故障案例。 | 测试先能暴露故障，修复后通过；正常行为保留，失败信息明确。 |
| W10 | 外部接口与数据边界：外部结果怎样成为程序可用的输入？ | 从固定模拟响应接到真实只读数据。 | 正常、缺字段、调用失败均有检查；数据来源变化后，核心处理结果仍符合规格。 |

以上敲定概念顺序、探索题型与验收方向。具体输入输出、测试接口、Prompt、实验初始状态、仓库路径和提交材料随各周台本明确。W10 保留 Longbridge 模拟环境与真实只读行情方向；固定响应实验与账号、授权、调用、撤销等接续环节的时间分配，留到该周细化时讨论。

三课时连续推进同一矛盾，课时只是软检查点，整周是完整备课与放行单位。现场操作、真实输出和随调查更新的关系图为主，Slides 为辅；先敲定 runbook 的主线、顺序与收口，再制作所需派生材料。主线容量与冻结方法以[通用备课系统](../../../../../docs/prep-system.md)为准。

当前 W3 是独立的 Agent 实验报告，不负责建立行情系统。练习是否接续、正式持续系统何时建立及其与 W3 的接续方式由当周任务明确；已有行情基线与工程材料继续保留，作为可选素材，不再以每周为同一行情程序增加功能作为固定课表。专项的语言对照、探索合同与材料职责见[W4～W10：概念与自由探索](./w4-w9-progressive-programming-system.md)。

学生中有较多数学专业研究生，可以用函数、映射、不变量和反例连接已有经验；全班共用一个最低出口，先完成短程序的预测与核验。进度快者增加反例、边界测试或跨语言观察。约 30 人且无助教，课堂优先处理共性问题，个人设备受阻时保留可接续的真实状态。

## 4. W10～W15｜仅做一次量化闭环

| 周次 | 唯一增量 | 本周留下的事实 |
| --- | --- | --- |
| W10 | 以外部接口与数据边界为中心，从固定模拟响应接续到 Longbridge 真实只读历史数据。 | 正常、缺字段与调用失败的测试；本人注册、最小只读授权、固定调用、撤销／退出，以及数据来源与查询时间。原始响应不公开，平台细节须按届时状态复测；实验与平台环节的时间分配待当周细编。 |
| W11 | 让一个最简单的决策模型读取有时间边界的数据并输出目标持仓。 | 统一数据格式、决策时点、模型输入输出、正常与错误测试；模型不能读取决策时点之后的信息。算法可以使用参考实现。 |
| W12 | 把目标持仓接入公共资金、订单与风控设施，争取完成第一次受控模拟成交。 | 事前目标、风险检查、人工确认、模拟订单编号、成交状态及账户前后快照。公共提交器必须与学生可写代码隔离，只允许 paper；不把下单请求成功冒充成交。 |
| W13 | 观察市场和账户反馈，区分程序行为与市场结果。 | 第一轮模型预期、实际订单／持仓／资金及价格变化；至少两种可能解释和仍缺少的证据。不因一次盈亏直接认定模型优劣。 |
| W14 | 只调整模型或配置中的一个因素，并在再次行动前冻结理由和测试。 | 一项可审查的 diff、调整前预测、保持不变的风险边界、离线测试与第二次行动计划；不开展算法竞赛。 |
| W15 | 在模拟盘运行调整后的版本，比较两轮结果。 | 第二轮订单与账户证据、两轮对照、意外事件及尚未排除的解释；对最终模型版本及其证据作出 `ACCEPT / HOLD / BLOCKED`。没有新的大型功能或第三种策略。 |

正常路线以模拟账户的实际成交和可归因的持仓／资金变化为目标。[Longbridge 官方交易 FAQ](https://open.longbridge.com/docs/qa/trade)说明模拟市价单默认撮合，但市场时段、购买力和权限仍须检查。提交之前由教师在自己的 Demo 账户上实测标的、交易时段、可买数量、权限、订单状态查询和账户核对；W10 的只读授权不能自动扩大为 W12 的交易权限。学生各自的账户状态独立记录，不假设模拟资金可重置。未成交、拒单或平台不可用时保存真实状态并切换同构事件包，不能伪造正常路线证据。

六周内不让约 30 人分别建立完整交易框架。`common/` 提供数据契约、时间边界、订单规划、风险检查和 replay；真正提交订单的受信工具由教师控制，持有与学生工作区隔离的凭证，并独立强制 paper、标的白名单、资金／数量上限和停止规则；仅把工具放在另一个目录并不构成隔离。学生唯一持续演化的是个人决策组件及其测试、配置和证据。真实凭证、完整账户响应和原始行情不进入公开仓库或 Agent 可读工作区。

## 5. W16｜不用 presentation，仍要验收责任

W16 不预留连续多课时的学生展示或集体讨论，也不要求短视频。学生登记最终版本，并提交统一的简短证据卡：两次数据与决策、模型改变、真实订单状态及账户前后状态、证据边界，以及对最终模型版本的发布决定。若未成交或使用 replay，按实际模式与结果填写，不伪造账户变化。自动检查先核对缺项、版本、测试和隐私边界；教师集中查看异常与少量抽样。

课堂保留一次约 15～20 分钟的个人书面短答：拿自己的两轮记录说明“为什么行动、实际发生什么、根据什么只改了一处、证据尚不能说明什么”。教师只对异常或抽样个案追加简短追问，不组织逐人口头展示。这不是代码作者鉴定，而是防止报告变成无人负责的 Agent 产物。必要的修复与补证在固定时间内完成；不现场重写系统来替代解释。

## 6. 对旧蓝图的明确取舍

- 不保留 W10 起五周自由选题、三四套参考策略、频繁阶段展示和 W15～W16 两周答辩。后半段只支持一条平台路线、一个学生可替换决策组件、两次有对照的运行。
- 并发、调度、幂等提交器或券商资金计算不作为学生独立开发要求；工程展示按当周概念选择。W12 由教师维护受信工具和安全检查，学生追踪它们对自己订单计划的作用。
- 不把盈利、代码手写比例、Agent 使用程度或模拟成交数量当作课程排名。验收对象是程序行为、外部反馈、证据和人的判断。
- 网站 `course.json.weekMap` 按此蓝图登记。旧版 W4～W16 的里程碑周号、PR/tag 与报告模板不自动沿用；在具体周任务成稿时再决定所需的提交与验收方式。

## 7. 冻结前必须由教师试跑

1. W4～W10 每周至少一条完整 Python 示例、一组有明确验收条件的探索任务，以及一份能被测试拒绝的错误案例；R、Bash 的理解目标与 Rust／C 的教师展示边界按本版执行。
2. 每周跨语言对照与探索环境须先试跑，确认写法与实际行为支持当周概念；选用异步工程展示时，教师须跑通目标路径，并准备真实输出或录屏作为退路。展示不增加学生的工具链要求。
3. Longbridge 的注册、授权、只读行情、paper 交易权限、受控下单、成交状态和账户前后核对；先在教师 Demo 账户中形成脱敏记录。
4. 市场时段、账户资金与标的规则下的正常成交路线，以及真实失败时的 replay 退路；W12 与 W15 的执行窗口必须匹配所选市场的常规交易时段，若班课时段不匹配，另定经教师试跑的课外人工执行窗口，不在课堂硬逼单；两轮行动不能依赖重置模拟账户。
5. 外部提交器、凭证隔离、白名单、风险上限、重复请求与未知状态停止；学生代码不能绕过这些边界。
6. 对约 30 名学生、无助教条件下，预演最终证据卡的自动缺项检查与教师批改时间。未被教师跑通的环节不设置为学生硬门槛。

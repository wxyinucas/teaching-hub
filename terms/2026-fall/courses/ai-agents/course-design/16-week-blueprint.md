# AI 辅助编程与量化实践：16 周课程蓝图（v1.0）

> 状态：冻结。后续教案、任务书、测试、课程网站和 Slides 均以本文件为周次基准。  
> 课程规模：16 周 × 每周 3 个 50 分钟课时；约 25 名零编程基础应用统计专硕；无助教。  
> 一句话主线：**学生先借助 `common/` 看见并运行整台低频模拟交易机器，再逐周把规格、测试、数据边界、实验设计和发布责任接到自己手中。**

## 1. 课程终点与评价对象

期末最小闭环为：

> 合规取得数据 → 在明确时点产生目标持仓 → 由公共设施形成订单计划并实施风控 → 在 paper/replay 中运行 → 收集订单与账户结果 → 核对预期与实际 → 提出竞争解释与下一次区分性实验

课程不教授一套完整的统计或量化理论，也不以收益、代码手写比例或 Agent 使用多少评价学生。学生可以使用参考算法甚至让 Agent 完成全部实现，但必须能够：

1. 给出明确规格；
2. 设计并解释覆盖主要功能的独立测试；
3. 判断公开测试、隐藏测试、CI 和平台反馈分别证明了什么；
4. 追踪程序如何从决策走到订单、风险结果和账户变化；
5. 说明现实结果与预期的差异、仍未知事项和下一次有区分力的实验；
6. 作出 `ACCEPT / HOLD / BLOCKED` 发布决定并承担后果。

### 1.1 最小量化词汇，不设理论单元

课程只要求学生在具体系统案例中正确使用以下词汇，不讲授完整金融或统计理论，也不单独考试公式：

| 在何处建立共识 | 最小词汇 |
| --- | --- |
| W4 数据 | 标的、日 K/bar、OHLC、交易日、时区、`event_time`、`available_at` |
| W5 行动 | 现金、持仓、目标持仓、账户权益、暴露、订单、买/卖、限价、成交/未成交/部分成交/拒单/撤单 |
| W9/W11 结果 | 交易成本、盈亏、收益、基准、回撤；只要求读懂定义并说明它们不能证明未来盈利 |
| 全程责任 | 数据泄漏、回放、paper、幂等、账户核对、事前契约与事后解释 |

词汇是否掌握通过报告和答辩中的正确使用来判断；学生有兴趣时可让 Agent 或另一门回归课继续教授理论。

## 2. 五个阶段

| 周次 | 阶段 | 阶段结果 |
| --- | --- | --- |
| W1～W3 | 第 0 单元：本地 Agent 工作台 | 能取得、运行、修改、测试、审查并提交项目；配置完成后立即运行第一个平台形状任务 |
| W4～W6 | 看见整机并接管确定性决策 | 真实数据 → 标准化 → OrderIntent → 风控/dry-run；学生首次对一个策略规格与测试负责 |
| W7～W9 | 数据、时间与首次外部事件 | 数据可追溯、禁止未来信息、陌生窗口可复现，并完成受控 paper 或同构 fallback 事件 |
| W10～W14 | 受约束的自由探索 | 学生只选一个小问题，完成事前契约、运行、核对、竞争解释和第二轮实验 |
| W15～W16 | 冻结、复现与个人答辩 | 不再增加功能；形成可复现 release，并个人说明主张、证据、局限和责任 |

因此，对“第 10 周以后才更自由”的准确理解是：**是；W10 起学生决定探索问题和算法增量，但接口、paper-only、低频、风险上限、防泄漏、证据格式与答辩责任始终不可取消。**

### 2.1 证据随任务阶段递进

课程不在第一周假装学生已经拥有一个成熟的软件项目，也不把所有证据形式一次性压给零基础学生。证据只需与当周真正完成的工作同构，并逐步接入下一层现实反馈：

- W1 用环境状态、命令输出和结构化故障记录证明“设备可以继续工作”；
- W2～W3 用可复现命令、给定测试、diff 与 Git 记录证明“项目确实按预期改变”；
- W4～W9 再加入数据契约、学生独立测试、隐藏测试、CI、防泄漏检查和 paper/replay 事件；
- W10～W16 用事前实验契约、平台对账、区分性实验、可复现 release 与答辩形成完整责任链。

证据会增强，但早期证据不会因此失效。新的机制只在它能够回答一个已经出现的问题时引入；例如，第一项真实编程任务出现后才需要代码测试，仓库协作稳定后再让 CI 承担外部验收。

## 3. 每周通用课堂节奏

三课时不是三次连续讲授，而是一轮闭环：

1. **课时 1：看见与预测。** 入口检查、真实案例、教师追踪和学生先预测；
2. **课时 2：有指导地完成。** 任务卡 + Agent + 公共骨架，教师处理共同故障；
3. **课时 3：独立验证与签字。** 不再引入大型概念，完成测试、证据、同伴追问和退出状态。

每课时只承诺约 40 分钟核心活动，保留约 10 分钟给登录、等待、失败恢复与验收。快组进入预制故障或陌生变体，不提前学习下周关键依赖；慢组走参考路线或同构 fallback，保留当周唯一最低线。周末任务主要是整理课堂成果，常规目标 30～45 分钟；若连续两周学生 `p90` 明显超出，应删减任务而非把课堂欠账转移到课后。

## 4. 16 周课程日历

### W1｜设备成为可接续的学习现场

- **唯一增量**：电脑达到 `READY-CODE`，或形成可由下一人继续处理的结构化 `BLOCKED` 状态。
- **课时 1**：介绍脱口秀《AI 都能写，为什么还要你签字？》；用“高收益但偷看未来”的例子区分漂亮结果、正确证据和未来盈利。
- **课时 2**：WSL 黄金路线短演示后滚动安装；学生可从此刻使用 Agent 解释官方步骤与错误。
- **课时 3**：继续 WSL、VS Code/WSL 接入；全员沿固定课程目录尝试 `code .`，但路径含义留到 W2 正式教授。
- **最低完成线**：责任退出卡 + `READY-CODE`；尚未成功者必须提交包含当前阶段、最后成功检查点、操作、完整错误、已检查项和下一步的 `BLOCKED`。`BLOCKED` 可以按时收口，但不等于通关。
- **慢/快分流**：慢组不被逐台代修；快组继续同一环境阶梯，不提前形成下周前置差距。
- **周末证据**：`week01/report.md` 草稿与状态记录；安装补做最多 1 小时，超时即停止随机尝试并上报。

### W2｜项目能够从正确位置复现运行

- **唯一增量**：在本地正确目录用锁定环境运行教师骨架和给定测试。
- **课时 1**：从一个可观察的 `git pull` 开始认识工作目录、local、remote 与上游变化；练习路径和从 Bash 当前目录执行 `code .`。
- **课时 2**：`uv sync --frozen`、`uv run`、测试；通过实际文件位置区分全局工具、项目环境与项目配置。
- **课时 3**：完成 `status/diff/add/commit`；教师用预制分支演示 `switch/checkout/merge`，快组实际练习；开始本地 Agent 安装与登录。
- **最低完成线**：从指定入口恢复环境并运行测试；能指出当前目录、项目环境和远端各在哪里。
- **慢/快分流**：慢组使用教师准备的练习副本，不把 branch/merge 熟练度列入门槛 0；快组从干净目录复现、实际完成预制 merge 或恢复一个小错误。
- **周末证据**：补交 `week01/`，完成 `week02/report.md` 和复现记录；Agent 登录失败不伪造完成状态。同步开放 Longbridge paper 注册/隐私说明与状态登记，学生不提交任何凭证，也可直接选择 replay 路线。

### W3｜Agent 成为受控修改者，系统第一次观察外部形状

- **唯一增量**：完成“Agent 修改 → diff → 测试 → commit/push”的责任闭环，并立即运行第一条平台形状观察命令。
- **课时 1**：完成本地 Agent 配置，限定工作目录、权限和密钥边界；正式 fork，辨认个人 `origin` 与教师 `upstream`。
- **课时 2**：让 Agent 完成一个极小修改；学生检查关键 diff、运行测试、提交、推送，再用 status/log 核验远端与本地状态。
- **课时 3**：运行教师预制的 `observe` 命令；只有个人授权和隔离取数负向测试都通过者才调用 Longbridge 行情，其余使用同格式合成 fixture，追踪输出来自哪里。
- **最低完成线 / 门槛 0**：能从指定入口运行、让 Agent 受控修改、解释至少一个测试、检查 diff 并提交；另产生一份明确标注运行模式的观察摘要。
- **慢/快分流**：未通关者仍可使用教师骨架参与观察，但进入补测队列；快组处理“Agent 改错目录/测试虽绿但行为错误”的故障卡。
- **周末证据**：第一次里程碑 PR、精选的一次 Agent 修正与收尾复核、`week03/manifest.json`。

门槛 0 要求学生对路径、pull/status/diff/add/commit/push、`uv`、测试和 Agent 审查闭环负责；`switch/checkout/merge` 在第 0 单元中必须看见并能沿任务卡追踪，但不考命令记忆或以 W3 前独立熟练作为阻断条件。以后第一次真正需要分支同步时再完成一次受控实作。

### W4｜真实行情成为稳定课程数据

- **唯一增量**：把一小段 Longbridge 历史日 K 转换为统一数据契约。
- **课时 1**：教师追踪“平台字段 → 课程字段”；只介绍标的、日 K/bar、OHLC、交易日、时区、`event_time` 和 `available_at` 等最少共识，不讲策略理论。
- **课时 2**：学生经 `common/` 读取指定标的；检查字段、排序、唯一性、价格关系和查询截止时间。
- **课时 3**：生成脱敏摘要、数据指纹和测试证据；比较真实读取与合成 fixture 的相同/不同。
- **最低完成线**：规范化数据通过契约测试，并明确来源、`as_of`、运行模式与不能声称的内容。
- **慢/快分流**：账号/网络失败者使用 fixture 并提交平台故障记录；快组更换一个标的或击穿一个时区/重复行故障。
- **周末证据**：数据观察报告；原始行情、token 和完整 SDK 输出不得进入公开仓库。

### W5｜系统产生订单意图，但尚不提交

- **唯一增量**：让教师给定的目标持仓经过账户快照、订单规划和公共风控，形成可解释的 `OrderIntent`/dry-run。
- **课时 1**：沿一个具体案例建立现金、持仓、目标持仓、账户权益、暴露和订单状态的词汇，并追踪“目标持仓 → 当前持仓差额 → 数量/购买力 → 券商规则 → 风控决定”；学生先预测每一步。
- **课时 2**：运行一个被接受和一个被拒绝的计划；认识允许标的、long-only、金额/数量上限和停止条件。
- **课时 3**：学生改变一个公开输入或配置，验证为什么结果应当改变；区分课程 dry-run 与平台正式验单。
- **最低完成线**：一份完整 trace，能指出系统想做什么、公共设施计划做什么、为何接受/拒绝以及哪些规则不要求学生独立实现。
- **慢/快分流**：慢组使用给定意图；快组补边界测试或识别资金计算与平台估算不一致的案例。
- **周末证据**：正常/拒绝两份 dry-run 摘要和“公共库不是魔法黑箱”的追踪说明。

### W6｜学生首次对确定性决策负责

- **唯一增量**：学生为给定接口规定一个极简单目标持仓规则，并用独立测试支持它。
- **课时 1**：把自然语言改写为输入、输出、正常、边界、错误和禁止项；为正常/边界/错误各写一个可执行例子。
- **课时 2**：让 Agent 实现参考规则或学生小规则；用学生测试击中教师故障实现，再看关键 diff。
- **课时 3**：接入 W5 dry-run，完成小组互答与教师抽查；解释测试为何正确、证明什么、没证明什么。
- **最低完成线 / 门槛 1**：规格、学生独立测试、公开/隐藏测试、无凭证泄漏，以及“输入 → 决策 → 风控 → FakeBroker/dry-run”的端到端证据。
- **慢/快分流**：慢组直接采用参考规则，把精力放在规格与测试；快组增加一个真正能击中故障实现的边界测试，不提前开放 paper 外部副作用。
- **周末证据**：v0.1 里程碑 PR、一页证据卡、Agent 收尾复核与发布决定。

### W7｜数据输入可追溯并可被故意破坏

- **唯一增量**：学生从正式来源取得小规模数据，形成数据清单，并据此构造可公开的人工 test data。
- **课时 1**：记录来源、标的、查询时间、覆盖期、时区、字段和使用限制；不把“下载成功”当成已理解。
- **课时 2**：经 `common/` 规范化；从真实样式制作小型合成数据，加入缺失、重复、乱序或异常值之一。
- **课时 3**：让契约测试区分正常与故障数据；说明真实样例与人工 test data 各自负责什么。
- **最低完成线**：数据清单、规范化摘要、一个可控 test data 和能击中故障的契约测试。
- **慢/快分流**：慢组使用教师指定标的和下载路线；快组增加第二种故障，不扩大策略范围。
- **周末证据**：`data-manifest`、数据指纹、测试数据与测试解释；原始行情仍留在本地。

### W8｜系统只能看到当时已经可用的信息

- **唯一增量**：加入确定性时钟和逐时点回放，建立禁止未来信息的数据边界。
- **课时 1**：冻结课程日线时间契约：交易日 D 的 bar 只有在该市场 D 日收盘并经 `common.clock` 标记为 confirmed 后才具有 `available_at`；决策只能读取 `available_at <= decision_time` 的记录，最早订单时点是 `common.clock` 给出的下一可交易时点，禁止用同一 bar 的收盘价成交。随后用纸面时间线预测一个明显泄漏程序的结果。
- **课时 2**：在微型数据上逐时点运行，记录每次决策真正取得的数据窗口。
- **课时 3**：修改未来数据后重跑；过去决策必须不变，相同输入/配置必须可复现。
- **最低完成线**：“改变未来不改变过去”的自动测试、日 K `available_at`/下一可交易时点测试，以及学生对其正确性的解释。
- **慢/快分流**：慢组使用给定回放器和数据；快组增加信息可用时间或乱序数据，不引入复杂偏差名词。
- **周末证据**：可重复回放摘要、防泄漏测试、该测试仍未覆盖的泄漏途径；另在 W9 课前运行无下单能力的自动准入检查，paper 学生得到安全链状态，replay 学生得到同格式路线卡。

### W9｜确定性证据与第一个受控外部事件汇合

- **唯一增量**：冻结同一策略，在陌生历史片段和 paper/replay 事件中各运行一次并接受审计。
- **课时 1**：运行教师隐藏历史窗口，读懂交易成本、收益、基准和回撤的最小定义及局限；读取课前自动准入结果，paper/replay 学生分别进入对应路线卡，不在本课临时搭建安全边界。
- **课时 2**：外置提交器重新查询账户、未完成订单和市场状态，并校验计划哈希/过期时间后，合格者提交一笔受控 Longbridge 模拟订单；任一状态未知即停止。平台不可用者领取同构事件包。成交、未成交、拒单或撤单均可。
- **课时 3**：小组答辩与教师抽查，分别说明历史测试和平台反馈能/不能证明什么。
- **最低完成线 / 门槛 2**：数据来源与契约、test data、防泄漏测试、陌生窗口复现、paper/fallback 事件和局限声明。真实平台不可用不影响通过，但运行模式必须如实标注。
- **慢/快分流**：慢组使用参考策略与 replay；快组追踪部分成交/重复请求故障，不增加第二种策略。
- **周末证据**：v0.2 里程碑 PR、冻结配置、脱敏事件包、平台/降级状态和发布决定。

### W10｜自由探索从事前契约开始

- **唯一增量**：学生选择相对 W9 的一个小变化，并在看结果前冻结实验问题。
- **课时 1**：从参考菜单或个人想法选题；写下预期、唯一改变项、不改变项、风险边界和准备观察的证据。
- **课时 2**：Agent 实现一个策略/配置增量；学生增加测试并在离线回放中检查。
- **课时 3**：同伴尝试反驳规格和证据；修订后冻结 `experiment-contract`，不允许看完结果再改题。
- **最低完成线**：事前实验契约、相对 W9 的唯一 diff 和至少一个新增测试。
- **慢/快分流**：慢组选择参考菜单；快组增加对照或观测点，不同时增加多个算法部件。
- **周末证据**：冻结契约和首次运行计划；本周不以 paper 盈亏为产物。

### W11｜核对“想做、提交、发生”

- **唯一增量**：加入订单生命周期和账户前后快照的对账。
- **课时 1**：按 W10 契约运行一次低频 paper/replay 事件，保存标准化日志。
- **课时 2**：查询订单状态、成交/未成交、现金、账户权益与账户摘要，建立三个层次：目标、实际请求、平台结果；所有比较都相对本次运行前快照，不假设 paper 资金可重置或全班初始余额相同。
- **课时 3**：用对账表找出未解释差异，同伴检查证据是否真的来自同一次 `run_id`。
- **最低完成线**：一份能连接意图、计划、请求、状态和账户变化的脱敏对账表。
- **慢/快分流**：慢组使用统一事件包；快组分析撤单或部分成交，不追求更多交易次数。
- **周末证据**：第一次实验运行报告、未解释差异和当前 `ACCEPT/HOLD/BLOCKED`。

### W12｜系统能够安全地重复运行

- **唯一增量**：把流程做成一次性低频 job，并验证重复执行不会意外重复下单。
- **课时 1**：整理确定入口、配置、时区和停止条件的一次性 job；默认人工启动，不假设电脑永远在线。
- **课时 2**：让同一逻辑订单复用稳定 `client_request_id`；演练网络调用前持久化 `PENDING`、单写者锁、响应后原子记录 `order_id`，以及 `UNKNOWN` 状态 fail closed；同时验证允许标的、最大暴露和订单次数限制。
- **课时 3**：从“写 PENDING 后崩溃、提交后响应丢失、重启、并发启动、超过幂等窗口、断网/拒单”中注入至少一种，执行“检测 → 停止/人工核对 → 账户核对”，禁止未知状态自动重下。
- **最低完成线**：重复或并发执行不产生意外重复行动；未知状态停止而非猜测；至少一个风险限制被故意触发并成功阻止行动。
- **慢/快分流**：慢组只做本地 FakeBroker 故障；快组在已有可靠环境时尝试调度，但调度不是必修。
- **周末证据**：一次性 job 清单、幂等证据和故障响应包。

### W13｜为不确定性增加有区分力的证据

- **唯一增量**：围绕一次差异增加观测点，并设计下一次能够区分竞争解释的实验。
- **课时 1**：对照事前契约、程序行为和平台结果，区分“系统没按规格做”与“市场结果不如愿”。
- **课时 2**：提出至少两种竞争解释，列出每种解释已有的支持/反对证据与缺失证据。
- **课时 3**：只改变少量因素，增加必要日志/测试，先在回放中预演下一实验。
- **最低完成线**：`预期 → 实际 → 差异 → 竞争解释 → 区分实验` 的完整链条。
- **慢/快分流**：没有自然事故者使用教师统一故障包；快组增加负面对照，不增加第二个新功能。
- **周末证据**：第二次实验协议及其可反驳预期。

### W14｜完成第二轮有控制的实验

- **唯一增量**：执行 W13 实验并形成冻结候选。
- **课时 1**：运行第二轮 paper/replay 或处理统一事故；保持已冻结的不变量。
- **课时 2**：比较前后两轮，核对证据链、Agent 关键互动、局限与仍未知事项；对 release candidate 运行学生测试、公开契约、防泄漏与运行安全累计测试，同伴审计。
- **课时 3**：阶段答辩和教师抽查，只修复证据缺口，不再扩张功能。
- **最低完成线 / 门槛 3**：事前契约、风险/订单/账户证据、一次事故或意外的事后响应、至少两种解释和一项区分性实验。
- **慢/快分流**：慢组使用参考策略和统一事件；快组帮助同伴复现，不继续调参。
- **周末证据**：v0.3 release-candidate 里程碑 PR、两轮对照、冻结前缺口清单和发布决定；最终证据包与短视频须在 W15 上课前 24～48 小时提交供预读。

### W15｜系统成为不可变、可复现的 release

- **唯一增量**：冻结代码、配置、数据清单和证据索引，并由他人从干净环境复现。
- **入口条件**：W14 release candidate、最终证据包和短视频已在上课前 24～48 小时提交；任何改变答辩版本的 correction 已以小型 PR 合入 upstream，最终登记 SHA 是 upstream 可达 commit，教师已对它运行隐藏契约及完整累计测试。迟交或失败者仍按已登记版本说明 `HOLD/BLOCKED`，不能用现场修改换取延期或冒充最终门槛通过。
- **课时 1**：核验外部登记 SHA，创建/检查冻结 tag；交换项目，按 README 做简化复现和反例审计；只允许追加 correction。
- **课时 2**：个人答辩区段 A；未答辩者担任证据审查员。
- **课时 3**：个人答辩区段 B。
- **最低完成线**：release、复现说明、同伴审计单、最终证据索引；本周不以现场改代码代替解释。
- **慢/快分流**：唯一快进任务是帮助复现或补充局限；所有新功能停止。
- **周末证据**：指定 correction、同伴审计回应和责任声明；不再补交会改变答辩对象的新版本。

### W16｜责任归属、答辩与归档

- **唯一增量**：为冻结系统形成明确的个人主张与责任边界，不再增加系统功能。
- **课时 1**：个人答辩区段 C。
- **课时 2**：个人答辩区段 D。
- **课时 3**：完成余下答辩和归档；复盘什么可以交给 Agent、什么判断和责任不能转交。
- **最低完成线**：每人独立回答输入、决策、约束、测试、平台结果、局限、Agent 贡献与下一实验。
- **慢/快分流**：若容量紧张，课程复盘改为书面；不能压缩个人追问来保留仪式性展示。
- **周末证据**：最终责任声明与归档索引。

## 5. 五个阶段门槛

| 时间 | 门槛 | 学生必须能够证明 |
| --- | --- | --- |
| W3 | 门槛 0：本地 Agent 工作台 | 从正确目录取得/恢复项目，运行测试，让 Agent 受控修改，检查 diff，再测试并提交；知道权限和密钥边界 |
| W6 | 门槛 1：确定性行动系统 | 给定接口下有明确规格、独立测试、公开/隐藏测试结果和端到端 dry-run/FakeBroker 证据 |
| W9 | 门槛 2：数据、时间与外部事件 | 数据可追溯，有人工 test data、防泄漏测试、陌生窗口复现，以及如实标注的 paper/replay 事件 |
| W14 | 门槛 3：不确定性与运行责任 | 有事前契约、风险/订单/账户核对、事后响应、竞争解释和已执行的区分性实验 |
| W15～16 | 最终门槛 | 外部登记的最终 SHA 重新通过全部学生/公开/隐藏/防泄漏/隐私/运行安全累计测试，且可由他人复现；个人能说明主张、证据、未覆盖风险、Agent 贡献和发布决定 |

门槛均允许重试。环境或平台问题可以进入 fallback；绕过安全边界、伪造运行模式、无法解释测试，或将亏损/盈利误作正确性证据，不能由 fallback 豁免。

## 6. 学生产物、测试与平台反馈

学生目录与报告 schema 见[《学生仓库与每周证据契约》](./学生仓库与每周证据契约-v1.0.md)。核心分工为：

- `common/`：教师维护的契约、适配器、风控、回放、FakeBroker 与证据生成；
- `system/`：学生唯一持续演化的决策系统；
- `weekXX/`：按周追加的报告、manifest 和证据；
- 学生先通过自编测试，再接受教师公开测试与隔离环境隐藏测试；
- CI 只证明无凭证环境中的可重复执行，不接触 Longbridge；
- paper 证明发生过一次平台交互，不证明算法正确或会盈利；
- 最终答辩用于检验学生是否会判断并承担责任，不能替代测试。

Longbridge 主路线、安全闸门和降级规则见[《Longbridge 课程接入决策》](./Longbridge课程接入决策-v1.0.md)。

## 7. 最终答辩容量

W15～W16 共 300 分钟。W15 第 1 课时用于 tag 核验和复现后，名义答辩时间剩 250 分钟；按 80% 可用容量计算，25 人平均约 **8 分钟/人，包含切换与追问**。

因此：

- 系统概览、主要证据和 Agent 记录课前以短视频或统一证据包预读；
- 现场以 1～2 分钟定位 + 5～6 分钟个别追问为主；
- 追问从规格、一个测试、一个平台事件、一个局限和下一实验中抽取；
- 技术演示失败时使用冻结证据包，不把整段时间花在现场救火；
- 展示压缩可以发生，个人责任追问不能取消。

## 8. 教师制作与运行预算

| 截止点 | 必须完成的教师产物 | 需要提前遇见的失败 |

| W3 前 | `common/` 最小行走骨架、合成平台 fixture、公开测试、证据生成器 | 学生改错目录、测试与本地不一致、公共库被误改 |

首轮课程的现实教师负担估计：普通周教学包和试跑约 3～5 小时，报告仪表盘与抽样约 45～60 分钟；W3 自动全检与人工抽样约 60～90 分钟；W6/W9/W14 每次全量里程碑另需约 2～3 小时；W15 的 25 份最终证据包/短视频预读和冻结核验另计约 2～3 小时。这里正是教师使用费曼法真正学习的地方。若每周垂直样例、参考实现、故障实现和 fallback 尚未由教师跑通，该内容只能作为试点，不能成为学生硬门槛。

## 9. 当前最需要监测的课程风险

1. **W2～W3 仍然拥挤。** 解决方式不是追加课时，而是滚动通关；平台观察可由未通关者在教师骨架中参与。
2. **Longbridge 账号可能形成假前置。** 平台状态与学习状态分开；真实读取、replay、fake 共用接口和 evidence。
3. **`common/` 可能变成无法质疑的黑箱。** 每个阶段至少追踪一个具体案例；学生不实现公共部件，但必须发现输入、规则、输出和证据矛盾。
4. **学生可能把绿灯或盈利当作责任结束。** 每份报告固定要求“证明什么/没证明什么”和 `ACCEPT/HOLD/BLOCKED`。
5. **自由探索可能退化成 25 个无法支持的技术栈。** W10 后只允许替换规定接口内的一项增量；新依赖统一申请，平台仍只有一条正式支持路线。
6. **每周报告可能淹没教师。** 自动检查全部、教师抽样普通周、全量评审里程碑；不收完整 Agent 对话。
7. **低频定时运行可能被误解为平台托管。** 首版最低要求是学生在规定时间人工启动一次性 job；只有可靠运行环境已经实测，调度才成为选做。
8. **市场数据和账户证据可能泄露。** 公开仓库只存合成数据、指纹和脱敏摘要；原始行情与账户回执留在本地或受控位置。

## 10. 蓝图冻结后的制作顺序

1. 以 W1～W3 为第一个垂直切片，制作学生任务卡、教师演示、故障卡、恢复路线和 evidence 命令；
2. 试做 Longbridge 账号、只读历史数据与 paper 安全链，填写白名单和上限；
3. 实现 `common/` 最小行走骨架与三种运行模式；
4. 为 W4～W6 制作数据契约、dry-run、参考/故障策略和公开/隐藏测试；
5. 使用 2～4 名近似新手试做，记录每个核心任务的 `p50/p80`，再校准课堂分钟数；
6. 最后才批量制作 GitHub Pages、Slides、PDF 和后续周教案。

这使材料生产始终服务于可运行课程，而不是先制造大量以后必须推翻的课件。

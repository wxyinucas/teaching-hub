# AI 辅助编程与量化实践：课程定位与设计原则（v2）

> 状态：课程定位仍适用；教学周次以[现行蓝图](./16-week-blueprint.md)为准。
> 本文件只回答“为什么这样设计”；周次、平台、仓库和教案细节分别由专项文件负责。

## 1. 基本背景

- 当前工作名：**AI 辅助编程与量化实践**。
- 公共选修课，3 学分，48 学时，16 周；约 30 名学生，其中不少是数学专业研究生。
- 每周三节连上，每节 50 分钟，中间休息 10 分钟；无助教。
- 假设学生没有编程经验和计算机基础概念，自备电脑。
- 教师以费曼学习法参与课程建设：通过真正实现、验证和讲授课程，迫使自己理解 Agent 协作、软件测试及现实不确定性。

## 2. 一句话定位

> 以低频量化模拟交易为现实反馈的 playground，训练零基础学生借助 AI Agent 提出规格、构造证据、判断证据、运行系统、解释结果并承担责任。

量化不是课程终点，而是让程序面对真实数据、外部规则、未成交、拒单、网络中断和随机结果的载体。

## 3. 课程不是什么

- 不是以语法默写为目标的 Python 课；W4～W9 会认真建立程序运行、追踪与诊断的基础，Python 是实践主线，R 与 Rust 只用来对照概念。
- 不是统计学或金融量化理论课；只建立完成项目所需的最小术语共识。
- 不是 Agent 架构、工具调用或多智能体系统开发课。
- 不是以收益率或模拟账户余额排名的投资竞赛。
- 不以手写比例判断学习，也不要求证明代码完全由本人编写。
- 不因申请稿曾列出 Python、SQL、JavaScript、PyTorch 就强行覆盖这些技术。

## 4. 核心能力

> **能否提出规格、设计证据、判断证据并承担结果。**

学生最终应当能够：

1. 说清楚系统应该做什么以及禁止做什么；
2. 根据给定接口设计或组织 Agent 设计覆盖主要功能的独立测试；
3. 解释测试为什么正确、证明了什么、没有证明什么；
4. 阅读关键 diff、测试结果、错误、运行日志和脱敏账户记录；
5. 识别数据泄漏、越权、密钥暴露及明显安全合规问题；
6. 在现实结果与预期不一致时提出竞争解释；
7. 设计下一次能够区分这些解释的实验；
8. 对 `ACCEPT / HOLD / BLOCKED` 发布决定负责。

这里的可解释性不是逐行背诵代码，而是能够追踪输入、决策、公共约束、系统行动、证据和局限。

## 5. Agent 与人的责任边界

- 允许 Agent autopilot；课程不把“必须手写”当作道德要求。
- autopilot 不等于甩手。学生更像 manager：设定目标、规定边界、要求证据、验收结果并承担责任。
- Agent 可以同时是实现者、诊断助手和私教；主动选择困难是一种可用方法，不设置成无法执行的强制要求。
- 工具保持中立：可以使用 VS Code 中的 Agent、Codex、Claude Code 或其他可支持工具。
- 课程统一的是工作目录、权限、规格、测试、证据与责任契约，而不是厂商。

## 6. 双重证据观

### 6.1 确定性证据

- 学生先通过自己的测试，再接受教师公开测试和隔离环境隐藏测试。
- CI 提供干净环境中的重复执行证据，但不等于语义绝对正确或安全审计完成。
- 数据泄漏必须同时进入规格、测试和个人证据核验。
- Agent 的自述、程序无报错或漂亮输出都不是充分证据。

### 6.2 随机世界的反馈

- 模拟账户提供外部状态和现实失败，但盈亏不能证明算法正确或错误。
- 评价重点是事前写下了什么、实际发生了什么、如何解释差异以及下一次实验。
- “验证实验的实验”可能继续套娃，但可审计的证据链仍优于事后两手一摊。

## 7. 已冻结的应用边界

- 第一支持平台是 Longbridge，只使用 paper account，不接入真实资金。
- W1～W3 建立工作台与 Agent，W4～W9 学习编程基础，W10 才进入平台和真实数据；外部下单必须通过确定性门槛和安全隔离。
- 平台不可用时降级到同接口 replay/FakeBroker，不改变报告和评分资格。
- 第一版采用低频、可重复的一次性 job；持续在线和平台托管不是要求。
- 学生可采用简单规则或参考实现；W10～W15 只做一次有两轮对照的量化闭环，不安排大规模自由选题。
- 选择算法的自由不能取消接口、paper-only、风险上限、防泄漏、证据格式和个人责任核验。

实施与安全细节见[《Longbridge 课程接入决策》](./longbridge-decision.md)，周次见[《16 周课程蓝图》](./16-week-blueprint.md)。

## 8. 第 0 单元为何是门槛

WSL、Bash 路径、VS Code、Git、`uv` 和本地 Agent 不是课程前的杂务，而是学生之后取得、运行、修改、测试和审查系统的工作台。

门槛不考命令背诵。学生可以查资料、使用 Agent 和接受同学帮助，但必须知道：

- 当前位于什么环境和目录；
- Agent 获得了什么权限；
- 准备执行什么动作；
- 什么证据表示完成；
- 何时必须停止并提交结构化 `BLOCKED`。

未通关者仍可用教师骨架参与后续课堂，再通过补测完成个人闭环。W1～W3 的已成稿材料位于 `../weeks/`；旧[《第 0 单元至首次 Longbridge 实践》](./unit-0-to-longbridge.md)仅作历史设计参考。

## 9. 学生产物的基本形态

- `common/`：教师维护的契约、回放、风控和公共设施；学生调用、追踪和质疑。
- `students/sXX/system/`：学生唯一一份持续演化的系统代码。
- `students/sXX/weeks/week-XX/`：追加式周报告和证据，不复制 16 份系统。
- Agent 对话只精选任务设定、一次关键修正和收尾复核，不提交完整聊天记录。
- 普通周以自动检查和教师抽样为主；W16 提交简短证据卡并完成一次个人书面核验，不安排逐人口头答辩。

完整目录、报告、CI 和隐藏测试约定见[《学生仓库与每周证据契约》](./student-repository-contract.md)。

## 10. 个人证据核验

学生最终的证据卡与书面说明至少回答：

1. 系统增加了什么行为；
2. Agent 做了什么，学生怎样收尾复核；
3. 哪些规格、测试和运行证据支持发布决定；
4. 一次预期与现实不一致的事件及竞争解释；
5. 若要继续探索，下一次怎样取得有区分力的证据；
6. 系统现在能声称什么、不能声称什么。

核验不是鉴定代码作者，而是检验学生能否判断证据并为冻结成果负责。

## 11. 与多元线性回归课程的关系

两门课松耦合：

- 共享 WSL、GitHub、`uv`、Agent 与测试习惯；
- 多元线性回归课负责模型假设、残差、估计、不确定性与统计解释；
- 本课程负责规格、数据契约、防泄漏、测试、运行与审计；
- 回归模型可以成为本课程系统中的可替换组件，但不是前置条件；
- 两门课作业与评分独立，避免进度互相阻塞。

## 12. 原申请内容的取舍原则

保留并强化：零编程基础假设、AI 辅助、“用中学”、验收 Agent 产物、编程基础、工程项目和个人证据核验。

不再默认保留：大而全的编程语言清单、Prompt 技巧专题、深度学习、复杂 Agent 系统，以及不能服务于增量系统和核心能力的技术内容。适合多元线性回归课的统计内容可以迁移，不因原申请写过而重复教授。

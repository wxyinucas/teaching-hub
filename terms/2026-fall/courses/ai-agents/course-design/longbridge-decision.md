# Longbridge 课程接入决策（v1.0）

> 状态：课程角色已冻结；账号与网络操作路线须在开课前试点后锁定。  
> 核心结论：**Longbridge 作为第一支持平台；本地 Agent 配置完成后立即进入真实数据实践，模拟下单则是通过证据门槛后才开放的外部副作用。**

## 1. 冻结的课程决策

1. 课程只支持 **Longbridge paper account**，不接入真实资金账户。
2. 第一次平台实践是读取小规模真实历史行情并转换为课程内部格式，不是下单。
3. 学生先产生标准化 `OrderIntent`，由 `common/` 完成资金/数量查询、统一风控、券商规则适配和证据生成；学生需要追踪这些步骤，不要求独立实现。
4. 只有确定性测试、dry-run 和安全检查通过后，位于学生 working tree 之外的受信 `course-paper` 提交器才可发送一笔受控模拟订单。
5. Longbridge、回放券商与确定性 FakeBroker 使用相同接口和证据格式；平台注册或网络失败不能阻断课程主线。
6. 公开 GitHub 仓库和 PR CI 永远不接触交易凭证；普通 Agent 编码会话只有在经过可验证的凭证/执行隔离后才允许与 paper 路线共存，否则全员使用 replay。

这不是把课程变成 Longbridge SDK 教程。平台只负责提供真实接口、真实数据和不可完全控制的结果；课程仍然评价规格、证据、判断与责任。

## 2. 为什么现在可以选 Longbridge

截至 2026-08-21，官方资料已经明确支持本课程所需的最小闭环：

- 官方 Python 包为 `longbridge`；旧包 `longport` 已弃用。[SDK 页面](https://open.longbridge.com/sdk)
- 无需开通真实证券账户即可启用 paper account，取得 paper 凭证并调试行情与交易接口；paper 行情覆盖港、美、A 股，模拟交易支持港美股票与 ETF。[模拟账户说明](https://open.longbridge.com/docs/qa/general)
- Python 配置支持 `enable_papertrading=True`；开启后服务器会拒绝真实资金账户 token。课程必须显式开启这一选项，不能依赖学生记得选择正确账户。[Python Config](https://longbridge.github.io/openapi/python/reference_all/#longbridge.openapi.Config)
- 支持历史 K 线、提交/修改/撤销订单、订单查询、成交查询、账户余额与持仓，因此可以形成“数据 → 意图 → 订单 → 状态 → 账户核对”的闭环。[历史 K 线](https://open.longbridge.com/docs/quote/pull/history-candlestick)、[提交订单](https://open.longbridge.com/docs/trade/order/submit)
- `client_request_id` 只提供 10 分钟的服务端幂等缓存；课程提交器必须稳定生成并事前保存它，不能在超时或结果未知后盲目重试。[提交订单](https://open.longbridge.com/docs/trade/order/submit)
- 中国大陆可使用 `.cn` 接入点，SDK通常会自动选择；学校网络仍须实际试测。[接入说明](https://open.longbridge.com/docs/getting-started)

这些资料证明“平台具备能力”，但不能证明 25 名学生都能顺利注册、授权和联网。因此平台能力已经进入蓝图，批量可用性仍由开课前试点决定。

## 3. 三步开放顺序

### 第一步：只读真实数据

本地 Agent 工作台可用后，学生立即使用教师维护的适配器或隔离的取数命令：

1. 读取指定标的的一小段日 K；
2. 转换为课程稳定数据格式；
3. 检查字段、时间、排序、唯一性和价格基本关系；
4. 只提交来源、数据指纹、规范化摘要和测试结果，不公开原始行情；
5. 说明 Agent 做了什么，以及自己为何接受这些证据。

这里的“只读”描述课程代码路径只调用行情接口，不自动推断 token 必然只有 quote 权限。若试点证明认证支持可靠的 quote-only scope，则 W3～W8 只授予该 scope；否则 token 必须由 Agent 不可读的隔离取数进程持有。没有这个边界、没有账号、拒绝注册外部平台或网络失败者使用同形状的合成 fixture，并把状态写成结构化平台证据。两条路线使用相同报告格式、具有同等课程资格。

### 第二步：课程侧 dry-run

策略只输出 `OrderIntent`，公共设施依次执行：

> 数据截止时间 → 目标持仓 → 当前账户快照 → 计划差额 → 购买力查询 → 允许标的 → long-only → 数量/金额上限 → 计划订单

这里的 dry-run 是课程自己的计划与风控，不是假装平台已经接受订单。Longbridge 没有被证实提供完整的原生下单 dry-run；购买力预估也不能替代正式订单校验。

### 第三步：受控 paper order

通过前两步和门槛 1 后，第 9 周才对学生开放外部副作用。此前的模拟订单仅由教师在开课前安全试点，不设“快组提前下单”。W9 由外置 `course-paper` 提交器形成全班正式的 paper/fallback 事件证据。未成交、拒单、撤单和平台故障同样有效，不以“成交成功”为完成标准。

## 4. 不可由学生取消的安全闸门

`course-paper` 必须同时满足：

- 在提交器自身的固定代码中显式设置 `enable_papertrading=True`，让服务器拒绝真实账户 token；`LONGBRIDGE_PAPERTRADING=true` 只能用于一致性检查，因为环境变量与显式参数是同一配置项，不算第二道防线；
- 提交进程只可能取得 paper token，课程设备/凭证库中不出现真实账户 token；这是与服务器 paper 校验独立的第二道防线；
- 提交器以教师签名/固定摘要的版本安装在学生 working tree 之外，或运行于教师控制服务；它不导入 `system/`，也不信任学生可修改的 `common/`、`VERSION` 或 Git clean 来证明自身完整性；
- token 由 Agent 无权读取、且无权直接执行提交的独立 OS 用户、受限服务或等价隔离边界持有；人类确认发生在该边界内，Agent 不能用参数跳过；
- 只允许课程白名单内的港美股票或 ETF，第一版 long-only；
- 只允许经试点确认的正常交易时段与订单类型；
- 单笔名义金额、总暴露、每日订单数和未完成订单数均有硬上限；
- 订单计划包含稳定 `plan_id`、数据/配置指纹、计划哈希、`as_of`、`created_at` 和 `expires_at`；人类确认必须绑定计划哈希；
- 真正调用前重新查询余额、持仓、未完成订单和市场状态，并重新执行白名单、时段、金额、暴露与次数限制；计划过期、查询失败或任何状态未知均拒绝提交；
- 同一个逻辑订单始终复用同一 `client_request_id`，不是每次启动生成新 UUID；网络调用前先持久化 `PENDING + client_request_id + plan_hash`，并使用单写者锁阻止并发提交；
- 收到响应后原子记录 `order_id`；若“可能已提交但响应丢失”，标记 `UNKNOWN`、立即 fail closed 并人工核对，不自动再次下单；超过官方幂等窗口后绝不把 `client_request_id` 当作保护；
- 查询采用有上限的轮询和退避，提交器自行遵守 Trade API 限流，因为官方 SDK 不替交易调用节流；
- 保存提交前账户摘要、订单计划、风险结果、平台返回、状态变化和提交后账户摘要；
- 超时未成交时有明确的查询、停止与撤单规则；
- 提交器只读取已经冻结的标准化订单计划，不重新执行学生策略；固定提交器或隔离边界校验失败时不加载凭证。

课程首版不开放真实账户、做空、期权、轮证、盘前盘后、市价追单、高频循环或无人监管的连续交易。

## 5. 凭证、数据与公开仓库边界

- 每位选择 Longbridge 路线的学生使用自己的 paper 授权；绝不共享教师 token。因地区、身份、隐私或个人意愿不注册外部平台者使用等价 replay，不因此扣分。
- OAuth 2.0 是官方推荐方式，但 paper OAuth 的学生端操作路线须经试点；如果旧式 paper 凭证更稳定，首版只支持其中一条黄金路线。
- 仅仅“放在项目目录外”不是安全边界：官方 OAuth 客户端可能把 token 持久化到用户主目录。凭证必须由 Agent 无权读取的 OS 用户、受限服务或等价隔离机制持有，不进入 `.env`、shell 全局配置、Agent 对话、Issue、PR、截图或 CI。[认证说明](https://open.longbridge.com/docs/getting-started)
- 学生 working tree 禁止调用会从项目环境/`.env` 自动取凭证的配置入口，也不启用可能写入 token、账户号或原始响应的 SDK 日志；隔离取数/提交器只接受显式受控输入并输出允许列表式摘要。
- W9 前必须做负向验收：普通 Agent 尝试读取 token、调用 `course-paper` 或绕过人类确认均应失败；任何一项不能证明，paper 路线自动降级为 replay。
- 公开仓库只保存合成测试数据、数据指纹、脱敏状态和标准化事件摘要。
- 原始行情、完整账户响应、完整订单号、账户号、精确余额/持仓和未脱敏日志留在仓库外。
- 平台事件先写入非公开位置，只有本地 `course publish/check` 脱敏与 pre-push 扫描通过后才生成公开文件；PR CI 是第二次检查，不是泄露后的补救。
- 怀疑泄露时先吊销或轮换 token；删除 Git 文件不等于撤销已经发生的泄露。

Paper 账户是累积状态，官方目前不支持学生自行重置模拟资金。[交易 Q&A](https://open.longbridge.com/docs/qa/trade) 因此：

- 不假设全班具有相同或可恢复的初始余额，也不比较余额高低；
- 每次实验以个人运行前账户快照为基线；
- 课程设置学期累计名义暴露和订单次数预算；
- 误操作、资金耗尽或账户状态污染后自动转入 replay，不把联系客服重置作为课程依赖。

## 6. 同构降级路线

```text
longbridge_paper / longbridge_readonly
                  ↓ 不可用
course_replay（合成或获准使用的脱敏平台形状事件）
                  ↓
deterministic_fakebroker（公开/隐藏测试）
```

三种模式必须输出相同的 `run-summary` 与 evidence schema，并显式记录：

- `execution_mode`；
- 数据来源类型与截止时间；
- 是否真的调用外部平台；
- 意图、风控决定、订单/模拟事件状态；
- 本模式能够证明什么、不能证明什么。

学生不得把 replay/fake 事件描述成真实平台事件。平台不可用不扣分；没有记录失败、擅自绕过闸门或夸大证据才构成责任问题。

## 7. 开课前必须完成的 2～4 人试点

教师本人和 2～4 名接近目标学生水平的试做者，在干净 WSL 环境完成：

1. `uv` 安装当前 `longbridge` 包，确认不再使用旧的 `longport` 示例；
2. 注册、开发者验证、paper 开通和授权，记录完成率与 `p50/p80` 时间；
3. 在校园常用网络验证自动路由、`.cn`/`.com` 与 OAuth 回调；
4. 读取指定日 K，并验证历史数据额度、行情权限、时区和数据口径；
5. 验证提交器硬编码 `enable_papertrading=True` 会拒绝真实账户 token，并确认提交进程只能取得 paper token；
6. 验证普通 Agent 无法读取 token、直接调用提交器或跳过人类确认；做不到即判定只能 replay；
7. 用最小允许单位完成一笔限价模拟订单，查询状态并按规则撤单或核对成交；
8. 覆盖“写 PENDING 后崩溃、提交后响应丢失、重启、并发启动、超过幂等窗口、查询限流和拒单”，确认所有未知状态 fail closed；
9. 验证计划过期、余额/持仓/未完成订单变化和市场关闭时会在提交瞬间重新检查并拒绝；
10. 检查所有公开证据确实已经脱敏；
11. 测量 W4 只读任务和 W9 paper 任务的课堂 `p50/p80`；
12. 确认模拟资金、累计预算、允许标的、最小单位和课堂时段后，再冻结白名单及金额上限。

### Go / fallback 判定

- 若账号、网络和 paper 安全链能够由至少 80% 试做者在规定时间内完成，Longbridge 成为全班正式主路线。
- 若不能，Longbridge 保留为自愿的真实数据/平台试点；正式课堂外部事件改为 `course_replay`，确定性验收使用 FakeBroker。
- 无论判定如何，16 周周次、学生接口、报告格式和阶段门槛不改变。

## 8. 仍待试点填写、但不阻塞蓝图的参数

- 首版唯一认证路线；
- 课程白名单及最小模拟订单单位；
- 统一单笔、总暴露和每日订单数上限；
- 港股课堂时段与美股课外运行的取舍；
- 低频 job 由学生电脑手动启动，还是由学校提供受控运行环境；
- 原始行情在教学场景中的保存期限与再分发许可。

这些是实施参数，不再改变“先真实数据、后受控副作用、统一证据、同构 fallback”的课程结构。

# 学生仓库与证据契约

> 状态：当前高层边界。各周的接口、测试和提交动作，只有写进当周任务后才成为要求；不沿用[旧版契约](./student-repository-contract-v1.md)的里程碑周号。

## 稳定的目录边界

```text
course/                         教师任务、公开测试与固定数据
common/                         教师维护的公共能力
students/sXX/system/            学生唯一持续演化的系统
students/sXX/weeks/week-XX/     当周报告与允许公开的证据
```

每名学生由教师分配唯一公开代号 `sXX`，按实际名单扩展；代号不编码完整学号或姓名。约 30 人的规模不改变“一人一份系统、按周追加证据”的结构。学生只修改自己的目录；不为完成个人任务改写教师区、公共区或其他学生目录。

W2 是独立热身；W3 才从正式项目仓库建立个人系统。普通周持续更新个人 fork 的 `origin/main`，不使用 `dev-week-*` 分支。教师会给出公共代码的统一同步方式；学生不靠复制目录或猜测 merge 解决版本差异。

## 证据随能力增加

- W1～W3：环境状态、命令输出、公开测试、实际运行、diff 和 `ACCEPT / HOLD`；W3 不要求 CI。
- W4～W9：在唯一的 `system/` 中累计维护本地行情处理器，保留事前预测、运行轨迹、回归测试、故障定位与修复证据；不以手写比例评分。消息队列、网络服务和实时前端属于教师工程展示，不自动成为学生仓库要求，边界见[编程阶段专项设计](./w4-w9-progressive-programming-system.md)。
- W10～W15：数据来源及时间边界、模型与测试、受控订单计划、实际平台状态、账户前后变化、一次调整与两轮对照。未成交或 replay 必须按真实状态标注。
- W16：冻结版本、简短证据卡与个人书面核验；不安排逐人口头答辩或短视频。

公开仓库只保存合成数据、可公开的测试和脱敏摘要。凭证、完整账户响应、原始行情与未脱敏日志不进入学生工作区、Agent 对话、公开 Git 历史或 CI。真正下单的受信提交器必须与学生可写代码隔离，独立强制 paper 和风险限制；具体门槛见[Longbridge 决策](./longbridge-decision.md)。

## 尚未指定的流程

PR/tag 的汇总周次、报告 schema、隐藏测试及自动验收只在具体周任务成稿时确定。不能因为旧版文档写过 W6/W9/W14 或 `rc-w14`，就把这些步骤当作当前要求。教师按约 30 人、无助教重新核算评阅量；优先检查自动结果、异常与抽样，不预设每周人工阅读全部代码。

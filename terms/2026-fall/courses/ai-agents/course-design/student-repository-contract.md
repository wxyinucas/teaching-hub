# 学生仓库与证据契约

> 状态：当前高层边界。各周的接口、测试和提交动作，只有写进当周任务后才成为要求；不沿用[旧版契约](./student-repository-contract-v1.md)的里程碑周号。

## 一个网站仓库，一个课程代码仓库

`teaching-hub` 保存台本、Slides 与 Guide；`ai-agents` 是唯一当前课程代码仓库。新克隆示例为 `~/course/ai-agents`，已有的 `~/course/w02-workbench` 继续沿用，不强制改名或重新 clone。

```text
week-02/                        W2 独立项目、环境、签名与测试
week-03/ ～ week-09/             已有各周任务与独立环境
project/                        后续唯一持续演化的项目，内部结构待任务明确
legacy/market-lab/              旧项目中保留的参考素材，不是当前任务入口
```

周目录保存任务、样例、测试与参考；后续项目代码在同一份 `project/` 中演化，不每周复制源码。项目采用哪份起始基线、公共代码如何接入、记录放在哪里，由对应周任务明确。每名学生继续使用自己的课程仓库；公开标识不编码完整学号或姓名。

普通周持续更新个人仓库的 `origin/main`，不使用 `dev-week-*` 分支；教师会给出公共代码的统一同步方式。旧 `ai-agents-project` 退出当前教学流程，历史原件保留，可复用内容由 `legacy/market-lab/` 说明。

## W2→W3 的仓库接续

W2 是 `week-02/` 中的工作台热身，学生已在同一课程仓库完成本地 commit。W3 先沿用已打开的 VS Code 窗口接通 Agent，报告阶段更新同一仓库并进入 `week-03/`。两个周目录各用自己的 `pyproject.toml`、`uv.lock` 和 `.venv/`，共享同一份 Git 历史。

W3 材料唯一维护在 `ai-agents/week-03/`，教学网站只链接与说明，不另存下载副本。完成报告后，学生保留当前 Git 历史，将教师 remote 保留为 `upstream`，个人 remote 设为 `origin`，上传包含 W2 与 W3 的同一仓库；不增加第二个代码仓库、PR 或学生编号目录。已有根目录 W2 签名和提交，按代码仓库 README 的迁移步骤保留；更新异常的备用求助提示见 W3 Guide 末尾。

## 证据随能力增加

W4 继续使用同一 `ai-agents` 仓库，在 `week-04/` 使用给定的独立 uv 配置。学生修改 `variant.py` 与 `tests/test_student.py`，教师公开验收、候选切换工具和故障对照保持不变；本地提交保存本周成果，不新增分支、模拟远端、PR 或 CI 要求。W2、W3 和 W4 的环境各自独立。

W5 沿用同一仓库，在 `week-05/` 使用独立环境、Notebook、三道函数任务与公开测试。学生修改 `operations.py` 和 `tests/test_student.py`，本地通过后 push 到已有个人远端，由给定工作流重复相同测试。个人仓库默认检查 student，教师原仓库默认检查 reference；必须连同提交编号与模式阅读结果。网络或 Actions 受阻时先保留本地验收证据，如实记录远端未完成；不要求另建仓库、分支或 PR。

- W1～W3：环境状态、命令输出、真实 API 响应，以及 W3 报告的公开测试、实际实验结果、PDF、diff 和 Git 记录；W3 不要求 CI。
- W4～W10：围绕每周核心概念，保留事前预测、实际观察、与 Agent 共写的测试、实现或操作结果，以及对证据的解释；测试从 W4 贯穿，不以手写比例评分。跨语言对照和自由探索的设计边界见[W4～W10 专项设计](./w4-w9-progressive-programming-system.md)。练习可以接续，持续项目从对应任务启用 `project/` 时开始，不倒推此前各周必须共用同一份实现。
- W9～W15：W9 核对平台接入、数据批次、校验、描述性分析与授权清理；W10 保留决策与目标持仓的测试，W11 验算历史回放的仓位、现金、资产与费用；W12～W15 保留受控订单、实际账户状态、维护修复、一次调整与两轮对照。具体任务随当周台本明确；未成交或 replay 必须按真实状态标注。
- W16：冻结版本、简短证据卡与个人书面核验；不安排逐人口头答辩或短视频。

公开仓库只保存合成数据、可公开的测试和脱敏摘要。凭证、完整账户响应、原始行情与未脱敏日志不进入学生工作区、Agent 对话、公开 Git 历史或 CI。真正下单的受信提交器必须与学生可写代码隔离，独立强制 paper 和风险限制；具体门槛见[Longbridge 决策](./longbridge-decision.md)。

## W4～W10 的实验与验收

每周由教师给出简单可恢复的起始环境、少量 Agent Prompt 和明确验收条件。学生与 Agent 先写测试，确认测试能拒绝错误实现或错误状态，再写代码或执行操作使其通过；最后核对实际产物并说明结果。学生测试是学习产物，不能替代教师给出的外部验收条件；检查脚本、另一份符合规格的输入或预设错误反例可以提供独立核验。

学生需要掌握 Python、了解 R 与 Bash；Rust 和 C 仅在特定场景由教师展示，不要求学生安装工具链或本地编译执行。跨语言对照用于理解共同概念和语言设计取舍，不要求学生独立实现每一种语言的版本。

branch／push 与 merge 是可采用的探索题：在设计好的实验仓库中检查文件内容、分支状态与历史关系，push 使用模拟远端。实验中的分支操作不自动成为课程正式提交流程，也不改变持续系统启用后普通周更新 `origin/main` 的约定。

各周细编时再明确练习是否接续、起始基线、接口字段、目录路径与提交材料。旧 `market-check`、`market-replay` 和历史工程展示继续保留为已有材料；W9 的适配器、OOP 与并发不再是固定必达要求。正式持续系统启用时间与 W3 的接续方式仍须写进相应周任务。

# 第 0 单元至首次 Longbridge 实践：垂直教案（v1.0）

> 覆盖 W1～W4；每周 3 × 50 分钟，中间各休息 10 分钟；约 25 人、无助教。  
> 目的：验证课程开头能否从零基础设备自然走到本地 Agent 和真实平台数据，而不是追求第一周全班整齐安装完毕。

## 1. 这四周的唯一出口

到 W4 结束，学生至少能够：

> 从正确目录取得并恢复课程项目 → 用 `uv` 运行 → 让本地 Agent 做受控修改 → 检查 diff 和测试 → commit/push → 运行教师提供的 Longbridge/fixture 观察任务 → 解释数据来源、运行模式与证据边界

W1～W3 是第 0 单元。W3 配置 Agent 后立即运行第一个平台形状任务；W4 才把“学生个人的真实 Longbridge 读取”作为正式主任务。这样真实账号审批不会卡住第 0 单元，Agent 配置也不会变成脱离应用的孤立教学。

## 2. 每节课共用的任务卡

每个课堂任务都用同一张六栏卡，学生可以把它直接交给 Agent：

```text
目标：本任务结束时，系统应出现什么可观察状态？
入口：开始前必须已经具备什么？我目前处于什么状态？
允许动作：可以读/改哪些目录，可以运行哪些命令？
禁止与停止：哪些动作、权限、数据不能碰；什么情况必须停止？
完成证据：哪条命令、输出、文件或 diff 能证明完成？
失败证据：完整错误、已经检查的项目和下一步从哪里接续？
```

教师处理的是任务状态，不是 25 台机器的无限维修请求。同一故障阻塞 5 人以上时停止全班操作、统一解释；个别 BIOS、管理员权限、持续网络和账号审批进入独立补救，不占据共同主线。

## 3. W1｜课程责任与滚动安装

W1 的唯一实施依据是 [`weeks/week-01/`](../weeks/week-01/) 中的五文件合同；本节只保留四周之间的高层关系，不再复制分钟稿、命令或验收模板。

### 课时 1：介绍脱口秀

- 从工业革命类比进入“当执行变得廉价，人的价值在哪里”；
- 用黑箱／白箱区分责任封装与实现控制；
- 说明量化为什么同时包含确定性工程与不确定现实；
- 最后留下两句签字判断，不继续增加新知识点。

### 课时 2：WSL

- 教师只演示官方黄金路线、命令所在窗口和安全边界；
- 学生滚动安装，Chatbox 只做逐步解释与诊断；
- 第 40 分钟停止开新问题，提交 `READY-WSL` 或结构化 `BLOCKED-*`。

### 课时 3：VS Code/WSL

- 从 WSL 的固定课程目录执行 `code .`，连接 Windows 版 VS Code；
- 用系统、目录、编辑器和课程标记四项证据核验结果；
- 第 40 分钟停止个别排错，提交 `READY-CODE` 或结构化 `BLOCKED-*`。

`READY-WSL` 是过程检查点，`READY-CODE` 是 W1 成功出口。W1 只复制固定目录命令，不教授路径原理；W2 仍需正式学习并在陌生变体中重新验收。

### 本周五文件合同

- `week.json`：机器登记；
- `draft.md`：教师临时收件箱，不进入网站资源；
- `runbook.md`：教师掌控；
- `slides.md`：课堂舞台；
- `guide.md`：学生行动与精确验收。

### 停止规则

- Agent 索取密码/token、建议来源不明的高权限脚本、关闭安全功能、修改 BIOS 或不可逆清理时停止；
- 课后补做累计 1 小时仍失败时停止随机尝试，提交结构化状态；
- 安装速度不计分，故障记录的可接续性计入门槛证据。

## 4. W2｜路径、Git、`uv` 与可复现运行

> W2 是一个“不影响未来的本节课实验”：同学只在 fork 中改一项公开签名，我只凭对方的仓库 URL，在自己的机器恢复环境、运行程序并观察这项改动。它不构成 W3 的代码基础。分钟级实施以 [`weeks/week-02/runbook.md`](../weeks/week-02/runbook.md) 为唯一依据。

### 课时 1：看懂项目为什么需要运行契约

- 区分全局工具、项目局部环境和环境变量的进程可见性；
- 用 uv 与 conda 说明环境组织方式，不把二者简化成全局／局部；
- 区分 local、remote 与 Git 版本记录；
- 认识 `course-check 0.1.0`、`pyproject.toml`、`uv.lock`，并辨认 Python、项目版本和 Git 版本记录回答的是不同问题。

### 课时 2：在 fork 中制造一个可见变化

- 教师完整示范 `clone → 定位 → sync → 运行 → 测试`，说明每一步在主链中的作用；
- 学生在 GitHub 网页 fork 课程仓库；
- 只把 `signature.toml` 中的 `teacher` 改为本人公开代号；
- 两人只交换个人 fork 的 HTTPS URL，不交换 commit、答案或运行截图；
- 预检 WSL、Git、uv 和空目标目录，为第三课时留出完整运行时间。

### 课时 3：在自己的机器发现同学签名

- 两人分别在自己的机器新 clone 同学的 fork；
- 进入 `warmups/week-02/course-check`，用 `uv sync --locked` 重新恢复 `.venv`；
- 使用 `COURSE_MODE=fixture` 运行体检程序和给定测试；
- 完成条件是程序与测试通过，并且输出显示同学代号而不是 `teacher`；
- 最后只记录“我的机器是否通过、看到的同学代号、一项观察”。

### 本周边界与教师材料

- 教师提供公开课程练习仓库、非 `teacher` 的示例 fork、干净 WSL 实测记录和已缓存 fallback；
- W2 不修改 Python 逻辑、不要求本地 commit/push、不接平台和凭证；
- 测试只检查程序是否按规则读取并展示签名；“是否看到了同学签名”由运行者判断，借此区分自动检查与人的结论；
- 快组解释输出字段和测试边界，不提前进入 W3；
- W2 课后开放 Longbridge paper 注册状态登记，但账号状态不构成成绩门槛。

W2 课后开放 Longbridge paper 注册状态登记：只记录 `未选择 / 申请中 / READY / BLOCKED-REGION / BLOCKED-IDENTITY / BLOCKED-NET / 选择 REPLAY`，不收集账号、身份材料、截图或 token。它为 W4 分流服务，不构成成绩门槛。

## 5. W3｜本地 Agent 责任闭环与第一次平台形状任务

### 课时 1：Agent 的工作目录、权限和 GitHub 关系

**唯一可观察目标**：Agent 只能在指定课程项目内工作；学生的 fork/origin 与教师 upstream 已辨认。

| 时间 | 活动 |
| --- | --- |
| 0～8 分 | Agent、GitHub 和 W2 补测状态检查；不在大屏暴露任何个人登录信息 |
| 8～18 分 | 演示工作目录、允许读写范围、命令审批、密钥边界与停止条件 |
| 18～32 分 | 从 W3 的新入口建立个人 fork，配置 `upstream` 与 push 认证；执行一次同步与 push |
| 32～43 分 | 学生让 Agent 只读项目并复述任务/边界，不立刻修改 |
| 43～50 分 | 检查 Agent 计划会改哪里、会运行什么；不合格计划先修改提示 |

### 课时 2：修改、审查、测试、提交

**唯一可观察目标**：完成一次 Agent 产物的验收，而不是只取得成品。

| 时间 | 活动 |
| --- | --- |
| 0～8 分 | 展示任务规格和给定测试，不讲实现 |
| 8～25 分 | Agent 完成一个极小行为修改；学生观察过程 |
| 25～35 分 | 学生检查关键 diff，确认没有越界文件和依赖变化 |
| 35～43 分 | 运行原测试和一个陌生小测试；不通过则回到规格/实现 |
| 43～50 分 | commit/push，并写一句收尾复核与 `ACCEPT/HOLD` |

预制快进故障包括：Agent 改错目录、顺手升级依赖、删除失败测试、只在当前机器硬编码路径、测试绿但规格错误。快组处理其中之一，不提前做下周内容。

### 课时 3：配置完就进入实践

**唯一可观察目标**：从同一命令得到一份明确标注 `longbridge_readonly` 或 `fixture` 的数据观察摘要。

| 时间 | 活动 |
| --- | --- |
| 0～8 分 | 教师用自己的 paper 身份演示一次真实只读历史 K 线；不显示凭证和原始账户信息 |
| 8～15 分 | 追踪 `source → adapter → normalized rows → checks → summary` |
| 15～35 分 | 全员运行预制 `observe`；个人授权与隔离取数负向测试均通过者可用行情路线，其余使用 fixture |
| 35～43 分 | 学生互换摘要，判断对方是否如实标注运行模式、查询截止时间与数据来源 |
| 43～50 分 | 生成 W3 manifest，说明真实读取和 fixture 分别能证明什么 |

这节课不教授 SDK，也不要求学生自行拼装请求。目标是让他们在 Agent 配置完成的同一天看见：程序已经在处理一个现实平台的问题，而后续课程要逐步接管证据与责任。

### 门槛 0

学生必须能够现场或补测完成：

> 正确目录 → 锁定环境 → 给定测试 → Agent 受控修改 → diff → 再测试 → commit/push

并解释 Agent 权限、至少一个测试及观察任务的运行模式。平台账号不是门槛 0 的条件。

### 本周教师材料

- 一个只有单一可改行为的练习任务和参考/故障实现；
- Agent 权限任务卡、diff 审查卡和 GitHub fork/origin/upstream 图；
- `observe` 命令、合成 Longbridge 形状 fixture、脱敏摘要生成器；
- 教师真实读取的本地录屏与静态截图，避免现场网络失败；
- 门槛 0 自动检查和 3 分钟口头追问清单。

## 6. W4｜学生自己的首次 Longbridge 只读实践

### 课时 1：真实响应为什么不能直接成为课程数据

**唯一可观察目标**：学生能说出平台响应、内部数据契约和公开证据不是同一文件。

| 时间 | 活动 |
| --- | --- |
| 0～8 分 | 统计账号/网络状态；状态只决定运行模式，不决定成绩 |
| 8～20 分 | 教师沿一个脱敏样例解释 symbol、日期、时区、OHLC 和查询截止时间 |
| 20～34 分 | 学生先预测重复、乱序、缺失、未来行分别应如何处理 |
| 34～44 分 | 运行适配器和契约检查；定位规范化前后字段 |
| 44～50 分 | 写出本节唯一主张及所需证据 |

### 课时 2：个人读取或同构 fallback

**唯一可观察目标**：取得小规模数据并通过课程契约，不以 API 成功为唯一成就。

| 时间 | 活动 |
| --- | --- |
| 0～10 分 | 通过 Agent 不可读的隔离取数命令或服务使用个人 paper/行情授权；若该边界未通过负向测试，全员改用 fixture |
| 10～32 分 | 读取指定标的日 K；失败者按状态切换 fixture，而不是随机改 SDK |
| 32～42 分 | 验证排序、唯一性、价格关系、时间范围和 `as_of` |
| 42～50 分 | 保存原始数据到仓库外，仅生成指纹和规范化摘要 |

### 课时 3：证据也要接受质疑

**唯一可观察目标**：学生能解释一个数据测试为何正确，以及它没有覆盖什么。

| 时间 | 活动 |
| --- | --- |
| 0～10 分 | 教师展示一个“测试全绿但查询包含未来一天”的故障摘要 |
| 10～28 分 | 学生补一个边界检查或用教师 test data 击穿故障实现 |
| 28～39 分 | 同伴按“主张—证据—不证明”表追问 |
| 39～47 分 | Agent 做收尾复核：越界文件、凭证、运行模式、时间边界、失败测试 |
| 47～50 分 | 形成 `ACCEPT/HOLD/BLOCKED` 和下周从数据到订单意图的入口 |

### 本周最低完成线

- 一份包含 `event_time`、`available_at` 和查询 `as_of` 的课程格式数据摘要；
- 一个能够解释的契约测试；
- 来源、查询时间、`as_of`、运行模式与数据指纹；
- 原始行情和凭证不在公开仓库；
- 真实平台失败者另有结构化故障记录和同格式 fixture 结果。

### 本周教师材料

- 经试点冻结的唯一 Longbridge 认证/读取路线；
- 当前 `longbridge` 包与 `LONGBRIDGE_*` 命名检查，明确拒绝 Agent 常生成的旧 `longport` 示例；
- 一个脱敏字段样例、一个合成 fixture、四种小型坏数据；
- 适配器参考实现、契约测试和故障实现；
- 凭证/数据红线卡、本地 pre-push 扫描、允许列表式证据导出与自动脱敏检查；
- 明确禁用项目 `.env`、SDK 自动加载项目凭证和未脱敏 SDK 日志；普通 Agent 读取 token 或调用交易提交器必须失败的负向测试；
- 平台状态到 fallback 的一页决策树。

## 7. 没有助教时的课堂队列

学生求助前先提交：

```text
任务编号 / 当前状态码 / 完整错误 / 已运行的只读检查 / Agent 建议 / 是否涉及权限或凭证
```

教师按下列优先级处理：

1. 可能泄露凭证、误触真实账户或破坏数据的安全问题；
2. 同时阻塞 5 人以上的材料/环境问题；
3. 无 fallback 且影响当周最低线的问题；
4. 有 fallback 的个人问题；
5. 快进任务。

完成者不是临时助教。他们可以用核对表检查同伴证据，但不能代输密码、代授权命令、接管机器或替别人签字。

## 8. 试做记录与推进规则

开课前由教师和 2～4 名近似零基础试做者完成这四周的核心任务。每个任务记录：

- 计划时间；
- 实际 `p50/p80`；
- 失败类型与恢复路径；
- Agent 首次建议是否安全、是否有效；
- 最低线完成率；
- 课外实际耗时。

课堂采用以下推进规则：

- 单课时核心任务的 `p80` 目标不超过约 40 分钟；
- 当周最低线完成率低于 80% 时，下周课时 1 先补救，不再增加新的关键依赖；
- 同一问题阻塞 5 人以上时视为课程系统故障；
- Longbridge 真实路线低于 80% 可用时切换为 fixture/replay，不把账号问题包装成学生能力不足；
- 任何尚未由教师完整跑通并准备故障/fallback 的内容，只能演示或选做。

## 9. 这四周的材料包形式

每周只制作一套单一来源材料：

1. 8～12 张课堂 Slides，负责问题、演示与共同节奏；
2. 一页学生任务卡，负责操作、停止条件和证据；
3. 仓库中的可运行骨架、公开测试、故障实现与 evidence 命令；
4. 一段 3～5 分钟本地录屏，作为现场网络/平台失败的演示 fallback；
5. GitHub Pages 上的可搜索文字版；
6. PDF/离线包作为教室网络失败时的备份。

学生产物仍以仓库中的 `system/ + weekXX/report.md + manifest.json` 为真源；不要求每人维护一套网站，也不把 Jupyter 当作必须掌握的提交界面。

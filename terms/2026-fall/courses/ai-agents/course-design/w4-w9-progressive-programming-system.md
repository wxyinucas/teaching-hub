# W4～W10：概念与自由探索

> 状态：2026-10-14 已确认的编程阶段框架。本文约定语言对照、实验与验收方式；概念顺序、探索题型和验收方向以[16 周课程蓝图](./16-week-blueprint.md)为准。各周接口、输入输出、Prompt、材料与课时细节在当周台本中明确。

## 1. 每周以一个概念为基石

W4～W10 围绕名字、对象与可变性，容器与迭代、键值对与映射、函数与可见性、模块组织与加载、异常与失败边界、外部接口与数据边界递进。一个概念对应一个能够反复追问的中心问题，再围绕它增加实验、对照、反例与较大的自由探索。

三课时围绕同一个具体矛盾连续推进，常见的重心是：

1. 让预期与实际操作发生冲突，留下需要解释的问题。
2. 用小实验、反例和跨语言对照排除解释、检验修复；每个例子必须推进同一问题。
3. 把尚未兑现的承诺交给自由探索，与 Agent 合作写测试、实现、核验并解释。

概念在解释矛盾时出场，不按术语目录轮流介绍。每个推进段都要说清楚学生先预测什么、教师操作什么、实际结果如何挑战预测、什么证据能够区分解释，以及为何需要下一步。

课时是软检查点，完整教学周是备课与放行单位。台本采用知识地图、三张整课时卡片和卡片内目录；根问题、最低出口、硬收口及临场取舍放在可展开的正文中。通用容量与冻结方法以[通用备课系统](../../../../../docs/prep-system.md)为准。

分支、循环、文件读写和调用等支撑知识按当周实验需要引入。前几周可由教师提供函数壳、数据读取和启动脚本，到相关周次再研究它们；测试从 W4 开始使用。

## 2. 语言目标与对照方法

| 语言 | 学生目标 | 使用方式 |
| --- | --- | --- |
| Python | 掌握 | 概念学习、主要实验、写测试、实现与验收。 |
| R、Bash | 了解 | 阅读和理解同一概念的表达与行为，完成与工作台相关的必要操作。 |
| Rust、C | 特定场景了解教师展示 | 教师展示源码、已准备的编译产物或实际运行结果；学生不需安装工具链或本地编译执行。 |

跨语言对照沿同一条线展开：

`共同问题 → 各语言形式与实际行为 → 共同结构 → 不同重点及其取舍 → Python 实践`

比较时使用同一个小问题和可对照的输入输出，分别辨认形式差异和语义差异：名字或写法不同，是否仍表达相同关系；语言施加了哪些约束，实际行为又如何变化。优劣结合当前任务、使用便利、错误发现时机和理解成本讨论。

每次选择最有解释力的一种或少数几种对照。解释执行与编译执行只是一个具体知识点，当前放在 W4 的可选 C 展示中，用教师预先跑通的示例观察实际工具链；它不是跨七周的语言分工。后续容器、映射、作用域和模块仍按各自共同问题对照。

## 3. 自由探索任务合同

每个教学周留一个较大的自由探索任务。任务的目标和验收条件明确，实现路径允许学生与 Agent 自行选择。

| 教师提供 | 必须明确的内容 |
| --- | --- |
| 简单实验环境 | 初始文件、必要数据、启动方式和可恢复状态；环境准备不吞掉概念学习。 |
| 探索目标 | 要实现或观察的行为、允许修改的范围及最终产物。 |
| 少量 Prompt | 帮助提出预期、设计测试、构造反例和定位失败，保留探索空间。 |
| 明确验收条件 | 可检查的输入输出、错误行为、文件或仓库状态；规则在开始前公开。 |

学生完成以下循环：

1. 读懂目标和验收条件，写下至少一个事前预测。
2. 与 Agent 合作设计测试，用已知答案或错误案例核对测试确实能发现问题。
3. 再编写代码或执行操作，处理测试暴露的失败。
4. 亲自运行检查，打开实际产物，核对 diff、输出或仓库状态。
5. 解释结果、一次修正以及证据仍未覆盖的地方；受阻时保留真实状态。

学生与 Agent 共写的测试是学习产物；教师给出的验收条件是外部依据。教师准备一份错误反例或另一份符合公开规则的输入，避免测试和实现共同接受同一个错误假设。具体测试接口、公开用例及提交形式在当周任务中明确。

Git 探索可以使用状态检查脚本以及文件、提交历史与远端记录作为测试证据。W4 在已有 `ai-agents/week-04/` 围绕投针实验配置隔离先写测试再实现，沿用本地提交，不要求新分支或模拟远端。branch／push 若另作探索，使用设计好的实验仓库和模拟远端；W8 的 merge 使用预设分支与冲突。实验不自动改变正式提交路线，实际流程以[学生仓库契约](./student-repository-contract.md)和当周任务为准。

## 4. 实验代码与跨周接续

当前 W3 独立维护投针报告，不建立行情系统。W4 的起始环境与 W3 的接续步骤须在详细台本中明确。

练习可以共享小素材或继续维护已有程序；是否接续、采用哪份基线、目录路径、接口字段和提交动作由各周任务明确。接续时保留已有版本和明确的行为合同，用原有测试保护重构与修复。新任务不自动继承尚未发布的接口和测试要求。

旧 `market-check`、`market-replay` 与历史工程材料继续作为已有素材保留，不再按旧周次作为固定要求。正式 `students/sXX/system/` 何时建立由当周任务决定；启用后的所有权与证据边界仍按学生仓库契约执行。

## 5. 阶段出口与证据

W9 结束时，学生能够借助 Agent 阅读一段短小的 Python 程序，并亲自：

- 说明值与名字的关系，以及容器、迭代和映射怎样决定结果；
- 找到函数的输入输出、可见名字、模块入口和导入行为；
- 预测正常与错误输入的结果，用测试、实际运行和 diff 核对；
- 说明测试为什么能拒绝某个错误，以及还不能证明什么；
- 解释一处跨语言差异涉及写法、约束还是实际行为。

学生的学习证据包括事前预测、实际观察、测试与结果、实现或操作的改动，以及自己的解释。它们按任务实际需要保留，不预设每周长报告、完整 Agent 对话或逐人口头展示。

## 6. W10 与后续量化实践

W10 以外部接口与数据边界为中心，先用固定模拟响应检查正常、缺字段与调用失败，再接续真实只读历史数据。Longbridge 模拟环境、最小只读授权、固定调用、撤销与退出保留为真实接续方向；平台细节须由教师在授课前复测。

固定响应实验与账号、授权、调用、清理等环节如何分配时间，在 W10 细编时明确。实际系统怎样接入数据来源及采用什么接口，也由当周任务说明；不提前冻结适配器、事件字段或工程选型。

W11 才让有时间边界的数据进入决策模型，W12 才接触教师受信设施中的受控模拟订单。既有的 paper、凭证隔离和风险边界继续执行，详见[课程蓝图](./16-week-blueprint.md)与[Longbridge 决策](./longbridge-decision.md)。

## 7. 教师展示与材料放行

教师按当周概念选择对照和工程展示；多进程、队列、实时前端或最小 OOP 可以作为特定场景素材，不构成新的固定周次或学生基础设施要求。每次展示只有一个明确观察问题，教师先跑通并准备真实记录作为退路。

台本是内容源，先集中开发并敲定当周 runbook，不同时推进派生材料。课堂以现场操作、真实输出和随调查更新的关系图为主；Slides 只辅助停住问题、对照或证据，是否需要及数量随后决定。Guide 需要时承载学生独立执行的步骤、短 Prompt、验收条件与接续方式。台本主线、顺序和收口确认后再生成或同步所需材料；网站组件、布局和交互按实际解析器与渲染实现选择。

编程关系图顶部固定两行短代码：必要的初始状态、本次操作或查询。主体用名字、对象和引用说明修改位置与后果，旧对象在上、新对象在下；紫色突出本次变化，灰色虚线只表示已解除的旧指向。不变字段可省略，不另铺一套前后数值清单。

框架已确认，W4 以论文追加实验的两次配置污染贯穿台本；新版 Guide、Slides 和 `ai-agents/week-04/` 实验包已在本地对齐，含函数壳、两份故障、公开参考、教师验收及 Notebook。学生测试初始留空，与 Agent 自行编写；教师和学生测试分开核验。真实设备与投影待教师课前复测，不自动视为课堂冻结。W10 的现有材料继续保留，按当周接口与数据边界细化后再同步；各周只在所需材料可执行、可核验、可收口后冻结。

# W01 第一课时内容结构：当 Agent 足够强，我们还要学什么？

> 状态：第一轮可试讲结构。本文只组织第一课时的叙事、判断与课堂出口，不是逐字讲稿，也不展开第二、三课时的安装教学。

## 本节唯一总问题

> 当 Agent 的执行能力越来越强、执行成本越来越低，我们还需要学习和积累什么？求职时，我们能够证明的价值是什么？

本节不要求学生记住一个完整的 Agent 定义。学生离开时应当形成以下判断：

> 不与 Agent 比较执行速度，而要学会激发、约束和验收它的能力，并对交付给现实世界的结果负责。

## 叙事主线

```text
工业革命改变生产结构
        ↓
Agent 从“回答”走向“行动”
        ↓
如果执行变得廉价，人应当积累什么？
        ↓
黑箱：通过责任封装获得可交付的结果
白箱：通过 CS 知识获得选择性的可见性与干预能力
        ↓
量化同时暴露确定性系统与不确定现实
        ↓
可以使用 Autopilot，但最终必须验收、解释并签字
```

## 0｜故事引入：工业革命时期的家庭纺织

设想一户以农业为主、用家庭纺织补贴生计的人家。机器、资本和工厂改变了纺织品的成本与组织方式之后，家庭作坊即使不愿改变，也必须面对价格和生产结构已经变化的现实。

这个故事只承担三个判断，不展开为工业革命史：

- 技术进步提高的首先是整个生产系统的效率；
- 系统生产力提高，不等于每个具体劳动者都得到减负；
- 当社会生产结构发生变化，个人是否采用新技术不再只是个人偏好。

由此转入今天的问题：Agent 会不会像机器与工厂一样，改变工作的分工、岗位和评价标准？

## 1｜看见变化：Agent 从回答走向行动

通过 Chatbox 与本地 Agent 的对比和一次简短现场演示，让学生看到：

- Chatbox 主要给出回答、解释或操作建议；
- Agent 可以读取文件、运行命令、操作工具并留下实际产物；
- Agent 能够完成超过使用者当前知识边界的任务。

现场只追问三个问题：我们提出的要求变了吗？人的介入程度变了吗？对使用者知识与判断的要求变了吗？

## 2｜价值危机：我们还要和 Agent 比什么？

如果人不会和拖拉机比赛耕地，也不会和卡车比赛负重，那么学生不应当把“比 Agent 更快地执行任务”作为自己的主要价值。

需要把问题明确落到学生身上：

> 如果 Agent 足够强，可以帮助我们完成几乎所有确定性的想法，那么我们应当积累什么？将来求职时，我们能够展示什么不可轻易替代的价值？

## 3｜黑白箱心智模型

黑箱和白箱不是互斥阵营，也不分别等于“不懂”与“全懂”。它们是面对复杂 Agent 系统时，两种互补的介入方式：

- **黑箱视角**：不追踪每一个内部步骤，通过输入、输出、约束、契约和证据判断结果能否交付；
- **白箱视角**：在风险较高或证据不足时，打开关键层，检查环境、数据、代码、依赖、权限和运行过程。

只盯最终结果可能失去控制；试图打开所有内部过程又会耗尽人的注意力。真正的能力是根据风险判断：哪些部分可以封装，哪些部分必须打开。

## 4｜黑箱：学生是一层责任封装

学生可以把 Agent 作为黑箱使用，但不能把责任也封装进去。对老师或未来的领导而言，学生本身应当形成 Agent 外面的一层责任边界：

```text
老师或领导的任务
        ↓
[学生：规划、约束、验收、解释、担责]
        ↓
[Agent：实现与执行]
```

学生最终向上交付的不是一个孤立结论，而是：

> **结论 + 证据 + 适用边界 + 责任人**

一句不严格的类比：

> 对上，他像政委，是一层责任封装，保证这支 Agent 队伍可靠、可托付、能打硬仗。

黑箱不等于甩手。即使不理解每一行实现，仍然需要规划任务、规定禁止项、设计验收并说明证据边界。

## 5｜白箱：CS 知识提供选择性的控制

CS 知识不是为了让学生重新和 Agent 比赛写代码，而是提供一套能够准确沟通、定位问题和实施干预的共同语言。本课程会逐步接触：

- WSL、Shell、文件、路径、进程与权限；
- Git/GitHub 所表达的版本、差异、历史与协作；
- Python 项目、`uv`、依赖与可复现环境；
- 数据、函数、接口、API、资金计算与订单流程；
- 测试、CI、安全边界、数据泄露与风险控制。

一句不严格的类比：

> 对内，他像团长，是一层实现封装，知道仗应当怎样组织、哪里需要介入、出问题时应当打开哪一层。

白箱不等于亲自冲锋或手写全部代码。它要求学生能够在关键位置看见系统，并获得必要的干预能力。

## 6｜我们真正积累什么

本节暂时把可迁移的积累归纳为三类：

- **系统理解**：理解工具、环境、数据和程序之间的关系；
- **工作方法**：把模糊意图变成任务、边界、接口和可检查结果；
- **判断经验**：评价证据，承认证据的边界，并根据现实反馈修正决定。

学生将来能够证明的价值，不只是“我知道某个模型怎么用”，而是：

> 我能把一个模糊问题组织成可执行的系统，调动 Agent 完成它，用可反驳的证据判断结果，并对最终决定负责。

## 7｜为什么选择量化

量化在同一个小系统里同时包含两类问题：

- **确定性系统**：数据是否在当时可用、资金计算是否正确、订单是否符合接口与风险规则。这些可以通过规格和测试进行验收；
- **不确定现实**：策略是否有效、市场将怎样变化、一次盈亏意味着什么。这些只能通过持续实验、现实反馈和事后复盘逐渐认识。

因此，量化只是本课程的 playground，而不是本节要教授的统计或金融知识：

> Agent 可以帮助我们实现确定性的想法，但不能替我们消除不确定性；程序做对了，不等于未来一定赚钱。

## 8｜课程契约与最终出口

课程允许学生使用 Autopilot，也不把“每一行代码是否由本人敲下”作为评价对象。但是，最终提交、解释和签字的人必须是学生。

学生需要能够说明：

1. 自己要求系统做什么、禁止它做什么；
2. 凭什么认为系统已经做到；
3. 现有证据不能证明什么；
4. 面对结果，自己作出什么决定并准备承担什么后果。

## 离场凭证

以后每节课的最后阶段停止增加新内容，每名学生都要留下一个很小但可以检查的离场凭证。它不是签到，而是证明本节形成了什么判断、完成到什么状态，以及下一步从哪里继续。

第一课时只回答两句话：

> 当 Agent 交付一个漂亮结果时，我签字前还需要 ______。
>
> 即使这些证据成立，它仍然不能证明 ______。

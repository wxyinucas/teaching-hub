# W1｜面对 AI Agent，我们应该做什么准备？

> AI Agent 课程 · W1 · 3 × 50 min · 约 25 名零基础学生 · 无助教

## 本次课

- 根问题：当 Agent 能够承担大量执行工作时，人应该怎样理解自己的身份与责任，并搭起可核验、可接续的工作台？
- 最低出口：第一课时留下关于“人的身份与责任”的问题，并区分 Agent 的行动能力、黑白箱视角与结果的不确定性；第二、三课时分别保存 `READY-WSL`／`READY-CODE`，或可接续的 `BLOCKED-*` 状态。
- 硬收口：第一课时最后 3 分钟停止增加例子，回到“人的身份与责任”；第二、三课时第 40 分钟停止新安装与新排障，末 10 分钟只保存真实状态、卡点和下一步。

## 第一课时 · 当 Agent 能够执行，人还负责什么？

### 0-8 | 看见 Agent 在执行工作

> Agent 不只生成回答，它还能观察界面、调用工具并连续完成任务。

#### 课前提醒

- [ ] 在无个人账号信息的 Chrome 环境完整跑通提示词；固定目标为 **《欢迎来到未来》**，[Bilibili · `BV1pb8o6yE8f`](https://www.bilibili.com/video/BV1pb8o6yE8f/)，现场不先透露标题或 BV 号。
- [ ] 保存搜索过程、目标页面和最终回答三张脱敏画面；第 6 分钟未完成就切换 Plan B，第 8 分钟必须转场。
- [ ] 演示只读公开网页：不登录，不读取 Cookie、token 或个人信息，不找媒体流地址，不下载视频，不临时追加任务或权限。

- 展示：把以下提示词原样交给浏览器 Agent。

```text
请打开一个新的 Chrome 无痕窗口，帮我在 Bilibili 找到“jyy 在 2026 年下，和我们类似的 AI Agent 课程”。

先搜索和判断，不要直接猜网址。找到后证明你选对了，再使用 Chrome 开发者工具读取页面公开信息，补充页面没有直接展示的内容并相互核对。

最后告诉我：你找到了什么、依据是什么，以及这些证据仍不能证明什么。现在开始。
```

- Computer Use：观察屏幕 → 操作界面 → 读取结果 → 继续行动。
- Agent 和以往 Chatbox 模式最大的区别是什么？
  - 做了原本需要人完成的外部动作;
  - 不只给出建议，还可以直接与不同程序交互并继续推进任务。
- 人不再必须先掌握全部操作细节，才让任务开始执行；
  - 写代码、运行程序和根据错误继续修改，也是同一种“观察—行动—反馈”循环。

### 8-17 | 用好 Agent，也要保留学习反馈

> 充分使用 Agent，与主动保留学习反馈并不矛盾。

#### 课前提醒

- [ ] Slides：任务完成 → 反馈减少 → 主动重建，使用从左到右的三栏布局。

- 飞行员会不会为了练习技术而拒绝自动驾驶？
  - 不会；完成飞行时，应该使用可靠而高效的工具。
- 飞行员为什么还要进入模拟机？
  - 自动驾驶完成任务的同时，也可能吸收原本属于人的尝试、错误和修正。
- Agent 降低了完成任务的门槛；
  - 作品变得更好，不等于人的能力也同步提高。
- 我们不需要拒绝 Agent，也不需要怀念低效率；
  - 真正需要主动补回的，是能够暴露错误、修正判断的反馈。
- 留给全学期的问题：
  - 哪些反馈对我的成长真正重要？
  - 我怎样判断变强的是自己，而不只是工具？


### 17-29 | 从“它做完了”到“我来负责”

> 执行与过程判断可以委托，最终决策与责任不能转移。

#### 课前提醒

- [ ] 准备 Slides“当执行变得廉价”“我们真正积累和证明什么”和“代码可以交给 Agent，责任不能”。

- 课程允许 Autopilot，也不追查代码究竟由学生、同伴还是 Agent 写；
  - 只要以学生的名字提交，学生就必须对安全合规、验收证据和结论边界负责。
- 从当下任务看，人不再只是执行者，还要承担管理者的责任：
  - 提出目标与限制；
  - 选择并判断证据；
  - 说明结论的适用边界；
  - 决定接受、拒绝或继续检查。
- 从长期学习与深入控制看，人也需要主动进入执行过程：
  - 保留能够暴露错误、修正判断的反馈；
  - 积累必要时能够接管和干预的能力。
- 以后每一次正式提交，都等同于你们写下：“这是我决定提交的结果，我愿意为它负责。”
- 负责是否意味着，审核 agent 结果，就是重做 Agent 的每一步？
  - 不；但它意味着，合作过程中，有足够“证据”决定接受、拒绝或继续检查。

### 29-40 | 不懂每一行，也要守住关键位置

> 黑箱和白箱不是系统的固定状态，而是为了不同目的选择的观察视角。

#### 课前提醒

- [ ] 准备 Slides“黑箱与白箱”“我们守在交互的边界”和 CS 知识地图。

- 一个系统并不“天然是”黑箱或白箱；同一个系统可以在不同层级切换视角：
  - 当作黑箱：强调调用，关注输入、输出、接口、约定和验收；
  - 当作白箱：进入实现，关注结构、状态、依赖和可以介入的位置。
- 视角不同，关注点和责任也不同：
  - 对外保证要求明确、结果可验收、边界说得清；
  - 对内保证关键状态看得见，必要时能够控制和排错。
- 白箱不是一路展开到底：只打开当前问题所需的抽象层级，更底层的细节仍然可以继续封装。
- 类比：同一个人对外像“政委”，保证队伍可靠、能打硬仗；需要进入实现时又像“团长”，决定具体怎样打。
- 本课程首先打开“人—Agent 工作系统”：文件与路径、命令行、权限、Git、依赖、接口和测试。
  - 大模型内部的参数和推理机制处在更底层的抽象层级，当前继续封装。
  - 后两课时先看终端、目录和保存状态，这是第一次进入当前所需的白箱层级。

### 40-50 | 量化：做对了，也未必有好结果

> 责任不是控制一切，而是把可控的部分做到位，诚实面对不可控的部分，并不断校准两者的边界。

> 赐我宁静，接受无法改变的；赐我勇气，改变能够改变的；赐我智慧，分辨两者。

#### 课前提醒

- [ ] Slides：用“可控／不可控／继续分辨”三栏组织内容，最后回到“人的身份与责任”。
- [ ] 最后 3 分钟停止增加例子，不安排填写或签字。

- 可控的部分：
  - 把目标、数据、接口、资金计算、风险规则和停止条件说清楚；
  - 在约定的输入、规则和覆盖范围内，用测试和其他证据支持“程序正确执行了想法”。
- 不可控的部分：
  - 即使这些工作全部做对，也不能保证未来一定盈利；
  - 接受随机性的存在，不为现实虚构确定性。
- 暂时分不清的部分：
  - 观察真实反馈，检查已有解释；
  - 设计下一次能够区分不同解释的实验。
- 不能用随机性掩盖程序错误和失控风险，也不能用程序正确承诺未来盈利。
- 回到本节：
  - Agent 让执行变得更便宜以后，人仍要选择目标、视角和证据，并对自己的判断负责。
  - **留给全学期的问题**：当 Agent 越来越强，什么仍然属于人的能力与责任？

## 第二课时 · 把 WSL 变成可核验状态

### 0-8 | 先认窗口，再动系统

> 先说清在哪个窗口、要做什么，再执行命令；认不清就先停。

#### 课前提醒

- [ ] 在学校电脑准备普通 PowerShell、管理员 PowerShell、Ubuntu／WSL 三个画面，以及一份完成重启与 Ubuntu 初始化的演示环境。
- [ ] 确认 Windows 10 2004（Build 19041）以上或 Windows 11、管理员权限和重启条件；学校电脑不满足时只演示预存环境。
- [ ] 不临时修改系统设置，不借用他人账号，不运行来源不明的修复脚本。

- 展示：`wsl --install` 只在 Windows 管理员 PowerShell 执行；Linux 命令只在 Ubuntu／WSL 执行；VS Code 留到第三课时。
- 让学生做：保存手头工作，确认自己的 Windows 版本、管理员权限和是否能够重启；暂不执行安装命令。
- 检查：学生能指出自己当前打开的窗口，以及下一条命令准备在哪里运行。
- 分流：无管理员权限记 `BLOCKED-PERM`；系统版本或重启条件不满足记 `BLOCKED-OS`。

### 8-15 | 一次看完唯一安装路线

> 主线只有安装、重启后进入 Ubuntu，再分别核验 Windows 与 Linux 两侧。

#### 课前提醒

- [ ] 打开 [Microsoft WSL 安装说明](https://learn.microsoft.com/zh-cn/windows/wsl/install)；准备安装前和重启后两个状态，避免全班等待下载与重启。
- [ ] 本段不进入 BIOS，不关闭安全功能，不删除发行版，不运行“一键修复”；第 15 分钟把操作交给学生。

- 展示：在 Windows 管理员 PowerShell 中运行或展示：

```powershell
wsl --install
```

- 展示：切到准备好的重启后状态，首次打开 Ubuntu 并创建 Linux 用户；说明密码输入时不显示字符是正常现象。
- 展示：在普通 PowerShell 核验发行版和 WSL 版本：

```powershell
wsl --list --verbose
```

- 展示：在 Ubuntu／WSL 中运行 `pwd`、`whoami`、`cat /etc/os-release`。

### 15-30 | 从自己的真实节点继续

> 每次只推进一个真实动作；系统没有给出结果，就不能假设这一步已经成功。

#### 课前提醒

- [ ] 准备 Slides“让 Chatbox 帮我达到 READY-WSL”、Guide 手动路线和 `BLOCKED-*` 模板。
- [ ] 密码不展示、不截图，也不发送给教师、同学或 Agent；重启前先保存工作。
- [ ] 出现 BIOS／虚拟化修改、未知管理员脚本、关闭安全功能或删除发行版等建议时立即停止并记录；同一问题阻塞 5 人以上才暂停全班统一说明。

- 让学生选择：直接按 Guide 操作，或复制 Chatbox Prompt 让 Agent 每次只给一个动作；两条路线不需要重复完成。
- 让学生做：从自己的真实节点开始安装、重启、初始化或核验，并把系统实际结果返回给 Agent 或写入记录。
- 巡视只问：这是哪个窗口？刚才实际做了什么？系统现在显示什么？下一步依据是什么？

### 30-40 | 围绕四项证据收敛

> `READY-WSL` 不是“Ubuntu 好像打开了”，而是 Windows 与 Linux 两侧都有可复核证据。

#### 课前提醒

- [ ] 第 40 分钟停止新安装、新分支和新的个别排障。
- [ ] 若进度快，只允许核验 Windows 版 VS Code 与 Microsoft WSL 扩展；不新增状态码，不进入 Python、Git 或 `uv`。

- 展示：普通 PowerShell 中应看到 Ubuntu 存在且 `VERSION` 为 `2`；Ubuntu／WSL 中三条核验命令均能运行。
- 让学生做：保存 `wsl --list --verbose`、`pwd`、`whoami`、`cat /etc/os-release` 的真实输出。
- 检查只看：Ubuntu 能否启动、发行版是否存在、版本是否为 2、三条 Linux 命令是否均可运行；证据不全不得写 `READY-WSL`。
- 分流：完成者保存状态并再次核验；未完成者写下最后成功点、完整错误、已检查项和下一步。

### 40-50 | 保存一种真实状态

> 本节只能以 `READY-WSL` 或可接续的 `BLOCKED-*` 结束，不接受一句“装不上”。

#### 课前提醒

- [ ] 第 40 分钟停止排障并投影两种出口模板；只统计大致人数，不集中收取记录。
- [ ] 记录中不出现密码、token、完整主机名或其他无关个人信息。

- 展示：完成者保存以下最短记录。

```text
状态：READY-WSL
PowerShell：Ubuntu 存在 / VERSION 2
Ubuntu 能够启动：是
WSL 核验：pwd / whoami / cat /etc/os-release 均可运行，输出已保留
```

- 展示：未完成者保存以下记录。

```text
状态：BLOCKED-*
当前阶段：
最后一个成功检查点：
实际操作与完整错误：
已经检查：
下一步准备：
```

- 让学生做：停止开启新问题，把其中一种状态保存在自己下次能够找到的位置。
- 检查：`BLOCKED-*` 必须足以让下一次从当前节点继续。
- 预告：第三课时从保存的状态开始，把 WSL 中的固定目录交给 VS Code。

## 第三课时 · 用证据完成工作台交付

### 0-8 | 从上一课时的真实状态开始

> 只有真实达到 `READY-WSL`，今天才可能把个人结果签成 `READY-CODE`。

#### 课前提醒

- [ ] 准备可用的 WSL、Windows 版 VS Code、Microsoft WSL 扩展和已经完成首次连接的教师演示环境。
- [ ] 第 8 分钟仍未达到 `READY-WSL` 者停止个人支线，跟随教师演示并继续记录真实卡点；不得把跟随演示记作本人完成。

- 展示：`READY-WSL → Windows 版 VS Code → WSL 扩展 → 课程目录 → code . → 四项证据`。
- 让学生做：找到上一课时记录；`READY-WSL` 者重新确认 Ubuntu 可启动，`BLOCKED-*` 者只从记录的节点继续。
- 检查：受阻者不从头重做；个人状态继续保留为 `BLOCKED-*`。

### 8-18 | 安装或核验 Windows 版 VS Code

> VS Code 装在 Windows，WSL 扩展负责连接；不要在 Ubuntu 中再装一份桌面版。

#### 课前提醒

- [ ] 打开 Windows 版 VS Code 官方安装入口和 Microsoft WSL 扩展页面；教师机提前完成首次连接。
- [ ] 下载长期无进展记 `BLOCKED-NET`，磁盘不足记 `BLOCKED-DISK`；不使用第三方安装包或来源不明的修复脚本。
- [ ] 第 18 分钟进入固定目录演示；仍在下载者继续等待，但不阻塞全班主线。

- 展示：指出 Windows 版 VS Code、Extensions 面板、扩展发布者 Microsoft 和安装后重新打开终端的动作。
- 让学生做：未安装者使用官方 User Setup 安装，按需勾选 Add to PATH，再安装 Microsoft WSL 扩展；已安装者只核验。
- 检查：确认打开的是 Windows 侧 VS Code，扩展名称与发布者正确；桌面上存在图标不等于 WSL 已接通。

### 18-28 | 从唯一课程目录执行 `code .`

> `code .` 把编辑器打开在刚刚由终端确认过的那个 WSL 目录中。

#### 课前提醒

- [ ] 在教师 WSL 中提前执行过一次 `code .`，避免首次下载 VS Code Server 被误判为失败。
- [ ] `code` 找不到时只核对 Windows 版 VS Code、Add to PATH、WSL 扩展并重开终端。
- [ ] 本段不展开完整路径知识；第 28 分钟把同一路线交给学生，不转向 Python、Git、`uv` 或其他工具。

- 展示：在 Ubuntu／WSL 终端逐条运行：

```bash
mkdir -p ~/course/w01
cd ~/course/w01
printf 'AI-COURSE-W01\n' > COURSE_MARKER.txt
code .
```

- 展示：指出 VS Code 左下角的 `WSL: Ubuntu`、资源管理器中的 `COURSE_MARKER.txt` 和同一窗口内的集成终端。
- 问后自答：命令从哪里运行？`.` 指向哪里？打开后看哪三处？答案固定为 WSL 终端、当前目录、连接状态／文件／集成终端。

### 28-40 | 完成连接并核对四项证据

> 编辑器能够打开还不够；系统、目录、编辑器和课程标记必须彼此一致。

#### 课前提醒

- [ ] 排障只查误用 PowerShell、目录不一致、`code` 不可用、VS Code Server 网络失败；没有新增信息时不重复同一操作。
- [ ] 若进度快，关闭窗口后从 WSL 再次执行 `code .` 并独立复核；不增加新工具。
- [ ] 第 40 分钟停止新连接、新下载和新的个别排障。

- 让学生做：在 Ubuntu／WSL 中建立 `~/course/w01`、写入课程标记并执行 `code .`；首次连接时等待 VS Code Server 完成。
- 让学生做：在新打开的 VS Code 集成终端运行：

```bash
printf 'SYSTEM=%s\nFOLDER=%s\nEDITOR=%s\n' "$(uname -s)" "${PWD/#$HOME/~}" "$TERM_PROGRAM"
cat COURSE_MARKER.txt
```

- 检查只看：`SYSTEM=Linux`、`FOLDER=~/course/w01`、`EDITOR=vscode`、`AI-COURSE-W01`，并确认左下角显示 WSL／Ubuntu。

### 40-50 | 保存 `READY-CODE` 或可接续卡点

> 今天的交付不是一个打开的窗口，而是一份别人和未来的自己都能复核的状态。

#### 课前提醒

- [ ] 第 40 分钟投影两种出口模板，不再添加命令或继续无边界排障。
- [ ] 记录中不放密码、密钥、token、完整主机名或无关个人信息；只统计大致人数，不集中收取记录。

- 展示：完成者保存以下记录。

```text
状态：READY-CODE
PowerShell：Ubuntu 存在 / VERSION 2
VS Code 左下角：WSL: Ubuntu
SYSTEM=Linux
FOLDER=~/course/w01
EDITOR=vscode
课程标记：AI-COURSE-W01
我准备在 W2 继续理解的一点：
```

- 展示：未完成者继续使用 `BLOCKED-*` 模板，写清最后成功点、完整错误、已检查项和下一步。
- 让学生做：把本人设备的真实结果保存在下次能找到的位置；教师示例和“跟着看完”不能写成本人证据。
- 预告：W2 从这些状态继续学习路径、环境和版本控制。

## 临场取舍

- 慢了：第一课时把自动驾驶压成一个问题、把量化压成一句话，但保留 Computer Use 展示、黑白箱视角和人的责任；第二、三课时保留唯一演示路线、学生真实操作和末 10 分钟状态保存。
- 快了：第一课时再补一个“调用／进入实现”的黑白箱视角切换例；第二课时提前核验 VS Code 与 WSL 扩展；第三课时关闭后重新执行 `code .`。始终不扩展到 Python、Git 或 `uv`。
- 坏了：浏览器演示切换三张预存画面；系统安装或网络整体受阻时停止真实路线，使用教师演示环境讲完链条，每名学生仍保存自己的 `BLOCKED-*`，不得把示例写成本人完成。

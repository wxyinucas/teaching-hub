# W1｜面对 AI Agent，我们应该做什么准备？

> AI Agent 课程 · 入门

## 本次课

- 根问题：开始学习前，需要怎样的职责意识、工作台与记录习惯？
- 最低出口：明白结果由自己负责；完成首次操作，或留下卡点与下一步。
- 硬收口：第三课时第 40 分钟停止排障，末 10 分钟保存结果、记录卡点和下一步。

## 第一课时 · 你是什么身份？

### 0-10 | 科技的影响：系统与个人
> 讲清：生产力提升，不等于个人自动减负。

#### 用一个家庭纺织故事开场

设想一户靠农业和家庭纺织维持生活的人家。机器和工厂改变了生产成本，个人的勤劳仍然重要，却不足以决定原有谋生方式是否还能持续。

- 不展开工业革命史，只保留“生产方式和岗位分工会变化”这个判断。
- 系统效率提高，不代表每个劳动者立即变得轻松。
- 这是帮助思考今天的类比，不把历史简化为每个人只有一条路。

**转场：** 如果 Agent 改变了执行工作的成本，我们该怎样重新理解自己的角色？

### 10-30 | 当执行变得容易，人的价值在哪里？
> 讲清：可以委托执行，不能外包责任。

先问学生：如果你不与拖拉机比耕地、不与卡车比负重，为什么要把“比 Agent 更快地执行”当作唯一价值？

#### 这一段保住三件事

- Agent 可以承担实现，学生仍要提出目标、边界并判断结果。
- 课程允许 Autopilot；不要求每一行代码都由本人敲下。
- 求职时需要展示的，是如何组织任务、验收结果和承担决定。

引入黑白箱心智模型：黑箱关注“能否交付”，白箱关注“关键位置能否看见和干预”。不是完全不懂与全部弄懂的二选一。

> Agent 交付一个漂亮结果时，我签字前还需要确认什么？

**转场：** 不追踪每一行代码，不等于放弃管理；懂一点 CS，是为了获得必要的控制。

### 30-40 | 守住责任与实现的边界
> 讲清：责任封装与实现可控，各管什么。

- **对外的责任封装：** 说明要求、限制、验收证据和适用边界。
- **对内的实现可控：** 在关键处看见环境、路径、权限、数据和运行状态。

CS 知识地图只点名：文件与路径、命令行、权限、Git、依赖、接口和测试。不在这里开始教授整套工具。

“政委／团长”可以用作一句辅助类比；重点仍是对外可托付、对内可干预，不讨论类比本身。

**落到今天：** 分清操作在哪个终端发生、结果保存在哪里，就是最早的一点控制能力。

### 40-50 | 量化：确定性的实现，不确定的结果
> 讲清：量化是练习场，不是收益承诺。

用两个问题区分关注点：

- 资金有没有算错、接口有没有按要求执行？这是可以用规格和测试检查的实现问题。
- 一段时间的盈亏意味着什么、策略将来是否有效？这是需要继续实验的不确定问题。

本课不系统教授统计理论，不以一次收益衡量课程成功。学生需要解释自己的要求、证据和下一次尝试。

**接入后两节：** 今天先搭起工作台，再留下第一份能接着做的记录。安装遇阻不需要掩饰，记录具体卡点也是对过程负责。

## 第二课时 · 把工作台搭起来

### 0-20 | 介绍 WSL 与 VS Code，示范安装入口
> 讲清：从哪里开始，受阻时记什么。

#### 演示前的状态

学校电脑负责展示；MacBook 留着这份台本。先确认 Windows 版本、管理员权限和是否允许重启，保存正在进行的工作。学校电脑如无安装权限，用已准备好的演示环境说明流程，不临时修改学校配置。

#### 最短演示路线

1. 打开 [Microsoft 官方 WSL 安装说明](https://learn.microsoft.com/zh-cn/windows/wsl/install)。演示命令运行在 **Windows 管理员 PowerShell**，不是 Ubuntu。

```powershell
wsl --install
```

2. 按系统提示重启，再首次打开 Ubuntu，创建 Linux 用户。输入密码时不显示字符是正常现象，**不要让学生展示密码**。
3. 在普通 PowerShell 查看安装结果；列表应有发行版，版本为 2。

```powershell
wsl --list --verbose
```

4. 安装 [Windows 版 VS Code](https://code.visualstudio.com/docs/setup/windows)，再安装 [Microsoft 的 WSL 扩展](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-wsl)。VS Code 装在 Windows 侧，不在 Ubuntu 内再装桌面版。

本段只让学生看清入口、所在窗口和预期结果。不逐个排障，也不进入 BIOS 或系统安全设置。

### 20-50 | 学生安装实操，末十分钟机动缓冲
> 完成者进入操作，未完成者记下卡点。

20–40 分钟以学生自行操作为主。40–50 分钟作为安装等待、集中说明和机动排障的缓冲，不增加新工具。

- 做得快：保存当前状态，准备进入文件操作；不临时扩展到 Python、Git 或 uv。
- 做得慢：记录最后一个成功动作与完整报错，课后从这里继续。
- 遇到权限、重启或虚拟化障碍：先停止，不让学生随机运行来源不明的修复脚本。

一份够用的卡点记录：

```text
我现在要完成：
最后一个成功动作：
当前看到的报错或现象：
下一步准备尝试：
```

[官方 WSL 环境设置说明](https://learn.microsoft.com/zh-cn/windows/wsl/setup/environment) 留作查阅，不需要课上逐页讲。

## 第三课时 · 事事留痕

### 0-10 | 打开文件夹，新建、编辑并保存文件
> 演示一次完整的打开、编辑和保存。

#### 从什么状态开始

WSL 已正常启动，Windows 版 VS Code 与 WSL 扩展已装好。首次连接可能下载 VS Code Server，教师课前先跑过一次，避免把等待误判成失败。

在 **Ubuntu / WSL 终端** 中：

```bash
mkdir -p ~/course/w01
cd ~/course/w01
code .
```

#### 屏幕上做三件事

1. 看 VS Code 左下角，确认连接的是 WSL / Ubuntu。
2. 在当前工作文件夹中新建 `notes.md`，写几行今天的工作记录并保存。
3. 重新打开这个文件，确认刚才的内容还在。

示例文字只为展示记录的意思，不是学生必须照填的表格：

```markdown
# W1 工作记录
已完成：
当前卡点：
下一步：
```

如果 `code` 找不到，先核对安装与 PATH，再重开终端。[VS Code 官方 WSL 连接指南](https://code.visualstudio.com/docs/remote/wsl) 是这里的参考入口。

### 10-50 | 学生操作并留痕，末十分钟统一收尾
> 留下操作结果，或卡点与下一步。

10–40 分钟让学生完成首次文件操作。你巡看他们操作的窗口和文件位置，不要求此时掌握完整的路径知识。

#### 第 40 分钟开始收尾

> 今天先做到这里。保存已经完成的结果；还没完成的，记清卡在哪里，以及下一次从哪里继续。

- 已完成者：保存并重新打开自己的记录。
- 尚未完成者：先用可用的本地文本工具或纸笔记下卡点，不继续无边界排障。
- 记录中不放密码、密钥或 token。

最后不添加新命令。下一次从工作台状态和这份记录继续。

## 临场取舍

- 慢了 · 删什么：删去拓展讲解，操作只保留打开、编辑、保存。
- 快了 · 做什么：重新打开工作文件夹，确认刚保存的记录仍在。
- 坏了 · 怎么退：安装受阻先记报错与下一步，跟随演示了解操作流程。

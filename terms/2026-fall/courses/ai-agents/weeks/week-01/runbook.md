# W1｜面对 AI Agent，我们应该做什么准备？

> AI Agent 课程 · W1 · 3 × 50 min · 约 25 名零基础学生 · 无助教

## 本次课

- 根问题：当 Agent 能够承担大量执行工作时，人应该怎样理解自己的身份与责任，并搭起可核验、可接续的工作台？
- 最低出口：第一课时留下关于“人的身份与责任”的问题，并区分 Agent 的行动能力、黑白箱视角与结果的不确定性；第二、三课时分别保存 `READY-WSL`／`READY-CODE`，或可接续的 `BLOCKED-*` 状态。
- 硬收口：第一课时最后 3 分钟停止增加例子，回到“人的身份与责任”；第二、三课时第 40 分钟停止新安装与新排障，末 10 分钟只保存真实状态、卡点和下一步。

## 第一课时 · 当 Agent 能够执行，人还负责什么？

### 0-8 | 看见 Agent 在执行工作

> Agent 不只生成回答，它还能观察界面、调用工具并连续完成任务。

#### 课前提醒

- [ ] 在无个人账号信息的 Chrome 环境完整跑通提示词；固定目标为 **《欢迎来到未来》**，[Bilibili · `BV1pb8o6yE8f`](https://www.bilibili.com/video/BV1pb8o6yE8f/)，现场不先透露标题或 BV 号。
- [ ] 保存搜索过程、目标页面和最终回答三张脱敏画面；第 6 分钟未完成就切换 Plan B，第 8 分钟必须转场。
- [ ] 演示只读公开网页：不登录，不读取 Cookie、token 或个人信息，不找媒体流地址，不下载视频，不临时追加任务或权限。

- 展示：把以下提示词原样交给浏览器 Agent。

```text
请打开一个新的 Chrome 无痕窗口，帮我在 Bilibili 找到“jyy 在 2026 年下，和我们类似的 AI Agent 课程”。

先搜索和判断，不要直接猜网址。找到后证明你选对了，再使用 Chrome 开发者工具读取页面公开信息，补充页面没有直接展示的内容并相互核对。

最后告诉我：你找到了什么、依据是什么，以及这些证据仍不能证明什么。现在开始。
```

- Agent 执行的第一个特点：信息的筛选与过滤，和 chatbox 一样。
- Agent 和以往 Chatbox 模式最大的区别是什么？
  - 做了原本需要人完成的外部动作;
  - 不只给出建议，还可以直接与不同程序交互并继续推进任务。
- Computer Use：观察屏幕 → 操作界面 → 读取结果 → 继续行动。
- 人不再必须先掌握全部操作细节，才让任务开始执行；
  - 写代码、运行程序和根据错误继续修改，变成了可以由 agent 负责的“自动化任务”，这个是最强力的。

**转场：** 既然 agent 这么强，面临新的 cs 问题时，我们应该怎么办？


### 8-17 | 面对新的 CS 问题：用 Agent，还是不用？

> 充分使用 Agent，与主动保留学习反馈并不矛盾。

- 飞行员会不会为了练习技术而拒绝自动驾驶？
  - 不会；完成飞行时，应该使用可靠而高效的工具。
- 飞行员为什么还要进入模拟机？
  - 因为在关键操作和紧急情况下，仍需要更有判断力、更加灵活、更能处理**复杂陌生**情况的人类来负责。
- 辩证的问题：我们不需要拒绝 Agent，也不需要怀念低效率；
  - 我们需要注意的是，如何在解决问题的同时，不忘记提升自己的能力。

- 作品变得更好，不等于人的能力也同步提高。
  - Agent 工具降低了完成任务的门槛；
  - 反馈减少，让产品质量的提升，和我们能力的提升有了错位；
  - 真正需要主动补回的，是能够**暴露执行错误、修正判断偏离**的反馈。

- 留给全学期的问题：
  - 哪些反馈对我的成长真正重要？
  - 我怎样判断变强的是自己，而不只是工具？

**转场：** 既然要用到 agent，那和 agent 合作时，应该有一个怎样的心态？

### 17-29 | 从“它做完了”到“我来负责”

> 执行与过程判断可以委托，最终决策与责任不能转移。

- 课程允许 Autopilot，也不追查代码究竟由学生、同伴还是 Agent 写；
  - 只要以学生的名字提交，学生就必须对安全合规、验收证据和结论边界负责。
- 从**当下、孤立**任务看，人不再只是执行者，还要承担管理者的责任：
  - 提出“目标与条件”，用数学语言说就是“目标函数和可行域”；
  - **查找证据**并做出选择；
  - 说明结论的适用边界；
  - 作出“接受、拒绝”最终结论；
  - “做事留痕”。
- 从**长期学习**看，人也需要主动介入执行过程：
  - 例如用 python 写一个 simulation；
  - 形成“心智模型”，要知道代码在做什么，有一定预测能力；
  - 保留介入和接管能力，以防止“效果和目标不匹配”。

- 以后每一次正式提交，都等同于你们写下：“这是我决定提交的结果，我愿意为它负责。”
  - 可以委托：执行与过程；
  - 必须承担： “最终决策”。
- 负责是否意味着，审核 Agent 结果就是重做它的每一步？
  - 不；但它意味着，合作过程中，有足够“证据”决定**接受、拒绝结论**，或继续检查。

**转场：** 既然我们达成了共识，使用 agent 最重要的是负责，那么下一个问题就是，我们该怎么负责？

### 29-40 | 怎样负责？运用抽象视角，分离关注点

> 黑箱和白箱不是系统的固定状态，而是为了不同目的选择的观察视角。

> 首先我们借用一下“黑白箱”的概念，这是观察系统的两种不同的视角。

- 一个系统并不“天然是”黑箱或白箱；同一个系统可以在不同层级切换视角：
  - 当作黑箱：强调“调用”，假设它**内部不可见**，关注“可以做什么”，用于**拼接、组合功能**；
  - 当作白箱：强调“具体实现”，假设它**内部可见可控**，关注“怎么做到的”，用于**修改、实现具体能力**。
- 视角不同，关注点和责任也不同：
  - 黑箱视角，对外保证：
    - 要求明确；
    - 结果可验收；
    - 边界说得清；
  - 白箱视角，对内保证：
    - 关键状态看得见；
    - 必要时能够介入。
- 白箱不是一路展开到底（用学习小组上交作业为例）：
  - 只打开当前问题所需的抽象层级，更底层的细节仍然可以继续封装。

- 本课程首先打开“人—Agent 工作系统”：
  - 关于计算机基础的部分；
  - 大模型内部的**参数分布和推理机制**，处在更底层的抽象层级，当前继续封装。
  - 后两课时先看终端、目录和保存状态，这是第一次进入当前所需的白箱层级。

**转场：** 前面谈的是怎样把可控部分做对。接下来用量化追问 Agent 的边界：做对以后，结果就一定好吗？

### 40-50 | 量化：做对了，也未必有好结果；做错了，也有可能赚钱

> 责任不是控制一切，而是把可控的部分做“对”，诚实面对不可控的部分，并不断校准两者的边界。

> 赐我宁静，接受无法改变的；赐我勇气，改变力所能及的；并赐我智慧，让我分辨两者。

#### 课前提醒

- [ ] 最后 3 分钟停止增加例子，不安排填写或签字。

- 一次盈亏不能证明程序正确或错误；证据要回答的是，程序有没有按意图执行。
- 可控的部分：
  - 我们的意图是否清晰；
  - 寻找的“证据”，是否证明我们正确的执行了意图。
- 不可控的部分：
  - 即使这些工作全部做对，也不能保证未来一定盈利；
  - 接受随机性的存在，不为现实虚构确定性。
- 暂时分不清的部分：
  - 是模型能力不够；
  - 还是线性模型中的 \(\varepsilon\)，本身就是不可估计的。

- **课程总结**：
  - Agent 让执行变得更便宜以后，人仍要作为**经理、导师**：
    - 选择目标；
    - 查找证据；
    - 并对自己的判断负责。
  - **留给全学期的问题**：当 Agent 越来越强时，怎样“保证自己真的在成长”？


## 第二课时 · 把 WSL 变成可核验状态

### 0-8 | 确认窗口，现场启动安装

> 先认清管理员 PowerShell；命令提交后，只依据学校电脑的真实返回判断。

#### 课前提醒

- [ ] 课前在教室 Windows 电脑实测：确认系统版本、管理员权限、普通 PowerShell 与管理员 PowerShell 的打开方式，以及当前 WSL 状态；记录真实结果，不预设课堂上一定安装成功。
- [ ] 准备普通 PowerShell、管理员 PowerShell、Ubuntu／WSL 三种窗口的真实画面；学校电脑未安装 Ubuntu 时，使用录屏中的画面补充。
- [ ] 不临时修改系统设置，不借用他人账号，不运行来源不明的修复脚本。

- 展示：对照普通 PowerShell、管理员 PowerShell 和 Ubuntu／WSL；说明 `wsl --install` 只在 Windows 管理员 PowerShell 中执行，Linux 命令只在 Ubuntu／WSL 中执行。
- 展示：在学校电脑的管理员 PowerShell 中实际运行一次：

```powershell
wsl --install
```

- 检查：这是哪个窗口？命令是否已经提交？系统实际返回了什么？

### 15-30 | 从自己的真实节点继续

> 每次只推进一个真实动作；系统没有给出结果，就不能假设这一步已经成功。

#### 课前提醒

- [ ] 准备 Slides“让 Chatbox 帮我达到 READY-WSL”、Guide 手动路线和 `BLOCKED-*` 模板。
- [ ] 密码不展示、不截图，也不发送给教师、同学或 Agent；重启前先保存工作。
- [ ] 出现 BIOS／虚拟化修改、未知管理员脚本、关闭安全功能或删除发行版等建议时立即停止并记录；同一问题阻塞 5 人以上才暂停全班统一说明。

- 让学生选择：直接按 Guide 操作，或复制 Chatbox Prompt 让 Agent 每次只给一个动作；两条路线不需要重复完成。
- 让学生做：从自己的真实节点开始安装、重启、初始化或核验，并把系统实际结果返回给 Agent 或写入记录。
- 巡视只问：这是哪个窗口？刚才实际做了什么？系统现在显示什么？下一步依据是什么？

### 30-40 | 围绕四项证据收敛

> `READY-WSL` 不是“Ubuntu 好像打开了”，而是 Windows 与 Linux 两侧都有可复核证据。

#### 课前提醒

- [ ] 第 40 分钟停止新安装、新分支和新的个别排障。
- [ ] 若进度快，只允许核验 Windows 版 VS Code 与 Microsoft WSL 扩展；不新增状态码，不进入 Python、Git 或 `uv`。

- 展示：普通 PowerShell 中应看到 Ubuntu 存在且 `VERSION` 为 `2`；Ubuntu／WSL 中三条核验命令均能运行。
- 让学生做：保存 `wsl --list --verbose`、`pwd`、`whoami`、`cat /etc/os-release` 的真实输出。
- 检查只看：Ubuntu 能否启动、发行版是否存在、版本是否为 2、三条 Linux 命令是否均可运行；证据不全不得写 `READY-WSL`。
- 分流：完成者保存状态并再次核验；未完成者写下最后成功点、完整错误、已检查项和下一步。

### 40-50 | 保存一种真实状态

> 本节只能以 `READY-WSL` 或可接续的 `BLOCKED-*` 结束，不接受一句“装不上”。

#### 课前提醒

- [ ] 第 40 分钟停止排障并投影两种出口模板；只统计大致人数，不集中收取记录。
- [ ] 记录中不出现密码、token、完整主机名或其他无关个人信息。

- 展示：完成者保存以下最短记录。

```text
状态：READY-WSL
PowerShell：Ubuntu 存在 / VERSION 2
Ubuntu 能够启动：是
WSL 核验：pwd / whoami / cat /etc/os-release 均可运行，输出已保留
```

- 展示：未完成者保存以下记录。

```text
状态：BLOCKED-*
当前阶段：
最后一个成功检查点：
实际操作与完整错误：
已经检查：
下一步准备：
```

- 让学生做：停止开启新问题，把其中一种状态保存在自己下次能够找到的位置。
- 检查：`BLOCKED-*` 必须足以让下一次从当前节点继续。
- 预告：第三课时用 `code .` 把 WSL 课程目录交给 VS Code，再从 VS Code 反向找到 Windows 中的同一目录。

## 第三课时 · 让三个入口指向同一目录

### 0-5 | 看清终点与两套路线

> 教师用 macOS 稳定示范关系，学生用 Windows／WSL 产生本人证据；两条路线服务于同一个目标。

#### 课前分界

##### Windows｜课前完整跑一遍学生路线

- [ ] 在教室或其他真实 Windows + WSL 2 电脑上，按 Guide 第三课时操作清单完整跑一遍；不要求重新安装已经存在的软件，但每个关键界面都要实际到达。
- [ ] 核验 Windows 版 VS Code、Microsoft WSL 扩展、从 WSL 课程目录执行 `code .`、左下角的 `WSL: Ubuntu`、项目区的 `COURSE_MARKER.txt`。
- [ ] 从 VS Code 项目区反向定位到 Windows 文件资源管理器，记录右键菜单的真实名称和行为；不在课堂上猜菜单名称。
- [ ] 保存三张真实画面：WSL 中的目录与标记、VS Code 中的同一标记、Windows 文件资源管理器中的同一目录。Windows 路线保证学生指南真实可行，课堂上可以展示，但不承担主要现场演示。

##### macOS｜课上演示相同的组织关系

- [ ] 确认 MacBook 中 Terminal、VS Code 与 Finder 可用；`command -v code` 有输出。若没有，提前在 VS Code 命令面板执行 `Shell Command: Install 'code' command in PATH`。
- [ ] 在 MacBook 完整演练以下路线：

```bash
mkdir -p ~/course/w01-demo
cd ~/course/w01-demo
printf 'AI-COURSE-W01-DEMO\n' > COURSE_MARKER.txt
pwd
code .
```

- [ ] VS Code 打开后，在其集成终端运行 `pwd`、`cat COURSE_MARKER.txt`，再运行：

```bash
open -a Finder .
```

- [ ] 固定对应关系：macOS Terminal ↔ WSL，Finder ↔ Windows 文件资源管理器；macOS 路线保证课堂演示稳定可复用，不要求学生复制 macOS 命令。

#### 上课

- 投影唯一目标页：WSL 中的 `~/course/w01`，经 `code .` 交给 VS Code，再从 VS Code 项目区反向定位到 Windows 文件资源管理器；三处都能找到 `COURSE_MARKER.txt`。
- 说明两套路线：教师用 macOS Terminal → VS Code → Finder 演示关系；学生按 Guide 完成 WSL → VS Code → Windows 文件资源管理器。
- 展示三张 Windows 实机画面，只标出学生稍后要找到的界面，不在此处重新演示安装。
- 转场：接下来 10 分钟完整看一次关系；第 15 分钟开始，各自带着这个目标推进。

### 5-15 | 用 macOS 完整示范一次

> 示范只回答一个问题：终端、编辑器和文件管理器怎样指向同一个目录？

- 先让学生停手观看；这一遍不中断跟做，不解释安装分支，不处理现场排障。
- 切换到 MacBook Terminal：进入预备好的 `~/course/w01-demo`，运行 `pwd`，并显示 `COURSE_MARKER.txt`。
- 执行 `code .`；VS Code 打开后，在项目区与集成终端再次确认同一目录和同一标记。
- 在 VS Code 集成终端执行 `open -a Finder .`；Finder 打开后，再次指出同一个 `COURSE_MARKER.txt`。
- 回到学生目标页，完成固定映射：Terminal ↔ WSL，Finder ↔ Windows 文件资源管理器；macOS 命令不要求学生复制。
- 第 15 分钟必须结束演示；不追加功能，不现场排查 macOS，不进入 Python、Git 或 `uv`。

### 15-40 | 带着目标自行探索

> 全班不追求同一步骤、同一进度；每个人只依据自己机器的真实状态继续推进。

- 展示一次可复制的 `READY-CODE` Prompt，随后停在“学生目标：三个入口，同一个目录”；所有具体步骤只查 Guide。
- 宣布两种起点：已经 `READY-WSL` 者从操作清单第一项开始；仍受阻者从自己的真实节点继续，不形式化地重做已经成功的核验。
- 学生任选 Guide 手动路线或 Chatbox 路线；两条路线不重复完成，也不等待全班同步。
- 巡视只问：现在要到达哪个目标？机器实际显示什么？下一步依据是什么？不替学生连续点击。
- 同一问题阻塞 5 人以上才暂停全班，用 Windows 实机画面统一指出一次；个别问题继续保存真实卡点。
- 完成者关闭 VS Code，再从 WSL 的课程目录执行一次 `code .`，独立确认三个入口仍指向同一目录；不增加新工具。
- 第 35 分钟提示还剩 5 分钟，不再开启新的安装路线或大范围排障；第 40 分钟所有人停止操作。

### 40-50 | 停止排障，保存真实状态

> 全体只保存 `READY-CODE` 或可接续的 `BLOCKED-*`；这十分钟不再教学。

- 第 40 分钟展示 Slides 的两种出口，投影 Guide 的最后两项；不再添加命令或继续无边界排障。
- 提醒：只有学生本人 Windows／WSL 的结果可以写入 `READY-CODE`；教师的 macOS 演示和 Windows 截图都不能替代本人证据。
- 完成者保存三处一致的证据；未完成者保存最后成功点、完整错误、已经检查的内容和下一步。
- 记录中不放密码、密钥、token、完整主机名或无关个人信息；只统计大致人数，不集中收取记录。
- 预告：W2 从这些状态继续学习路径、环境和版本控制。

## 临场取舍

- 慢了：第一课时把自动驾驶压成一个问题、把量化压成一句话，但保留 Computer Use 展示、黑白箱视角和人的责任；第二课时保留唯一安装路线；第三课时把 macOS 示范压到 `code .` 与 `open -a Finder .` 两个动作，但不压缩学生探索和末 10 分钟状态保存。
- 快了：第一课时再补一个“调用／进入实现”的黑白箱视角切换例；第二课时提前核验 VS Code 与 WSL 扩展；第三课时完成者关闭 VS Code 后，再从 WSL 独立执行一次 `code .`。始终不扩展到 Python、Git 或 `uv`。
- 坏了：浏览器演示切换三张预存画面；Windows 安装或网络整体受阻时，教师仍可用 macOS 完成“终端—编辑器—文件管理器”的关系演示，每名学生保存自己的 `BLOCKED-*`，不得把教师示例写成本人完成。

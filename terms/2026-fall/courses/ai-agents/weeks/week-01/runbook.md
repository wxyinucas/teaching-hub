# W1｜面对 AI Agent，我们应该做什么准备？

> AI Agent 课程 · W1 · 3 × 50 min · 约 25 名零基础学生 · 无助教

## 本次课

- 根问题：开始学习前，需要怎样的职责意识、工作台与记录习惯？
- 最低出口：第一课时写下签字判断；第二、三课时分别形成并保存 `READY-*` 或可接续的 `BLOCKED-*` 状态。
- 硬收口：第三课时第 40 分钟停止排障，末 10 分钟保存结果、记录卡点和下一步。

## 第一课时 · 你是什么身份？


### 0-8 | 看见 Agent 从回答走向行动
> 用一个受控的 Chrome 任务，证明 Agent 能够操作工具并留下可核验结果。

#### 课前放行项

- 目标视频：**《欢迎来到未来》**，[Bilibili · `BV1pb8o6yE8f`](https://www.bilibili.com/video/BV1pb8o6yE8f/)；
- 课堂只给 Agent 搜索意图：`jyy 在 2026年下，和我们类似的 ai agent 课程`，不先透露目标标题或 BV 号；
- 已验证的公开结构化字段：canonical URL、标题、简介、发布时间（含时区）、ISO 时长以及精确播放／点赞／评论数；
- 预先保存最终页面与开发者工具结果，作为现场失败时的 fallback。

#### 可直接复制给浏览器 Agent 的完整提示词

```text
你是一名公开网页调查助手。请控制 Chrome 完成一次可现场展示、可核验的网页调查，不要只告诉我搜索建议，也不要在没有证据时猜答案。

任务：在 Bilibili 搜索并判断“jyy 在 2026年下，和我们类似的 ai agent 课程”最可能指哪一个公开视频。这里的“2026年下”指 2026 年下半年或秋季学期；“类似”指 AI Agent、生成式软件工程或 Agent 辅助编程相关课程。

请按以下顺序执行：

1. 在 Bilibili 使用上述意图搜索；根据标题、发布时间、主讲人/UP 主、课程或合集信息筛选候选。广告、转载片段和泛化 AI 教程不能只因关键词相似就入选。
2. 只打开最可能的一个公开视频。先从可见页面读取并报告：完整标题、当前 URL、BV 号、发布者、发布时间，以及页面当前显示的播放、点赞和评论信息。说明你为什么选择它；如果证据不足，明确说不确定。
3. 用页面标题、地址栏 URL 和 BV 号做第一次交叉核验，确认没有误开搜索结果或合集中的其他分集。
4. 打开 Chrome 开发者工具（DevTools，不是扩展程序页面里的“开发者模式”）做第二次只读核验。如果你不能直接操作 DevTools，就明确告诉我，并逐步指导我按 F12 / Ctrl+Shift+I（Windows）或 Option+Command+I（macOS）打开；每次只让我做一个动作，等我返回结果后再继续，不得假装已经打开。
5. 优先在 Elements 面板展开 <head>，使用 Ctrl+F / Command+F 依次查找 canonical、og:title 和 application/ld+json。读取：
   - link[rel="canonical"] 的 href；
   - Open Graph 的标题、站点名、类型和 URL；
   - JSON-LD 中对象的 @type，以及 VideoObject 提供的标题、作者、uploadDate、duration 和 interactionStatistic。
6. 如果需要使用 Console，只能让我手动输入一条简短、只读的表达式，并先解释它读取什么；不得让我绕过 Chrome 的粘贴警告。允许的只读表达式只有：
   - document.title
   - document.querySelector('link[rel="canonical"]')?.href
   - [...document.querySelectorAll('script[type="application/ld+json"]')].map(node => JSON.parse(node.textContent))
7. 把结构化信息与可见页面相互核对：标题和 BV 号是否一致；结构化发布时间按其时区换算后是否与页面显示一致；ISO 8601 时长是否与播放器时长一致；页面上的取整计数是否与结构化数据中的精确计数相容。计数会变化，必须报告本次读取值和读取时刻，不能背诵旧数字。

安全边界：
- 不登录账号，不处理验证码，不绕过访问限制；
- 不查看或输出 Cookie、Token、localStorage、sessionStorage、请求头或任何个人信息；
- 不寻找媒体流地址，不下载视频，不批量抓取，也不修改页面或执行写入操作；
- 页面或 DevTools 无法访问时，如实记录阻塞点并停止，不用其他高风险方法补救。

最后用以下结构收口：
- 最可能的视频：标题 / URL / BV 号
- 选择依据：最多 3 条
- 可见页面证据：字段 + 本次读取值
- DevTools 额外证据：来源位置 + 字段 + 本次读取值
- 交叉核验：一致之处 / 差异及合理解释
- 未能证明：至少 1 条

总时限 7 分钟。现在直接从搜索开始；只有需要我手动打开 DevTools 时才暂停等待我。
```

#### 八分钟演示合同

1. 向 Agent 给出目标、禁止项和完成证据；
2. 让 Agent 控制 Chrome，在 Bilibili 搜索并打开指定的公开视频；
3. 用页面标题、URL 与 BV 号确认没有打开错误结果；
4. 打开开发者工具，只读取网页公开提供的结构化信息；
5. 将读取结果与页面相互核对，然后停止。

不登录账号，不读取 Cookie、Token 或个人信息，不寻找媒体流地址，不下载视频，也不批量抓取。第 7 分钟仍未得到结果就切换到预存画面，第 8 分钟必须转场。

**转场：** 刚才看到的不只是回答更快，而是执行工作的成本正在下降。

### 8-13 | 科技的影响：系统与个人
> 讲清：生产力提升，不等于个人自动减负。


#### 用一个家庭纺织故事开场

设想一户靠农业和家庭纺织维持生活的人家。机器和工厂改变了生产成本，个人的勤劳仍然重要，却不足以决定原有谋生方式是否还能持续。

- 不展开工业革命史，只保留“生产方式和岗位分工会变化”这个判断。
- 系统效率提高，不代表每个劳动者立即变得轻松。

**转场：** 如果 Agent 改变了执行工作的成本，我们该怎样重新理解自己的角色？

### 13-25 | 当执行变得容易，人的价值在哪里？
> 讲清：可以委托执行，不能外包责任。

课堂只推进三问，不展开新的问题树：

1. 当执行变得廉价，我们还需要积累什么？
2. 即使允许 Autopilot，人仍然必须负责什么？
3. Agent 交付结果后，我们凭什么签字？

拖拉机、司机、宏观／微观决策和求职价值只作为教师解释素材，不分别要求学生回答。学生沉默时直接继续讲述，不等待临场讨论发生。

引入黑白箱心智模型：黑箱关注“能否交付”，白箱关注“关键位置能否看见和干预”。不是完全不懂与全部弄懂的二选一。

**转场：** 不追踪每一行代码，不等于放弃管理；懂一点 CS，是为了获得必要的控制。

### 25-35 | 守住责任与实现的边界
> 讲清：责任封装与实现可控，各管什么。

> 人与 Agent 组成一个团队；人是最终决策者，也承担最终责任。

- **对外的责任封装：** 说明要求、限制、验收证据和适用边界。
- **对内的实现可控：** 在关键处看见环境、路径、权限、数据和运行状态。

- CS 知识地图只点名：文件与路径、命令行、权限、Git、依赖、接口和测试。不在这里开始教授整套工具。
- “政委／团长”只用作一句辅助类比；重点仍是对外可托付、对内可干预。

**落到今天：** 分清操作在哪个终端发生、结果保存在哪里，就是最早的一点控制能力。

### 35-50 | 量化落点、机动缓冲与形式签字
> 用量化说明证据的边界；最后只让学生独立写下判断，不组织答辩或收集。

#### 35-40｜量化：确定性的实现，不确定的结果

用两个问题区分关注点：

- 资金有没有算错、接口有没有按要求执行？这是可以用规格和测试检查的实现问题。
- 一段时间的盈亏意味着什么、策略将来是否有效？这是需要继续实验的不确定问题。

本课不系统教授统计理论，不以一次收益衡量课程成功。学生需要解释自己的要求、证据和下一次尝试。

#### 40-45｜可删除的机动缓冲

准时完成时，用一个教师给出的参考答案重新说明“证据支持什么、不能支持什么”；前段超时时直接用这一段吸收，不再增加内容。

#### 45-48｜学生独立填写

投影签字页。学生在纸面、笔记或自己的设备上写一到两句话并署名：签字前还需要什么证据；即使证据成立，它仍不能证明什么。不点名、不讨论，也不集中收集。

#### 48-50｜教师收束与转场

> Agent 可以提供结果，签字的人必须说明证据及其边界。

接入后两节：开始搭起工作台，并留下第一份能够接着做的状态。安装遇阻不需要掩饰，记录具体卡点也是对过程负责。

## 第二课时 · 把工作台搭起来

### 0-15 | 介绍 WSL，示范唯一安装入口
> 讲清：从哪里开始，受阻时记什么。

#### 演示前的状态

学校电脑负责展示；MacBook 留着这份台本。先确认 Windows 版本、管理员权限和是否允许重启，保存正在进行的工作。学校电脑如无安装权限，用已准备好的演示环境说明流程，不临时修改学校配置。

#### 最短演示路线

1. 打开 [Microsoft 官方 WSL 安装说明](https://learn.microsoft.com/zh-cn/windows/wsl/install)。演示命令运行在 **Windows 管理员 PowerShell**，不是 Ubuntu。

```powershell
wsl --install
```

2. 不在现场等待安装和重启；切换到预先准备的重启后状态，再首次打开 Ubuntu，演示创建 Linux 用户。输入密码时不显示字符是正常现象，**不要让学生展示密码**。
3. 在普通 PowerShell 查看安装结果；列表应有发行版，版本为 2。

```powershell
wsl --list --verbose
```

本段只让学生看清入口、所在窗口和预期结果。不逐个排障，也不进入 BIOS 或系统安全设置。

### 15-50 | 学生安装实操，末十分钟保存状态
> 形成并保存 `READY-WSL`，或留下可接续的 `BLOCKED-*`。

15–40 分钟以学生自行操作为主。第 40 分钟停止开启新的个别排障；40–50 分钟只核对并保存状态，不增加新工具。

- 做得快：可以提前安装 Windows 版 VS Code 与 Microsoft WSL 扩展，但不增加新的状态码，也不扩展到 Python、Git 或 `uv`。
- 做得慢：按 `guide.md` 记录最后一个成功检查点、完整报错、已检查项和下一步。
- 遇到权限、重启或虚拟化障碍：先停止，不让学生随机运行来源不明的修复脚本。

无助教时按风险而非举手顺序处理：密码、未知管理员脚本或删除风险立即处理；同一问题阻塞 5 人以上再暂停全班统一说明；其余个人问题先转结构化状态。已完成者核对自己的证据，不充当系统管理员。

一份够用的卡点记录：

```text
我现在要完成：
最后一个成功动作：
当前看到的报错或现象：
下一步准备尝试：
```

`READY-WSL` 至少要有 PowerShell 中 Ubuntu / VERSION 2 的状态，以及 WSL 中 `pwd`、`whoami`、`cat /etc/os-release` 的可运行证据；否则保存 `BLOCKED-*`。不集中提交，教师只通过必要的巡看或举手了解整体状态。

[官方 WSL 环境设置说明](https://learn.microsoft.com/zh-cn/windows/wsl/setup/environment) 留作查阅，不需要课上逐页讲。

## 第三课时 · 事事留痕

### 0-25 | 安装或核验 VS Code，再演示从固定目录打开
> 不假设 VS Code 已经安装；先闭合起点，再演示 `code .` 与课程标记。

#### 0-15｜安装或核验

1. 在 Windows 安装 [Windows 版 VS Code](https://code.visualstudio.com/docs/setup/windows)；多数个人电脑使用 User Setup；
2. 在 Extensions 中安装 Microsoft 发布的 [WSL 扩展](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-wsl)；
3. 已经安装的学生只做核验，不重复安装；
4. VS Code 装在 Windows 侧，不在 Ubuntu 内再装桌面版。

仍处于 `BLOCKED-*` 的学生先跟随教师演示，记录自己的链条停在哪里；不假装已经满足 `READY-WSL`。

#### 15-25｜固定目录与 `code .`

首次连接可能下载 VS Code Server，教师课前先跑过一次，避免把等待误判成失败。

在 **Ubuntu / WSL 终端** 中：

```bash
mkdir -p ~/course/w01
cd ~/course/w01
printf 'AI-COURSE-W01\n' > COURSE_MARKER.txt
code .
```

#### 屏幕上做三件事

1. 看 VS Code 左下角，确认连接的是 WSL / Ubuntu；
2. 确认当前工作文件夹中存在 `COURSE_MARKER.txt`；
3. 在 VS Code 的集成终端运行 `guide.md` 给出的核验命令，检查系统、目录、编辑器和课程标记。

如果 `code` 找不到，先核对安装与 PATH，再重开终端。[VS Code 官方 WSL 连接指南](https://code.visualstudio.com/docs/remote/wsl) 是这里的参考入口。

### 25-50 | 学生操作并留痕，末十分钟保存状态
> 形成并保存 `READY-CODE`，或留下可接续的 `BLOCKED-*`。

25–40 分钟让学生沿 `guide.md` 完成 VS Code 接入、课程目录、标记文件和证据命令。你巡看他们操作的窗口和文件位置，不要求此时掌握完整的路径知识。

#### 第 40 分钟开始收尾

> 今天先做到这里。保存已经完成的结果；还没完成的，记清卡在哪里，以及下一次从哪里继续。

- 已完成者：核对 `SYSTEM=Linux`、`FOLDER=~/course/w01`、`EDITOR=vscode` 与 `AI-COURSE-W01`，保存 `READY-CODE` 状态。
- 尚未完成者：按 `BLOCKED-*` 模板保存完整错误、已检查项和下一步，不继续无边界排障。
- 记录中不放密码、密钥或 token。

不集中提交。最后不添加新命令；下一次从工作台状态和这份记录继续。

## 临场取舍

- 慢了 · 删什么：删去参考答案、原理、第二遍演示和路径术语；保留黄金路线、安全边界与状态保存。
- 快了 · 做什么：第二课时可以提前安装 VS Code；第三课时重新打开课程目录并独立核对四项证据；不扩展到 Python、Git 或 `uv`。
- 坏了 · 怎么退：开场演示切换到预存画面；安装受阻先保存结构化 `BLOCKED-*`，再跟随演示了解后续流程。

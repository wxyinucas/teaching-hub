# W2 学生行动指南：从项目入口到 `READY-RUN`

> 本页用于课前准备，以及第二、三课时的操作与核验。本周只完成一件事：在正确目录和锁定环境中运行教师项目与给定测试。

## 课前准备

- 个人设备达到 `READY-CODE`；仍受阻时保留 W1 状态，课堂中使用教师准备的环境跟随；
- 等待教师发布唯一的项目入口、固定目录、骨架运行命令和测试命令；
- 不从搜索结果自行安装 Git、`uv` 或运行“一键配置”脚本；
- 课前可以阅读本页，但不要求提前跑通项目。

教师尚未发布上述四项入口时，不要让 Agent 猜测仓库或命令。

## 两条平行路线

- 直接路线：按照下文逐项操作；
- Agent 路线：把后面的简短 Prompt 交给 Agent，让它一次只带你做一步。

两条路线使用相同的 `READY-RUN` / `BLOCKED-*` 出口，不需要重复做两遍。

## 第二课时｜取得、定位、恢复、运行

### 1. 确认当前终端

在 Ubuntu / WSL Bash 中运行：

```bash
uname -s
pwd
git --version
uv --version
```

最低预期：系统为 Linux，Git 与 `uv` 能显示版本。工具不存在时使用教师给出的安装路线，不自行寻找脚本。

### 2. 取得或更新项目

第一次取得项目时，只复制教师发布的完整命令；已有项目时，先进入固定目录，再使用教师指定的更新命令。

目标目录已经存在、更新出现冲突或命令要求删除现有内容时，立即停止，不要重置或重新克隆。

### 3. 证明位置正确

进入项目后运行：

```bash
pwd
git rev-parse --show-toplevel
git remote -v
ls pyproject.toml uv.lock
```

核对本地目录、项目根目录和教师公布的远端一致，并且项目根目录存在 `pyproject.toml` 与 `uv.lock`。

### 4. 恢复项目环境

仍在项目根目录运行：

```bash
uv sync --frozen
uv run python -c 'import sys; print(sys.executable)'
```

不要删除或改写 `uv.lock`，不要换用另一个包管理器，也不要让 Agent 随意升级依赖。

### 5. 运行骨架与测试

复制教师发布的骨架命令和给定测试命令，不自行改写入口。保存成功标记、测试摘要和退出状态。

本周不修改项目功能，不 `commit`、不 `push`，也不连接外部平台。

## 可以交给 Agent 的简短 Prompt

```text
请按本周 guide，一步一步带我把课程项目运行起来。

先确认我在 WSL 和正确项目目录；每次只给一个操作，等我返回真实结果再继续。只使用 guide 给出的项目、uv 和测试入口，不要自行换工具、重建项目或假设成功。

最后按“远端、本地目录、项目环境、运行、测试”核对证据；受阻时帮我保存完整错误和下一步。现在开始。
```

Agent 的建议与课程指南冲突时，以课程指南为准。

## 第三课时｜让同伴核对

如果已经 `READY-RUN`，从新的 WSL 终端重新进入项目、运行骨架和测试；本人操作，同伴只核对。

如果仍是 `BLOCKED-*`，依次说明目标、最后成功处、完整错误、已经检查和下一步，请同伴复述你的断点。

```text
远端：通过 / 未通过 / 证据不足
本地与当前目录：通过 / 未通过 / 证据不足
项目环境：通过 / 未通过 / 证据不足
骨架运行：通过 / 未通过 / 证据不足
给定测试：通过 / 未通过 / 证据不足
证据边界是否说清：
建议补充的唯一证据：
```

## 必须停止并保存状态

- 课堂进入最后 10 分钟；
- 不确定自己是否在项目根目录；
- Agent 建议删除项目、强制重置、重新克隆或修改锁文件；
- 命令要求来源不明的脚本、管理员权限或敏感凭证；
- 同一操作反复失败，却没有得到新证据。

不要只写“跑不起来”。完整错误和明确下一步，也是本周能够继续学习的条件。

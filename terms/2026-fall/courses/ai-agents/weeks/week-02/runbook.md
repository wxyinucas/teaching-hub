# W2｜正确地跑起来

> AI Agents · W2 · 3 × 50 min · 约 25 名零编程基础学生 · 无助教

## 本次课

- 根问题：程序在屏幕上跑起来时，怎样证明它来自正确项目、正确目录和锁定环境，并且能够再次运行？
- 最低出口：从指定入口取得项目，在正确目录恢复锁定环境并运行给定测试，保存 `READY-RUN` 或可接续的 `BLOCKED-*`。
- 硬收口：第三课时第 40 分钟停止展示与排障；末 10 分钟只保存证据边界、当前状态和下一步。

## 第一课时 · 看懂：“在我电脑上能跑”还缺什么

### 0-5 | 把绿色结果重新变成问题
> “在我电脑上能跑”不是可交付结论；我们至少还要定位代码状态和运行状态。

#### 首问

> 同一份代码换一台电脑，为什么不一定得到同一个结果？

#### 不可遗漏

- 程序结果不只由屏幕上的代码决定，还受解释器、依赖和外部配置影响；
- 不同目录或不同版本的代码，也可能暂时显示同一个绿色结果；
- 本周不是学习怎样把报错变绿，而是学习怎样证明自己运行的究竟是什么。

**转场：** 先把这两个状态拆开，避免所有东西都被含混地叫作“环境”。

### 5-13 | 分开全局工具与项目局部环境
> 全局工具回答“我能调用什么”，项目局部环境回答“这个项目按什么条件运行”。

#### 首问

> `git`、`uv` 和某个项目需要的 Python 包，是装在“同一个地方”吗？

#### 不可遗漏

- `git`、`uv` 是系统或用户范围内可调用的工具，可以服务多个项目；
- `pyproject.toml`、`uv.lock` 和项目自己的 Python 环境属于当前项目；
- “全局”与“局部”描述可见范围和归属，不代表高级／低级或可靠／不可靠；
- 固定说“项目局部环境”，避免稍后与“本地仓库”里的 local 混为一谈。

**转场：** 即使代码和依赖相同，程序还可能读到不同的外部信息；这就涉及可见性。

### 13-21 | 用环境变量看见“可见性”
> 环境变量是运行时的外部输入；关键问题是“谁在什么时候看得见它”。

本段只让学生接触概念，不要求记忆命令，也不讲永久配置。

#### 演示前状态

- 使用教师 Bash 终端，不让学生逐机操作；
- 示例变量固定为无敏感信息的 `COURSE_MODE`；
- 不读取或展示真实 token、Cookie、`.env` 或其他个人配置。

#### 完整演示

先让学生预测每一步能否看到 `fixture`，再逐条执行：

```bash
unset COURSE_MODE
printenv COURSE_MODE
COURSE_MODE=fixture printenv COURSE_MODE
printenv COURSE_MODE
command -v uv
```

预期画面依次是：空、`fixture`、再次为空，最后显示本机 `uv` 的路径。只解释两点：

1. `COURSE_MODE=fixture` 只对紧随其后的那个进程可见；
2. 终端能找到 `uv`，是因为 shell 会在 `PATH` 指定的范围内寻找它。

不展开 `export`、启动文件、系统级持久化或密钥配置。

#### 固定退路

现场终端异常时，直接展示下面的预期记录，不排查个人 shell：

```text
（空）
fixture
（空）
/.../uv
```

**转场：** 现在把工具、项目环境和可见范围放进两种常见的 Python 管理方式。

### 21-32 | 用 uv 与 conda 比较环境怎样归属
> conda 偏向“管理一个命名环境”，uv 偏向“恢复并运行一个项目”；本课只实践 uv 路线。

不现场安装 conda，也不让学生同时维护两套路线。

#### 首问

> 为什么有的人说“进入 conda 环境”，我们却经常说“在这个项目里运行 uv”？

#### 不可遗漏

- conda 通常以命名环境为中心，环境可以独立于某个项目目录；
- uv 更贴近以项目为中心的组织方式：依赖写入 `pyproject.toml`，版本由 `uv.lock` 固定，环境通常跟随项目；
- conda 激活后会改变当前终端看到的 Python；`uv run` 则可以明确要求在当前项目环境中执行；
- 两者都能实现隔离与复现，不能简化成“conda 是全局、uv 是局部”；
- 本课程统一使用 uv，是为了路线短、恢复快、项目边界清楚，不是给工具排绝对高下。

若仍有时间，只补充一句：conda 还能统一管理许多非 Python 依赖；不展开包格式或科学计算环境配置。

**转场：** 环境解决“怎样运行”，但我们还没有解决“究竟运行哪一份代码”。

### 32-45 | 从 local、remote 引出版本控制
> Git 负责回答“本地代码怎样变化”，remote 负责回答“认可的版本在哪里共享”；Git 不等于 GitHub。

本段只建立场景和心智模型，不演示 `pull`、分支或合并。

#### 场景顺序

沿同一个课程项目依次增加需要：

1. 我在自己电脑上修改了一份文件；
2. 我想知道今天到底改了什么，并在出错时找回昨天的版本；
3. 我想让教师和同学取得我认可的同一个版本。

前两项引出版本控制与本地 Git 仓库；第三项引出 remote。强调 Git 在断网时仍然能够记录本地版本，GitHub 只是承载远端仓库的一种服务，远端也不会自动与本地同步。

#### 术语边界

- **项目局部环境／全局工具**：描述运行条件的归属；
- **本地仓库／远端仓库**：描述代码与版本记录的位置。

**转场：** 最后把代码位置、代码版本、项目环境和外部输入重新拼成一张图。

### 45-50 | 重建一张可信运行地图
> 可信运行要同时定位代码、版本、项目环境和可见输入；下一课时把这四问变成自己机器上的证据链。

45–47 分钟由学生独立写下，不点名讨论：

```text
代码在哪里：
运行的是哪一版：
由哪个项目环境运行：
本例是否还有只在运行时可见的外部信息：
```

47–49 分钟由教师给出固定对应关系：本地／远端定位代码，Git 定位版本，项目局部环境定位解释器与依赖；若程序使用环境变量，它说明当前进程可见的外部输入。49–50 分钟只说收口句并转入课间，不用前段超时吞掉这一分钟。


## 第二课时 · 做成：在自己的状态上运行

### 0-10 | 说明唯一任务和停止边界
> 统一任务与停止条件以后，下一段只完成个人运行。

课前放行必须确认 `draft.md` 中五项技术入口已经替换进 `guide.md` 并经过干净环境实测。

学生可直接沿指南操作，也可把指南中的简短 Prompt 交给 Agent。Agent 建议删除、重置、重新克隆、改锁文件或更换包管理器时，立即停止。

### 10-40 | 学生完成，教师按故障类别巡查
> 每个人都留下五类运行证据，或一个可继续处理的真实断点。

学生依次取得或更新项目、进入正确目录、恢复环境、运行骨架并运行给定测试。教师只按四类问题巡查：

```text
PATH | GIT / NET | UV | RUN / TEST
```

同类问题阻塞 5 人以上才暂停全班统一说明。完成者可核对同伴证据，但不代替同伴输入命令。

### 40-50 | 保存 `READY-RUN` 或 `BLOCKED-*`
> 本节以 `READY-RUN` 或 `BLOCKED-*` 按时结束，第三课时再交给同伴核对。

停止新的安装、下载和随机排障。`READY-RUN` 至少定位远端、本地目录、项目环境、骨架运行和测试结果；证据不足时按指南保存最后成功处、完整错误、已检查项和下一步。

## 第三课时 · 说清：让另一人能够核对

### 0-8 | 示范一次 90 秒说明
> 统一说明格式以后，同伴只需按同一顺序核对。

教师用固定次序示范：来源、目录、环境、运行与测试证据、证据边界。受阻状态则说明目标、最后成功处、完整错误和下一步。

### 8-35 | 两人互相复现或核对断点
> 每个人都得到一条同伴意见，并能指出自己仍缺少什么证据。

- `READY-RUN`：本人从新终端进入项目并重跑；同伴只按清单核对；
- `BLOCKED-*`：本人展示断点；同伴复述“已确认什么、还缺什么、下一步是什么”；
- 不代输命令，不把“我觉得没问题”写成证据。

### 35-50 | 抽样讨论并完成本周收口
> 每个人都为可复现运行签字，W3 从这条经核对的基线开始修改。

教师预选两份成功状态和一份受阻状态；没有合适样本就使用预制案例。第 40 分钟停止展示，末 10 分钟保存：

```text
状态：READY-RUN / BLOCKED-*
远端与本地目录：
项目环境：
运行与测试证据：
这些证据能够证明：
这些证据仍不能证明：
同伴核对：
下一步：
```

本周不进入版本提交、远端写入、Agent 修改或平台连接。

## 临场取舍

- 慢了 · 删什么：第一课时删 conda/uv 的扩展优劣，只保留组织差异与课程选型；后两课时删预制故障和全班展示，保住正确目录、锁定环境、运行／测试证据与最后十分钟收口。
- 快了 · 做什么：从新终端独立复现，或识别一个错误目录也出现绿色结果的预制故障；不提前进入 W3。
- 坏了 · 怎么退：使用保留 Git 信息的教师项目副本和离线环境完成同构核对，同时如实保留个人设备的 `BLOCKED-*`。

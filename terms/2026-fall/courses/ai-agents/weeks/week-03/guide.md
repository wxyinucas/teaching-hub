# W3 学生行动指南：让 Agent 做一次受控修改

> 本页用于课前准备，以及第二、三课时的操作与核验。你不需要手写全部代码，但必须知道任务范围、实际 diff、测试证据和最终保存的版本。

## 课前准备

- 保存 W2 的 `READY-RUN` 或真实 `BLOCKED-*`；
- 确认能够登录自己的 GitHub 账号，并准备课程选定的本地 Agent 所需账号；
- 不把密码、token、`.env`、账户信息或其他凭证交给 Agent 或写入项目；
- 等待教师发布 fork/远端配置路线、Agent 配置路线、本周唯一任务、允许文件、禁止文件、测试命令与 fixture 观察命令。

不要求在课前完成 fork、远端配置或 Agent 安装；这些状态会在第一课时内建立并核验。入口尚未发布时，不要让 Agent 自行猜测或替换工具。

## 第一课时｜建立个人工作起点

### 1. 建立并核验三个位置

按教师任务卡完成个人 fork，并把现有 W2 本地项目配置为：

```text
upstream = 教师课程仓库
local    = 当前本地项目
origin   = 本人的 GitHub fork
```

随后运行：

```bash
pwd
git remote -v
git status --short --branch
```

不要凭名称猜测；逐项核对任务卡公布的教师地址、个人地址和本地项目根目录。配置失败时保存完整错误，不删除 W2 项目，也不重新克隆来掩盖问题。

### 2. 建立并核验本地 Agent

只使用教师发布的一条安装、登录和健康检查路线。在课程项目根目录启动 Agent，让它先回答：

```text
你当前读取的是哪个目录？请只读取项目并复述 W3 任务入口，暂时不要修改任何文件。
```

目录或任务入口不正确时先停止。到教师规定的收口时间仍未成功，记录 `BLOCKED-AGENT`，课堂中使用教师预制 diff 继续学习审查；这不等于已经完成 Agent 配置。

### 3. 写下本次接受条件

```text
本次唯一目标：
允许 Agent 修改：
明确禁止修改：
给定测试：
我只有在什么条件下才接受：
```

## 第二课时｜完成一次受控修改

### 1. 核对起点

在课程项目根目录运行：

```bash
pwd
git status --short --branch
git remote -v
uv run pytest
```

确认当前目录、W2 测试、`origin` 和 `upstream` 都符合教师任务卡。无法解释的旧修改必须先停止。

### 2. 写下任务边界

```text
本次唯一目标：
允许 Agent 修改：
明确禁止修改：
给定测试：
我只有在什么条件下才接受：
```

任务卡没有允许的修改，默认不允许。

### 3. 给 Agent 一条简短 Prompt

```text
请先阅读 W3 任务卡和当前项目，复述目标、允许修改的文件和验收命令。等我确认后完成这个小修改，只改允许范围。

完成后不要提交，先告诉我改了什么，展示 diff，并运行任务卡指定的测试。需要越界就停下问我。
```

先核对 Agent 的复述；目标、范围或测试有一项不准确，就先修正，不让它开始修改。

### 4. 人工检查全部修改

Agent 停止后运行：

```bash
git status --short
git diff --name-only
git diff --stat
git diff
```

逐项回答：

```text
改动文件是否全部在允许范围：
哪一处 diff 对应任务目标：
有没有顺手修改依赖、测试入口或公共代码：
有没有我无法解释的修改：
```

### 5. 运行并解释测试

运行任务卡指定的测试，再选择其中一个填写：

```text
测试名称：
它给程序什么输入：
它期待什么结果：
实际结果：
它支持什么判断：
它没有覆盖什么：
```

测试通过但 diff 越界，仍然选择 `HOLD`。

### 6. 决定是否保存版本

```text
决定：ACCEPT / HOLD / BLOCKED
理由：
还缺少的证据：
```

只有 `ACCEPT` 才按任务卡暂存允许文件。不要使用 `git add .`。暂存后先运行：

```bash
git diff --cached --name-only
git diff --cached
```

确认无误后，使用教师给定的 commit 信息并 push 到个人 `origin/main`。push 失败时保留本地 commit 与完整错误，不强制 push。

## 第三课时｜观察、展示与核验

### 1. 运行 fixture

运行教师任务卡中的唯一观察命令，核对输出明确包含：

```text
execution_mode=fixture
```

它支持课程数据形状与处理链检查，不证明已经连接真实 Longbridge、数据来自真实市场或策略将来盈利。

### 2. 准备五项展示内容

```text
1. 我交给 Agent 的任务：
2. Agent 实际修改：
3. 我接受、拒绝或修正：
4. diff、测试、commit/push 与 fixture 证据：
5. 证据仍不能证明什么，我的决定：
```

同伴只需要找到一处关键 diff、一个能够解释的测试、一个可定位的版本和一项尚未得到证明的内容。

## 本周完成状态

### `ACCEPT`

```text
完成程度：complete
发布决定：ACCEPT
当前 commit：
push 结果：
观察模式：fixture
我能解释的测试：
本周证据支持：
本周证据不能支持：
下一步：
```

### `HOLD`

任务可能已经运行完成，但范围、diff 或证据不足。写清缺少哪一项，不为取得完成标签直接提交。

### `BLOCKED-*`

```text
状态码：
当前阶段：
最后一个成功检查点：
实际执行的命令：
完整错误或观察：
当前改动文件：
已经检查：
下一步：
是否涉及密码、token 或个人信息：否
```

可使用 `BLOCKED-ENTRY / REMOTE / AGENT / SCOPE / TEST / PUSH / OBSERVE / OTHER`。

## 必须停止并保存状态

- Agent 准备修改任务范围外文件、锁文件、测试入口或公共代码；
- Agent 建议删除失败测试、强制重置、强制 push 或不可逆删除；
- Agent 索取密码、token、账户信息或要求读取 `.env`；
- 当前工作区包含自己无法解释的修改；
- 课堂进入本课时的硬收口时间；
- 同一操作反复失败，却没有得到新证据。

`BLOCKED-*` 能让课堂按时收口，但不等于通过门槛 0。

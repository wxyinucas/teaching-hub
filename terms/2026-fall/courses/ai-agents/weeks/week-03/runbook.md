# W3｜Agent 建完项目以后，凭什么保留？

> AI Agents · W3 · 3 × 50 min · 约 30 名学生，按零编程基础设计 · 无助教

## 本次课

- 根问题：当 Agent 从一份任务说明生成了整个项目，人怎样用范围、diff、公开测试和实际运行决定是否保留？
- 最低出口：从新的正式仓库独立开始，用课程脚本建立自己的 `students/sXX/`；让 Cline 只在 `system/` 中生成最小 uv 项目，运行教师区中的 5 个公开测试及一组正常／失败输入，检查全部 diff，填写本周报告，并留下 `ACCEPT / HOLD / BLOCKED-AGENT` 及相应证据。
- 硬收口：第二课时第 47 分钟停止 Agent 生成，第三课时第 40 分钟停止个人操作与展示；只有 `ACCEPT` 才 commit/push，参考实现与恢复基线只能在展示讨论结束后揭示。

## 第一课时 · 讲：先看懂共同工作台、Agent 服务链与验收合同

### 0-12 | 把 VS Code 定为全班共同工作台
> 本段结束时，学生能够指出 VS Code 中五个固定位置及各自职责；下一段再拆开 Agent 背后的四层服务。

教师打开已经试跑过的 W3 示例工作区，只指认位置，不演示逐项点击：

1. **文件资源管理器**：确认当前项目有哪些文件、目录层级是否正确；
2. **编辑器**：阅读任务、测试和代码；
3. **集成终端**：确认当前目录并运行项目命令；
4. **源代码管理／差异视图**：看哪些文件改变，以及每一行怎样改变；
5. **Cline 对话面板**：给 Agent 上下文、看行动提议并决定是否授权。

扩展管理只在安装 Cline 时作为入口，不成为课后要记住的“第六个位置”。全班统一使用 VS Code，不同时维护其他编辑器路线。

明确 W3 与 W2 解耦：本周从新的正式仓库 `https://github.com/wxyinucas/ai-agents-project` 独立开始，不复用 W2 目录、环境或完成状态。VS Code 始终从仓库根打开；实现命令进入本人的 `students/sXX/system/` 后运行。教师用同一个窗口来回定位教师合同、个人系统、一条命令、一次 diff 和一段 Agent 对话，让学生口头说出“应该去哪里看”。

**收口：** 全班能用同一组位置名称描述屏幕；明确 W3 有独立仓库、独立起点；下一段只回答 Cline 调用模型时各层分别负责什么。

### 12-25 | 拆开 IDE、插件、API 服务商与模型
> 本段结束时，学生能够把“在哪工作、谁代为行动、请求发给谁、谁生成回答”分成四层；下一段据此判断权限与密钥边界。

用一条固定链路建立共同语言：

```text
VS Code（IDE）
→ Cline（Agent 插件）
→ API 服务商（账号、额度、请求入口）
→ 模型（生成判断与内容）
```

- **IDE** 组织工作区、编辑器、终端和 diff，本身不是模型；
- **插件** 把工作区上下文交给模型，并把读文件、写文件、运行命令等行动带回本机；
- **API 服务商** 负责连接、账号、额度与计费入口，不等于某一个固定模型；
- **模型** 生成回复和行动建议，换模型不等于换工作区或换插件。

课堂主线冻结为 **VS Code + Cline**。Cline 中可用的免费模型是默认入口；已经具备条件的学生可以把 **DeepSeek API** 作为低价增强，但它不构成通关条件，也不值得占用全班时间排查充值、区域或额度问题。

只用一张对照图认识另外两种形态：Codex 是可独立使用的 GUI Agent，Claude Code 是终端中的 TUI Agent。二者本周只作选学认知，不现场安装、不另开操作支线，也不替代指定的 Cline 路线。

**收口：** 随机请学生把一个故障归到四层之一；冻结本周唯一主线及免费／低价入口；下一段把“能调用”与“可以授权”分开。

### 25-36 | 冻结权限与密钥边界
> 本段结束时，学生能在授权前说清 Cline 将读取、修改、执行或联网做什么；下一段再把这些边界落实到项目合同。

教师依次展示四类行动提示，学生先翻译、后决定：

- **读文件**：只读取当前工作区，为复述任务取得上下文；
- **写文件**：Agent 只可以修改本人的 `students/sXX/system/**`；本人周报告由学生自己填写；
- **运行命令**：只运行能够说清作用、且属于建项目或验收的命令；
- **联网**：Cline 请求模型、uv 取得依赖可能需要网络，但生成的 `market-check` 本身不得联网。

不打开全局自动批准。看到 Agent 越出本人 `system/`，试图修改根 `README.md`、`course/**`、`common/**`、根 `.gitignore`、`students/README.md`、其他学生目录或本人周报告，或者读取环境变量、执行不可逆命令、实现未来功能，立即拒绝并回到合同。

密钥只放在对应服务商的安全设置入口，不粘贴进对话、终端命令、项目文件、`.env`、截图或提交。默认免费模型不要求学生为了本课临时购买 API；选择 DeepSeek API 的学生自行承担账号与额度准备，课堂只核对“是否可用”，不展示或收集 key。若密钥意外出现在屏幕或文件中，先停止任务并撤销密钥，不继续演示。

**收口：** 每名学生能说出“一次授权的对象、范围和理由”；密钥与项目边界已经冻结；下一段阅读公开合同，不讨论实现写法。

### 36-50 | 把 brief 与 5 个公开测试读成验收合同
> 本段结束时，学生能从 starter 说出成功、失败和禁止事项；下一课时只按这份合同让 Agent 行动。

教师展示正式仓库的完整 starter；顶层先把责任分成三个区域：

```text
course/
└── week-03/                     # 教师给定的本周合同
    ├── PROJECT_BRIEF.txt
    ├── data/sample_prices.csv
    ├── tests/
    │   ├── fixtures/
    │   └── test_project_contract.py
    ├── report-template.md
    └── init-student.sh
common/                           # 教师公共区；以后逐步增加
students/                         # 每个人自己的持续项目
README.md                         # 教师维护的仓库说明
.gitignore
```

课程脚本运行后，一个学生只得到：

```text
students/s07/
├── system/                      # 唯一持续演化的实现
└── weeks/week-03/report.md      # 本周责任记录
```

特别指出：`system/` 起点没有 `pyproject.toml`、实现代码或 `uv.lock`。Agent 的任务是只在这里补成名为 `quant-lab`、使用 Python 3.12.x、pandas 和 pytest 的最小 uv 项目，并提供：

```bash
uv run --locked market-check <CSV 文件路径>
```

成功输出必须稳定报告 `execution_mode=fixture`、排序后的 symbols、rows、start、end 和 `DATA_CHECK=PASS`；文件不存在或缺少必需列时必须清楚失败、包含 `DATA_CHECK=FAIL` 并返回非零状态。根 `README.md`、`course/**`、`common/**`、根 `.gitignore`、`students/README.md` 和其他学生目录全部只读；不得增加联网、Longbridge、策略、订单、账户、网页、数据库或未来功能空壳。

公开测试从学生的 `system/` 外部验收它：

```bash
cd students/s07/system
uv run --locked pytest -q ../../../course/week-03/tests
```

公开测试不是参考实现，而是从项目外部保存五次可重复检查：

1. 个人 `system/` 中的 uv 项目声明、Python 范围、pandas、pytest 与锁文件正确；
2. `sample_prices.csv` 报告可见事实；
3. 另一份正常 fixture 得到不同结果，防止硬编码样例答案；
4. 逐一缺少 `timestamp`、`symbol` 或 `close` 时，都要说出缺少的字段并明确失败；
5. 文件不存在时明确失败。

全部测试从一开始公开，本周没有隐藏测试或 CI。教师已经从同一 starter 试跑：Agent 生成约 3 分钟，随后得到 `5 passed`；因此课堂时间优先留给 VS Code、安装登录、授权和人工审查，不把生成代码本身安排成主体。参考实现此时保持隐藏。

**收口：** 学生能复述“教师给什么、公共区归谁、Agent 只改哪里、周记录放哪里、验收命令从哪里运行”；第一课时停止在合同，不提前生成代码。

## 第二课时 · 做：从个人 fork 到一次受控生成

### 0-12 | fork、clone、初始化个人区，再从根目录打开
> 本段结束时，每名学生要么拥有一个由课程脚本建立的个人区，并从正确仓库根打开 VS Code，要么留下真实入口阻塞；下一段只处理 Cline 可用性。

学生从正式仓库建立个人 fork，再把**自己的 fork** clone 到一个新的本地目录。进入仓库根后，把 `s07` 替换为教师分配的公开代号，只运行一次初始化脚本：

```bash
bash course/week-03/init-student.sh s07
```

成功时只认四行输出：

```text
STUDENT_INIT=PASS
student=s07
system=students/s07/system
report=students/s07/weeks/week-03/report.md
```

脚本若报告代号格式错误或目录已存在就停止：它不会覆盖已有学生目录。确认成功后仍从**仓库根目录**运行：

```bash
code .
```

教师不逐页导航，只守住六项检查：集成终端当前目录是新仓库根目录，`origin` 指向学生自己的 HTTPS fork，分支是 `main`，`git config --get user.name` 与 `git config --get user.email` 有明确结果，个人 `system/` 与本周报告已经创建，其他学生目录未被触碰。邮箱优先使用学生从自己 GitHub 设置页复制的 `noreply` 地址，不替学生猜测。出现 W2 文件、嵌套仓库或无法解释的修改就停止，不靠重新 clone 掩盖原因。

本周只把最终接受版本 push 到个人 `origin`。不配置第二个远端，不向教师仓库提交 PR，也不把 W2 是否完成当成入口条件。

**收口：** 可继续者已经用 VS Code 打开正确的新仓库、核验 `origin`，并得到自己的 `system/ + report.md`；未进入者保存实际地址、目录和错误，不侵占下一段的 Cline 收口时间。

### 12-28 | 安装 Cline，并建立唯一可用会话
> 本段结束时，Cline 必须能在当前工作区回应；否则立刻标记 `BLOCKED-AGENT`，下一段转为跟随审查而不继续安装。

学生通过 VS Code 扩展入口安装教师屏幕指定的 Cline，打开 Cline 面板并完成所需登录。默认选择当前可用的免费模型；已经提前准备好 DeepSeek API 的学生可以使用它，但不在现场比较多个服务商或反复换模型。

健康检查只问三件事：Cline 是否连接成功，它识别的工作区是否为刚打开的 `ai-agents-project`，它能否准确指出本人的 `students/sXX/system/`。此时不要求修改文件或运行项目命令。

第 28 分钟统一停止安装、登录、额度与 API 排障。仍不能得到有效回应者记录：

```text
状态：BLOCKED-AGENT
卡在：安装 / 登录 / 服务商 / 模型 / 工作区
已经成功到达：
屏幕上的实际错误：
```

这些学生从下一段起跟随教师投影或一名已就绪同伴，继续完成“复述合同、看权限、审查 diff、解释测试”的学习任务；这能保留课堂进度，但不能冒充本人已经完成 Agent 配置或生成。

**收口：** 全班按 `READY-AGENT / BLOCKED-AGENT` 明确分流，停止安装支线；下一段所有人共同做只读自解释。

### 28-37 | 先让 Agent 只读并复述合同
> 本段结束时，可操作学生必须亲自核对一次 Agent 的任务复述；下一段只有复述准确者才授权生成。

给 Cline 一个只读请求，意思固定为：

```text
只读取当前工作区，不修改文件，也不运行命令。
我的公开代号是 sXX。请区分 course、common 和 students 三个区域，确认你只能修改
students/sXX/system，并根据 course/week-03 中的 brief 与公开测试复述：
目标、成功输出、两类失败、保护范围、禁止实现的范围，以及从 system 中运行的验收命令。
```

学生必须对照 `course/week-03/PROJECT_BRIEF.txt` 和 `course/week-03/tests/test_project_contract.py` 自己核验，不能把 Agent 的摘要当作合同。漏掉本人目录、非零退出、`--locked`、教师／公共区只读或“程序不得联网”中的任何一项，就先纠正；包结构和函数拆分不是合同内容，不要求全班一致。

`BLOCKED-AGENT` 学生使用教师投影的同一回复完成核对，并明确标注“观察他人会话”，不得把这段记录写成自己的 Agent 已可用。

**收口：** 留下一份经人核对的合同复述和一处可能的 Agent 遗漏；下一段只授权合同范围内的最小生成。

### 37-50 | 授权最小生成，并在第 47 分钟硬停止
> 本段结束时，只冻结现有工作区与 Agent 状态，不为追求绿色结果越过第 47 分钟；下一课时统一用证据判断。

复述准确后，学生授权 Cline 按 brief 完成最小 uv 项目。允许它只在本人的 `students/sXX/system/` 中新增实现、项目声明、锁文件和必要包文件，并从该目录运行建项目与验收命令；明确禁止修改本人周报告、教师区、公共区和其他学生目录，不运行 `git add/commit/push`，不实现未来功能。每次权限提示仍需先说明动作与范围，再批准或拒绝。

教师巡视只看四个信号：Agent 是否只改本人 `system/`，是否想修改保护区，是否借失败测试扩大任务，以及学生是否读过权限提示。试跑表明纯生成约 3 分钟；本段多出的时间用于理解命令、等待依赖与及时叫停，不用于“顺便完善”项目。

第 47 分钟全班停止发送新提示和接受新修改。最后 3 分钟只保存：

```text
git status --short
Agent 声称完成了什么：
实际新增或修改了什么：
状态：READY-REVIEW / BLOCKED-AGENT
```

生成未完成、会话中断或只能借看他人结果者保持 `BLOCKED-AGENT`。不要复制同伴项目来伪造自己的完成状态；下一课时仍可跟随同一套证据审查。

**收口：** 第 47 分钟以后没有新增代码；每人留下可定位的工作区状态；第二课时不作 `ACCEPT`，不 commit/push。

## 第三课时 · 展示与讨论：用证据作出保留决定

### 0-13 | 先从仓库根检查完整改动范围
> 本段结束时，学生必须证明 Agent 只改了本人 `system/`，并能说清每个变化文件的职责；下一段才检查行为是否满足合同。

`READY-REVIEW` 学生先确认终端位于仓库根。以下 `s07` 只是示例，必须替换为教师分配的本人 `sNN`：

```bash
pwd
git rev-parse --show-toplevel
git status --short
git diff --cached --name-status
git diff --cached
git add --intent-to-add .
git diff HEAD --name-status
git diff HEAD
git diff HEAD -- README.md course common .gitignore students/README.md
```

先用两条 cached diff 检查 Agent 是否擅自暂存内容；正常应为空，非空就不能跳过。`--intent-to-add` 只让所有全新文件出现在 diff 中，不会暂存其内容；随后完整查看文件清单和 diff。每一条变化路径都必须位于 `students/s07/**`，最后一条保护区 diff 必须为空；其他学生目录也不能出现变化。此后 `git status --short` 中的 ` A` 是审查标记，不代表内容已暂存，选择 `HOLD` 时可以保留。

学生同时在 VS Code 源代码管理面板中逐个打开文件，回答：为什么需要它，哪处实现对应 brief，有没有凭证、联网、未来功能、被绕过的测试或无法解释的内容。此时本人报告应仍是初始化脚本复制的空白模板；报告由学生稍后亲自填写，不属于 Agent 实现。

**收口：** 留下完整文件清单和关键 diff；只要出现越界、已暂存内容或不可解释文件，下一段仍可收集行为证据，但最终只能选择 `HOLD`。

### 13-27 | 再进 system 运行三类证据，并解释一个测试
> 本段结束时，个人项目必须留下公开测试、正常运行和预期失败三类原始证据，并能解释其中一个测试；下一段才作出发布决定。

从仓库根进入自己的唯一系统目录，依次运行：

```bash
cd students/s07/system
uv sync --locked
uv run --locked pytest -q ../../../course/week-03/tests
uv run --locked market-check ../../../course/week-03/data/sample_prices.csv
uv run --locked market-check ../../../course/week-03/tests/fixtures/missing_close.csv
echo "FAILURE_EXIT=$?"
cd ../../..
```

公开测试的完整成功画面是 `5 passed`。正常输入应报告 fixture、AAPL、4 行、起止时间并以 `DATA_CHECK=PASS` 结束；缺列输入应说明缺少 `close`、包含 `DATA_CHECK=FAIL` 并以非零状态结束。紧接着的 `FAILURE_EXIT` 必须非 0；这是程序成功拒绝错误输入，不应为了“全绿”改成零状态。测试还覆盖第二组正常数据、三种必需列分别缺失和不存在路径。

命令失败、输出不符或锁文件不能恢复时如实保存，不重新召回 Agent 现场追修。再从五个公开测试中任选一个，用六句话解释：测试名称、输入或起点、程序动作、预期结果、实际结果，以及它支持／不能支持的判断。例如，第二份正常 fixture 能反驳只为 AAPL 样例硬编码，但不能证明所有 CSV 都有效。

`BLOCKED-AGENT` 可以跟随教师或同伴核对同样的证据，但记录必须注明证据不来自自己的实现。

**收口：** 每人拥有三类可读结果或准确缺口，以及一个可复述的测试解释；任何失败都带入下一段判断，不用临时修改抹掉。

### 27-40 | 展示证据，作出 ACCEPT／HOLD，再决定是否发布
> 本段结束时，每人必须先公开自己的判断，再让符合条件的 `ACCEPT` 保存版本；第 40 分钟后才允许看参考实现。

两人一组各用两分钟展示：任务边界、一个关键 diff、一个公开测试、正常／失败运行和自己的初步决定。核验者只追问一项证据缺口。教师随后抽取一份范围清楚的 `ACCEPT` 和一份“测试虽绿但仍 `HOLD`”的理由，全班比较判断依据，不现场修复代码。

只有同时满足以下条件才可 `ACCEPT`：

- Agent 只修改本人 `system/`，教师／公共区、根保护文件和其他学生目录未变；
- 5 个公开测试通过，正常与失败命令符合合同；
- 学生检查过全部 diff，能说明新增文件和至少一个测试。

状态分界只看“有没有自己的可审查候选实现”：Agent 在硬停止前没有为本人仓库产生一份可完整检查的候选实现，包括安装／登录／工作区失败、会话中断或生成未完成，统一记为 `BLOCKED-AGENT`；候选实现已经存在，但范围、测试、证据或发布条件不够，统一记为 `HOLD`。

所有人先亲自完成本人 `students/sXX/weeks/week-03/report.md`。`ACCEPT` 学生再只暂存已逐项检查的 `students/sXX/system/` 与这份报告，复核 staged diff 后 commit，并 push 到个人 `origin/main`。第一次 push 若出现 VS Code 的 GitHub 登录提示，只走浏览器授权，不输入 GitHub 密码或把 token 交给 Agent。不得使用完成标签替代检查，也不向教师仓库提交 PR。`HOLD` 不 commit；`BLOCKED-AGENT` 保持原状态，不能因看懂他人实现改记为本人完成。push 受阻时保留本地 commit 和真实错误。

第 40 分钟停止个人操作与展示。此时仍不启用 CI，不接 Longbridge，不增加隐藏测试或未来功能。

**收口：** 展示和讨论已在不知道参考实现的前提下完成；每人留下 `ACCEPT / HOLD / BLOCKED-AGENT`、理由及 commit/push 状态；现在才进入基线揭示。

### 40-50 | 揭示参考实现，并给每个人可恢复的起点
> 本段结束时，每名学生都明确 W4 将从自己的已接受版本还是教师恢复基线继续；参考实现不追认本周未完成状态。

教师此时才发布“参考实现 + 可恢复基线”，并用同一份 brief 和五个公开测试说明：

- 教师版本只是满足合同的一种实现，不是唯一代码形状；
- 每个测试分别约束哪项外部行为，为什么测试通过仍要检查 diff；
- 教师为什么愿意接受这个版本，以及它仍没有解决哪些未来问题。

不要求学生在最后 10 分钟覆盖个人工作区。`ACCEPT` 可以带自己的版本进入 W4；`HOLD` 或 `BLOCKED-AGENT` 可以在课后按发布说明切换到教师基线，但要保留第一次尝试与原决定，并写明为什么采用基线。采用基线不是失败，冒充独立完成才会破坏证据链。

最终记录固定为：

```text
本周状态：ACCEPT / HOLD / BLOCKED-AGENT
公开测试：5 passed / 实际结果
正常输入：PASS / 实际结果
失败输入：FAIL（非零）/ 实际结果
我能解释的测试：
commit/push：仅 ACCEPT 填写
W4 起点：自己的已接受版本 / 教师恢复基线
```

**收口：** 所有人都带着真实状态和可继续的 W4 起点离开；后续实现继续在同一份个人 `system/` 上增长，周次只增加责任记录。W3 到此结束，不追加 CI、Longbridge 或教师仓库 PR。

## 临场取舍

- 慢了 · 删什么：删 Codex／Claude Code 的口头补充、第二个全班案例和自由问答；不合并或拖延 12 个分段收口，必须保住正确工作区、`BLOCKED-AGENT` 硬停、只读复述、5 个测试、正常／失败运行、全部 diff、一个测试解释和先判断后揭示。
- 快了 · 做什么：让学生比较自己的结构与另一位同学的结构，或指出哪个公开测试能抓住硬编码；不提前揭示参考实现，也不扩展到 CI、Longbridge、额外 API 或新功能。
- 坏了 · 怎么退：Cline 到第 28 分钟仍不可用就标记 `BLOCKED-AGENT` 并跟随投影／同伴审查；依赖下载失败保留完整错误并使用教师已生成项目观察证据；GitHub push 失败保留本地 commit；测试失败直接进入 `HOLD`。任何退路都保留来源标签，不把借看的证据冒充个人完成。

#### 开场：这份原始记录必须留下来（约 8 分钟）

**照念：** “这是一次分析的原始方案。我们想试另一组参数，并修正第三个数，但原始方案必须保留。先给新方案起个名字，看看这件事有没有完成。”

在编辑器建立下面的记录，先只运行到两次 print。这里 alpha 是一个数，data 是三个数的列表；只说明读懂本例所需的写法：方括号取指定字段或位置，Python 的位置 2 是第三项。

~~~python
source = {"alpha": 0.05, "data": [10, 20, 30]}
variant = source
print("原始：", source)
print("新方案：", variant)
~~~

停住，暂不运行修改。请学生押答案：改 variant 后，source 会保持原样吗？依据是什么？把两种预测留在旁边。

~~~python
variant["alpha"] = 0.01
variant["data"][2] = 99
print("原始：", source)
print("新方案：", variant)
~~~

两行都成为 {"alpha": 0.01, "data": [10, 20, 99]}。先停在失败处，不立刻宣布“用深复制”。

**追问：** “我操作的每一行都写着 variant。究竟是两份数据一起变了，还是我们一直只有一份？仅凭这两行内容，分得出来吗？”

#### 第一条证据：看起来一样，是不是同一份（约 10 分钟）

继续当前会话，另建一份内容相等的记录。

~~~python
same_content = {"alpha": 0.01, "data": [10, 20, 99]}
print(source == variant, source is variant)
print(source == same_content, source is same_content)
~~~

实际结果是 True、True 和 True、False。让学生先指出：哪一项证据能够区分刚才的两种解释？

**照念：** “is 检查是否同一个对象，== 检查值是否相等。两个问题不同；内容相等，不能证明只有一份对象。”

此时才画第一张关系图；A、B 是讲解用编号，由 is 核验关系，不是伪造的内存地址。

~~~text
source ──┐
         ├→ 字典对象 A：alpha 为 0.01，data 为 [10, 20, 99]
variant ─┘

same_content → 字典对象 B：alpha 为 0.01，data 为 [10, 20, 99]
~~~

**暂定解释：** variant = source 建立了名字到同一对象的绑定，没有复制字典。沿 variant 修改这个字典，沿 source 也会看到改变。

**下一问：** “那么两个名字指向同一个对象，只要改其中一个，另一个就一定跟着变吗？”

#### 反例：整数不跟着变，列表却跟着变（约 15 分钟）

把复杂记录缩成一个整数。先执行到第一次身份检查，确认 x is y 为 True，再预测并执行后续操作。

~~~python
x = 1000
y = x
print(x is y)
x += 1
print(x, y, x is y)
~~~

结果为 True，随后是 1001、1000、False。请学生修正刚才的暂定解释：两个名字原先指向同一整数，为什么 y 没跟着变？

~~~text
操作前：x ─┐
           ├→ 整数对象：1000
        y ─┘

操作后：x ───→ 整数对象：1001
        y ───→ 整数对象：1000
~~~

**照念：** “原来的整数没有被改成 1001。计算得到另一个整数结果，x 改了指向，y 留在原处。Python 的赋值仍是建立绑定，不能把这次结果解释成赋值自动复制了整数。”

再缩成开场用过的三个数。这次额外留下第三项的旧引用；先预测两行输出。

~~~python
l = [10, 20, 30]
other = l
saved_item = l[2]
l[2] += 1
print(l, other, l is other)
print(saved_item, l[2], saved_item is l[2])
~~~

两份列表都显示 [10, 20, 31]，身份比较为 True；留下的整数仍是 30，新位置是 31，身份比较为 False。

让学生在关系图上只改发生变化的箭头：l 和 other 仍指向同一列表；列表第三个位置改为关联 31；saved_item 仍关联 30。

**追问：** “列表的内容变了，是否等于里面的整数对象被改了？”

**落点：** 可变性是对象的性质。修改列表所含的关联会改变列表内容；整数对象本身没有被原地改写。判断一次操作，必须指明哪一层。

#### 回到现场：第一种修复该改什么（约 7 分钟）

把整数与列表的证据带回开场：variant 的名字没换指向，原始字典及其 data 列表被修改了。因此“换一个名字”没有兑现“独立方案”的承诺。

**变量与内存位置只在这里补一句：** “Python 的名字通过绑定关联系统中的对象。id(source) 取得对象身份；在 CPython 中它对应对象地址，并不是名字 source 自己的固定地址。”

需要核验时，在修改前保存 before_id = id(source)，保留 source 的引用，再修改内容、比较 id(source) == before_id。对象身份可以没变，内容已经变了；不要求学生识记地址数值，不研究缓存与垃圾回收。

让学生各补完一句：“开场失败，因为……；接下来我想试……。”接住“真正复制一次”的建议，暂不替它担保。

**悬念留到下一课时：** “好，我们这次明确复制。只要 source is variant 变成 False，原始记录就安全了吗？”

### 50-100 | 我已经复制了，为什么还会串？

> 外层身份不同，只排除了外层共享；需要独立修改的内层仍须检查。

#### 第二次尝试：这回确实复制了（约 10 分钟）

从干净记录重来，不接着修改上一课时已经污染的 source。先运行到身份检查，学生确认结果为 False；暂不运行两次修改。

~~~python
source = {"alpha": 0.05, "data": [10, 20, 30]}
variant = source.copy()
print(source is variant)
~~~

**押答案：** “外层已经是两个字典。现在两项修改是否都会留在新方案里？”

同一会话先只执行 alpha 修改并查看两份记录，再执行 data 修改。

~~~python
variant["alpha"] = 0.01
print("改参数后：", source, variant)
variant["data"][2] = 99
print("改数据后：", source, variant)
~~~

alpha 成功隔离，data 却再次污染原始记录。不要把两行结果一次掠过：让学生指出第二次失败和第一次失败究竟哪里不同。

**下一问：** “外层都不同了，什么东西仍然是同一个？”

#### 顺着箭头再查一层（约 8 分钟）

~~~python
print(source is variant)
print(source["data"] is variant["data"])
~~~

结果为 False、True。先请学生补图，再核对：

~~~text
source  → 字典 A → alpha：0.05
                 → data ─┐
                         ├→ 列表 L：[10, 20, 99]
variant → 字典 B → data ─┘
                 → alpha：0.01
~~~

**照念：** “我们复制了字典，却保留了它指向原来 data 列表的关系。复制到哪一层，独立就只到哪一层。”

借这张图说明字典两种操作的差别：variant["alpha"] = 0.01 替换字典 B 中的值关联；variant["data"][2] = 99 沿关联找到共享列表，修改它第三个位置的关联。

追问另一种修复，不立即运行答案：“如果先给 variant 换一份独立的 data 列表，再修改第三项，source 的那条路径还会通向它吗？”让学生画出预计的第二个列表。

此处只形成修复方向。具体如何复制、重建或使用 deepcopy，留给学生与 Agent 选择；不要求所有数字也拥有不同身份。

#### 一个看似通过的检查，为什么也会被骗（约 7 分钟）

**照念：** “为了证明原始记录没变，有人建议先保存 before，改完后再比较。这个检查会不会把开场的错误也放过去？”

从干净状态运行；揭示比较结果前先让学生预测。

~~~python
source = {"alpha": 0.05, "data": [10, 20, 30]}
before = source
variant = source
variant["data"][2] = 99
print(source == before)
print(source)
~~~

检查为 True，但原记录已污染。请学生在图里加入 before，指出为什么这个“证据”没有保住原来的内容。

**落点：** 保留旧引用适合问“是否仍是那个对象”；要问“内容是否保持”，必须保存独立的基准。已知输入的预期结果来自任务条件，不能从候选实现反推。

本题可以使用独立写出的已知记录，或对给定普通字典使用 copy.deepcopy 保存内容快照。快照必须覆盖会被修改的 data 列表；只做 before = source.copy() 会重演第二次失败。

**下一问：** “我们不仅要修好程序，还要让验收本身不被同一种共享关系骗过去。”

#### 换一种语言，先前的预测还成立吗（约 5 分钟）

把刚才的问题缩回“三个数，两个名字，改第三个数”。先预测普通 R 向量的结果，再展示教师已核验的操作。

~~~r
a <- c(10, 20, 30)
b <- a
b[3] <- 99
print(a)
print(b)
~~~

a 保持 10、20、30，b 成为 10、20、99。普通 R 向量通常通过修改时复制呈现值语义；不说赋值当场必然完整复制内存，也不把 identical 当成 Python is。

**追问取舍：** “我们可以直接把 Python 列表的预测搬过来吗？”Python 的共享便于有意让多处观察同一份修改，也让独立方案需要额外隔离；R 普通向量使另一绑定观察到的值更容易保留，复制由实现管理。

Bash 再给一个短对照，只有普通文本赋值：

~~~bash
a=cat
b="$a"
a=cut
printf '%s %s\n' "$a" "$b"
~~~

输出 cut cat；这里把展开后的文本赋给 b，没有建立本例 Python 列表式的共享可变对象关系。不同语言的写法相近，实际操作必须按各自模型判断。对照之后立即回到 Python 任务。

#### 把两次失败交给探索：怎样才算独立方案（约 7 分钟）

出示教师准备的函数壳。这里只把签名读作本次实验的输入输出，不提前展开函数与作用域体系。

~~~text
make_variant(source, alpha, index, replacement)

输入：含 alpha 和 data 的普通字典；data 为数字列表。
输入结构、数值与 index 均合法。
输出：修改后的独立方案。
~~~

用同一个已知任务读懂验收：source 为 {"alpha": 0.05, "data": [10, 20, 30]}；传入 alpha=0.01、index=2、replacement=99；结果应为 {"alpha": 0.01, "data": [10, 20, 99]}。

| 承诺 | 学生要取得的证据 |
| --- | --- |
| alpha 与 data[index] 更新，其他内容保留 | 与独立预期结果比较 |
| 原始记录保持原内容 | 与调用前的独立快照比较 |
| 两个字典以及两份 data 列表独立 | 分别做 is 检查 |
| 后续修改结果不影响 source | 再改一次，重新查看原记录 |
| 两次产生的结果互不干扰 | 两次调用，再修改其中一份 |

**接手任务：** “你们已经见过两种失败。先与 Agent 写测试，证明测试能拒绝它们；然后再让 Agent 实现一份真正独立的方案。实现方式由你们选择，验收看承诺是否兑现。”

#### 临场备用：只在主线已收住时追加

- 慢了：不展开地址细节与复制 API；保住开场失败、整数反例、is／==、浅复制再失败、独立快照和自由探索。探索至少留出第三课时，不用备用例填满讲解。
- 快了：从下列短例选择一个，继续回答根问题；不轮流展示全部例子。
- 坏了：用课前真实输出和关系图推进预测、判读与解释。实验包仍未可靠时保存受阻状态，不将材料标为课堂冻结。

**备用一：如果这次修改的是文字呢？** 先预测字符串字符赋值能否成功；失败例单独执行。

~~~python
s = "cat"
s[1] = "u"
~~~

实际为 TypeError。再从干净状态取得不同文本，检查新旧关系：

~~~python
s = "cat"
old = s
s = s.replace("a", "u")
print(s, old, s is old)
~~~

结果为 cut、cat、False。字符串不可原地替换字符；这里取得不同字符串结果，再改变 s 的绑定。回问整数反例，不另开字符串操作清单。

**备用二：相同结果，能否隐藏不同关系？** 两段分别从 a = [1, 2]、b = a 开始，对照 a += [3] 与 a = a + [3]。a 的结果相同；前者原地扩展内置列表，b 跟着变化、身份仍相同；后者建立新列表并重新绑定 a，b 保留旧列表。出现赋值语法，不等于前后绑定关系一定改变。

**备用三：能否同时改变内容和绑定？** 先共享 a、b 指向 [1, 2]，再 a[0] = 9，随后 a = a + [3]。b 留在内容已改变的旧列表，a 指向新列表；要求学生画两步图并取得身份与内容证据。

**备用四：变量的地址一定这样解释吗？** 教师用已核验的 C 普通 int 示例显示 x += 1 可更新同一变量存储位置，再对照 Python 不可变整数与名字绑定。C 的变量地址和 Python 对象身份是不同观察层次；只用“源码 → 编译产物 → 运行”说明本例工具链，学生不本地编译执行。

#### 只改新方案，原记录也变了

> 给同一份记录增加一个名字，没有兑现“保留原件、独立修改”的承诺。

- **说清任务。**

  - **照念：** “这是一次分析的原始方案。我们想换一个参数、修正第三个数，但原始记录必须保留。”
  - 指认输入：alpha 是一个参数，data 是三个数的列表；本题只使用这两个字段。
  - 方括号取字段或位置；Python 从 0 编号，位置 2 是第三项。

- **运行初始记录。** 在当前 Python 会话执行：

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  variant = source
  print("原始：", source)
  print("新方案：", variant)
  ~~~

  - 看：两行内容相同，都是原始参数与三个数。
  - 先问：“我只改 variant，source 会保持原样吗？”

- **再运行修改。**

  ~~~python
  variant["alpha"] = 0.01
  variant["data"][2] = 99
  print("原始：", source)
  print("新方案：", variant)
  ~~~

  - 看：两行都成为 `{"alpha": 0.01, "data": [10, 20, 99]}`。
  - 问：“是两份数据一起变了，还是我们一直只有一份？只看内容能分清吗？”

- **转场：** 先不修程序，找一条能区分这两种解释的证据。

#### 内容相等，是不是同一对象？

> is 比较对象身份；== 比较值。这两种检查回答不同问题。

- **另建一份内容相等的记录。** 接着刚才的会话执行：

  ~~~python
  same_content = {"alpha": 0.01, "data": [10, 20, 99]}
  print(source == variant, source is variant)
  print(source == same_content, source is same_content)
  ~~~

  - 第一行：`True True`；内容相等，也是同一对象。
  - 第二行：`True False`；内容相等，但不是同一对象。

- **用身份结果补图。**

  ~~~text
  source ──┐
           ├→ 字典 A：alpha 为 0.01，data 为 [10, 20, 99]
  variant ─┘

  same_content → 字典 B：alpha 为 0.01，data 为 [10, 20, 99]
  ~~~

  - A、B 是图中的对象编号，不是内存地址。
  - `variant = source` 把另一个名字绑定到同一字典，没有复制字典。
  - 问：“原先指向同一对象，只要对其中一个名字操作，另一个就一定跟着变吗？”

#### 整数没跟着变：名字重新绑定

> 整数对象没有原地改变；计算得到另一个结果，再改变 x 的绑定。

- **先建立两个名字。**

  ~~~python
  x = 1000
  y = x
  print(x is y)
  ~~~

  - 看：`True`，此刻指向同一整数。
  - 先问：“接下来 x 加一，y 会变成多少？”

- **运行并对照。**

  ~~~python
  x += 1
  print(x, y, x is y)
  ~~~

  - 看：`1001 1000 False`。

  ~~~text
  操作前：x ─┐
             ├→ 整数对象：1000
          y ─┘

  操作后：x ───→ 整数对象：1001
          y ───→ 整数对象：1000
  ~~~

  - **照念：** “原来的整数没有被改成 1001。x 改了指向，y 留在原处。”
  - 赋值仍是建立绑定；y 没变，不能解释成赋值自动复制了整数。

#### 列表跟着变：对象内容被修改

> 列表的第三个位置换了关联；列表本身仍是同一个对象，旧整数也没有被原地改写。

- **建立列表，并留下第三项的旧引用。**

  ~~~python
  l = [10, 20, 30]
  other = l
  saved_item = l[2]
  print(l is other)
  ~~~

  - 看：`True`。
  - 先问：“修改第三项后，other 与 saved_item 各会看到什么？”

- **修改，再看两层结果。**

  ~~~python
  l[2] += 1
  print(l, other, l is other)
  print(saved_item, l[2], saved_item is l[2])
  ~~~

  - 第一行：`[10, 20, 31] [10, 20, 31] True`；两个名字仍看到同一列表。
  - 第二行：`30 31 False`；旧整数仍是 30，列表第三项关联到 31。
  - 在图上保留 l／other 到列表的箭头，只更新第三个位置；saved_item 仍指向 30。
  - 问：“列表内容变了，是否等于里面的整数对象也被改了？”

#### 回到原记录：这次改了哪一层？

> 判断一次操作，要同时指出名字的绑定、被操作的对象和发生变化的内容。

- `variant = source`：增加名字绑定，字典未复制。
- `variant["alpha"] = 0.01`：替换共享字典中 alpha 的值关联。
- `variant["data"][2] = 99`：找到共享列表，替换第三个位置的关联。
- source／variant 仍指向同一字典；沿两条路径都能看到修改。
- 问：“如果明确复制字典，source is variant 变成 False，原记录就安全了吗？”

### 50-100 | 复制以后，为什么仍会污染原记录？

> 查清复制到哪一层，并用独立基准检查原始内容是否保持。

#### 复制以后，先分别改两项

> 外层字典不同，参数修改被隔离；内层列表仍可能共享。

- **从干净记录重新开始。**

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  variant = source.copy()
  print(source is variant)
  ~~~

  - 看：`False`；这次确实是两个字典。
  - 先问：“现在改 alpha、改 data，是否都会只影响 variant？”

- **只改 alpha，先看一次。**

  ~~~python
  variant["alpha"] = 0.01
  print("原始：", source)
  print("新方案：", variant)
  ~~~

  - 原始 alpha 仍为 `0.05`；新方案为 `0.01`，data 都还是 `[10, 20, 30]`。

- **再改 data，看第二次。**

  ~~~python
  variant["data"][2] = 99
  print("原始：", source)
  print("新方案：", variant)
  ~~~

  - 两份记录的 data 都成为 `[10, 20, 99]`；alpha 仍各自保持。
  - 问：“第一次连参数都一起变；这一次只有 data 一起变。什么仍然共享？”

#### 沿关系再查一层

> 浅复制建立了新的外层字典，却保留了指向原来 data 列表的关系。

- **分别检查外层与内层。**

  ~~~python
  print(source is variant)
  print(source["data"] is variant["data"])
  ~~~

  - 看：`False`、`True`。

- **按结果补图。**

  ~~~text
  source  → 字典 A → alpha：0.05
                   → data ─┐
                           ├→ 列表 L：[10, 20, 99]
  variant → 字典 B → data ─┘
                   → alpha：0.01
  ~~~

  - 改 alpha：只替换字典 B 的关联。
  - 改 data 的第三项：沿字典 B 的关联找到共享列表，修改其内容。
  - **照念：** “复制到哪一层，独立就只到哪一层。”
  - 问：“给 variant 换一份独立的 data 列表，再改第三项，source 还会通向它吗？”
  - 在图中增加第二个列表，画出预计的关系；实现方式留到后面的任务。

#### “原件没变”的检查也可能被骗

> 旧引用可以检查身份；保存原始内容，需要独立的基准。

- **先预测这一条检查。** 从干净记录重来：

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  before = source
  variant = source
  variant["data"][2] = 99
  print(source == before)
  print(source)
  ~~~

  - 看：`True`，但 data 已成为 `[10, 20, 99]`。
  - 将 before 画到同一字典上：它也看到了污染后的内容，没有保留旧值。

- **换成浅复制快照，再试一次。**

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  before = source.copy()
  variant = source
  variant["data"][2] = 99
  print(source == before, source["data"] is before["data"])
  ~~~

  - 看：`True True`；外层快照不同，data 仍共享，检查又漏掉了污染。

- **用独立基准拒绝同一个错误。**

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  expected_source = {"alpha": 0.05, "data": [10, 20, 30]}
  variant = source
  variant["data"][2] = 99
  print(source == expected_source)
  ~~~

  - 看：`False`；预先写下的原始内容没有跟着改变，检查发现了污染。
  - 已知输入可以独立写出预期；一般输入可对本题普通对象用 `copy.deepcopy` 保存内容快照。
  - 快照必须覆盖会被修改的 data；候选程序自己的输出不能充当预期答案。

- **转场：** 程序可能共享错误，验收也可能共享同一种错误。接下来把“独立”写成明确的承诺。

#### 换一种语言，赋值的行为相同吗？

> 围绕同一个小问题，比较实际行为；相近的写法不保证相同语义。

- **R：两个名字，改第三个数。** 先预测，再运行教师已准备的 R 会话：

  ~~~r
  a <- c(10, 20, 30)
  b <- a
  b[3] <- 99
  print(a)
  print(b)
  ~~~

  - a：`10 20 30`；b：`10 20 99`。
  - 普通 R 向量通常通过修改时复制呈现值语义；不说赋值时必然完整复制内存。
  - R 的 `identical` 不等于 Python 的 `is`，这里不借它判断是否同一对象。
  - Python 列表的共享便于多处观察同一修改；需要独立方案时，必须额外隔离。R 普通向量使另一绑定观察到的值更容易保留，复制由实现管理。

- **Bash：普通文本赋值。** 在 Bash 运行：

  ~~~bash
  a=cat
  b="$a"
  a=cut
  printf '%s %s\n' "$a" "$b"
  ~~~

  - 看：`cut cat`。
  - b 接收的是当时展开后的文本；本例没有 Python 列表式的共享可变对象关系。
  - 问：“把 Python 列表的预测原样搬到 R 或 Bash，会可靠吗？”

#### 把独立方案写成验收条件

> 先确定修改结果和隔离要求，再与 Agent 选择实现方式。

- **出示函数壳，读一次输入输出。**

  ~~~text
  make_variant(source, alpha, index, replacement)

  source：含 alpha 与 data 的普通字典，data 是数字列表。
  其余三个参数：新 alpha、要改的位置、替换值。
  本题输入结构、数值与 index 都合法。
  返回：修改后的独立方案。
  ~~~

  - 函数名是本次任务的固定入口；参数是交给它的输入，返回值是我们要检查的结果。
  - 本周不展开函数与作用域体系。

- **用已知输入确定结果。**

  ~~~text
  原始：{"alpha": 0.05, "data": [10, 20, 30]}
  参数：alpha=0.01，index=2，replacement=99
  结果：{"alpha": 0.01, "data": [10, 20, 99]}
  原件：仍是 {"alpha": 0.05, "data": [10, 20, 30]}
  ~~~

- **指认五条验收承诺。**

  - 更新指定参数与位置，其他内容保留；对照独立预期。
  - source 保持原始内容；对照调用前的独立快照。
  - 结果字典与 source 不同，结果的 data 与原 data 不同；分别用 is 检查。
  - 再修改结果，不影响 source。
  - 调用两次产生两份结果，修改其中一份不影响另一份。

- **交给学生，先测试。**

  ~~~text
  请先读实验说明和 make_variant 函数壳，与我一起写测试，暂不修改实现。
  先检查给定输入的结果、原始内容、外层身份和 data 身份。
  解释预期答案从哪里来；保存原始内容时，不要留下共享的可变数据。
  分别运行教师的直接共享、浅复制两份故障，指出哪项断言拒绝了它们。
  给我实际输出，等我检查后再实现。
  ~~~

  - 第二课时约第 37 分钟开始探索，最迟第 40 分钟交接。
  - 学生先做一次调用的检查，再增加后续修改与两次调用；用实验包的已核验入口运行，不改 W3 项目或正式 remote。

### 100-150 | 用测试核验：这次独立，以后也不会串吗？

> 用同一份测试拒绝故障、接受修复，再检查约定的后续操作与两次调用。

#### 先让测试拒绝两种已知错误

> 测试的依据来自公开承诺；先证明它能发现已经见过的污染。

- **看测试怎样比较。** 在已加载候选 make_variant 的测试中，展示一次调用的验收骨架：

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  expected_source = {"alpha": 0.05, "data": [10, 20, 30]}
  expected_result = {"alpha": 0.01, "data": [10, 20, 99]}

  result = make_variant(source, 0.01, 2, 99)

  assert result == expected_result
  assert source == expected_source
  assert result is not source
  assert result["data"] is not source["data"]
  ~~~

  - 前两条检查值：修改结果与原始内容。
  - 后两条检查身份：外层字典与需要独立修改的列表。
  - 预期记录各自建立，不从 source 或 result 直接赋值得到。

- **分别运行两份故障。** 每份从新的已知输入开始，运行同一组测试。

  - 直接共享：结果可能符合预期，但原始内容已变；外层与内层身份也不满足要求。
  - 浅复制：外层身份不同、alpha 保持，但原 data 被污染，内层身份仍相同。
  - 找实际失败的输入、断言和输出；一次运行可能停在第一条失败断言，不要求一屏同时报出所有问题。
  - 有运行报错或没有收集到测试，先确认测试是否真的执行；不把环境错误当作共享关系的反例。

- **只读解释真实失败。**

  ~~~text
  这是刚才的真实测试输出：……
  先对照任务说明，指出输入、预期值、实际值和失败断言。
  再找到候选实现对应的位置，解释共享发生在哪一层。
  不要修改测试或实现，每次只解释这一处，等我确认。
  ~~~

#### 根据同一份测试实现修复

> 实现方式可以不同，公开承诺与预期答案保持不变。

- **再委托实现。**

  ~~~text
  根据刚才核验过的测试，实现 make_variant。
  可以按层级复制、重建容器，或对本题普通对象使用 deepcopy。
  不要修改测试的预期值；运行同一份测试，给我实际改动与结果。
  指出哪里建立了独立关系，哪里修改指定内容；等我核对后再继续。
  ~~~

- **本人重跑，核对实际文件。**

  - 在自己的实验目录执行已核验的测试入口，对照 Agent 工具记录。
  - 打开实际实现，找到独立字典、独立 data 与指定修改的位置。
  - 查看 diff：修的是实现，不是把失败断言删掉或改成接受污染。
  - 用同一组输入再看 source 与 result：各自内容、外层身份与内层身份都符合承诺。
  - 不要求源码中出现某个 copy 词；不要求不可变数字也拥有不同身份。deepcopy 是本题的一种可行方法，不是所有系统的统一解法。

#### 通过一次以后，再修改一次

> 当前值正确，未必排除了后续才会触发的共享。

- **后续修改：结果再变，原件仍保持。** 使用当前实现，从干净输入执行：

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  expected_source = {"alpha": 0.05, "data": [10, 20, 30]}
  result = make_variant(source, 0.01, 2, 99)

  result["alpha"] = 0.02
  result["data"][0] = -1
  assert source == expected_source
  ~~~

  - 看 source 仍是原始记录；把这项检查加入测试。
  - 只看首次返回值，可能漏掉尚未触发的共享关系。

- **两次调用：修改一份，不影响另一份。** 再从干净输入执行：

  ~~~python
  source = {"alpha": 0.05, "data": [10, 20, 30]}
  expected_source = {"alpha": 0.05, "data": [10, 20, 30]}
  first = make_variant(source, 0.01, 2, 99)
  second = make_variant(source, 0.02, 0, -1)

  assert first is not second
  assert first["data"] is not second["data"]

  first["alpha"] = 0.03
  first["data"][1] = 777
  assert second == {"alpha": 0.02, "data": [-1, 20, 30]}
  assert source == expected_source
  ~~~

  - 看 second 仍保留自己的结果，source 仍保留原始内容；把这项检查加入测试。
  - 再换教师准备的另一组合法输入，确认没有把本例结果写死。

#### 主线完成后的备用反例

> 只在主线已收住时选一个，继续区分绑定与内容；不挤占学生测试与收尾时间。

- **字符串能原地改字符吗？** 先预测，单独运行失败例：

  ~~~python
  s = "cat"
  s[1] = "u"
  ~~~

  - 看：TypeError。从干净状态换成返回新文本的操作：

  ~~~python
  s = "cat"
  old = s
  s = s.replace("a", "u")
  print(s, old, s is old)
  ~~~

  - 看：`cut cat False`；原字符串未改写，s 绑定到新结果。回到整数反例。

- **a 的结果相同，对 b 的影响相同吗？**

  - 两段分别从 `a = [1, 2]; b = a` 开始，执行 `a += [3]` 与 `a = a + [3]`。
  - 前者原地扩展内置列表，b 看到变化，身份仍相同；后者新建列表并重新绑定 a，b 保留旧列表。
  - 问：“出现赋值语法，是否就能断定绑定一定改变？”

- **可以先改内容，再改绑定吗？**

  - 从 `a = [1, 2]; b = a` 开始，依次执行 `a[0] = 9`、`a = a + [3]`。
  - 看：b 留在已改内容的旧列表，a 指向新列表。画两步关系图，并核对身份与值。

- **变量地址和对象身份，是同一观察层吗？**

  - 保留旧引用后比较 `id(source)`：同一对象的内容可以改变，身份保持。
  - Python 的名字绑定对象；CPython 的 id 对应对象地址，不是名字 source 自己的固定地址。
  - 教师用已核验的 C 普通 int 示例，对照 `x += 1` 更新同一变量存储位置；只展示“源码 → 编译产物 → 运行”，学生不安装工具链。

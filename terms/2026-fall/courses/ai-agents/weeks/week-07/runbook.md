# W7｜调试：找到第一次偏差

> 3 × 50 min · 给定输入复现错误，在关键位置看实际状态，修复后重跑原用例和变式。

## 知识地图

- **Road map：复现 → 定位 → 修复 → 复测**
  - 复现：固定输入，对照实际结果与预期。
  - 定位：数组的 `shape`、筛选掩码、沿哪个 `axis` 聚合，以及上一层实际传进了什么。
  - 修复：从运行时看到的证据出发，改导致偏差的一处。
  - 复测：原用例通过，再用变式查修复是否只对当前输入有效。

## 本次课 · 用调试器看清程序怎么走到错误结果

### 0-50 | 在结果出错之前停一次

> 跑通一次断点调试，每个人给同桌展示一段修改过程。

- [ ] 课前：在学生仓库 `week-07/` 执行 `uv sync --locked`，确认能 `import numpy as np`。用浏览器 Jupyter 打开 `demo.ipynb`，选择 **W7 Python 3.12**。启用顶部小虫图标，通过 **View → Debugger Panel** 打开面板，设断点并运行调用格，看一次变量和调用栈。学生在 VS Code 打开 `exercises.ipynb` 时，选择本周 `.venv`，用 **Debug Cell** 操作。
- [ ] 课前：两台电脑演练。学生机分享练习目录，授课机加入。学生机改一个 cell 并重跑，授课机确认能看到更新后的输出。核对投影字号。
- [ ] 课前：保留演示副本的错误版本和两组输出。Live Share 连不上或输出不同步时，切回教师 Notebook 继续。

#### 两组数据，为什么都算出 6？

*翻页：两组数据，为什么都算出 6？*

- **0–5 分钟**。预期 `6, 3`，实际 `6, 6`。先让大家各自判断：均值函数算错了，还是第二次传错了数据？
- *翻页：一次调试的四步*。说完切到 `demo.ipynb`。

#### 停在第二次调用

- **5–15 分钟**。浏览器 Jupyter 中普通运行一次复现。启用顶部小虫图标，打开 **View → Debugger Panel**，给均值函数的 `return` 行下断点，选中「报告」格，点击 **▶ 运行**。VS Code 的对应步骤保留在 Notebook 折叠区。
- 第一次停住看 `values`，点 **Continue** 到第二次，还是 `[1, 5, 12]`。点调用栈中报告函数那一层，指认第二次调用的实参。
- 改一处、退出调试、重跑定义和检查。对照 `6, 6 → 6, 3`。补一句：`print` 能把值记下来，断点能在这一刻同时看变量和调用者。

#### 学生动手：有效的 0 消失了

- **15–30 分钟**。打开 `exercises.ipynb`。先看数组起步说明，确认 `shape` 表示各轴长度，`np.nan` 代表缺失，布尔数组可以筛选数据。
- 题一。输入 `[0, np.nan, 6]`，看 `valid` 和筛选后的数组。应留下 `[0, 6]`，均值为 `3`。全缺失与空数组返回 `np.nan`。
- 进展快的接题二。矩阵每行是一次观测，每列是一个传感器。先看 `raw.shape`、`offset.shape`，再看调用者把偏移扩成了哪种形状。

#### 检查点：让同桌看见你怎么改的

- 选题一，全班两人一组轮流演示，共约 5 分钟。每人打开自己的 Notebook，展示**复现输入 → 停点和实际值 → 改动 → 重跑结果**。
- 还没修好就复现故障，展示已经查过的一个停点，说下一步要看什么。你抽看几组。
- 从中挑一位同学用 Live Share 重跑一次，约 5 分钟。调试面板不便共享时，让他把关键变量打印在 cell 输出里。你接过解释，其余同学在本机核对。

### 50-100 | 数组形状和索引，怎样决定结果

> 先看中间数组的形状和含义，再判断聚合方向与索引是否一致。

#### 每个窗口求和，为什么结果长度都不对

- 题三。`[2, 7, 4, 1]` 按宽度 `2` 形成三行窗口，`windows.shape` 为 `(3, 2)`，预期 `[9, 11, 5]`。先给独立调试时间。
- 看 `windows` 的每行代表什么，`sum(axis=...)` 消掉的是哪个维度。把实际结果的长度也与预期比较。
- 完成后核对窗口宽度 `1` 和等于数据长度的情况。

#### 迟到的旧数据覆盖了新数据

- 题四。编号、时间、读数分别保存在三个等长数组。看排序得到的 `order`，三个数组是否使用同一组索引，再看每个编号第一次出现的位置代表新记录还是旧记录。
- 检查点选题四，两人轮流展示约 5 分钟。全班复测改变到达顺序的同一组记录，核对时间与读数的对应关系。
- 提前完成者进题五。需要集中讲解时，挑一个共同卡点讲完，留时间让大家重跑。

### 100-150 | 先区分原因，再分别验证

> 追一段试步轨迹，再用两个不同用例拆开两个独立的故障。

#### 步长在减半，试点却越走越远

- 题五。`f(x) = ||x - [3, -1]||²`，起点 `[0, 0]`、方向 `[6, -2]`。正确试点依次为 `[12, -4]`、`[6, -2]`、`[3, -1]`，目标值为 `90, 10, 0`。
- 先预测第二次试点，再观察步长和试步起点。这里保留顺序试步循环，向量运算一次更新两个坐标。
- 换起点和方向再验。只在原输入通过的修正还要继续检查。

#### 修好组内结果，整体均值为什么仍然错

- 题六。二维数组每行一组，`np.nan` 补齐缺失位置。分别跑「含有效的 `0`」和「组大小不同」两个用例，观察 `valid`、每组计数和总和。改一处后重跑两项，判断哪条证据变了。
- 组均值正确以后，再看整体按组平均还是按有效观测加权。A 组 `[0, np.nan, 6]`、B 组 `[12, np.nan, np.nan]`，组均值为 `3, 12`，整体应为 `6`。
- 检查点选题五或题六，两人轮流展示约 5 分钟。要求展示一个运行时看到的值，以及它排除了哪一种猜测。
- 提前做完就用题六后面的变式。让学生自己造一个输入，使两种看似正确的汇总程序给出不同结果，再解释差异。

# 学习与讲解方法：直观、数学与程序的对应

本文件记录扩散模型自学课的讲解与学习方式；章节范围和专题顺序另见[教材与专题地图](topic-map.md)。通用备课流程仍以 [docs/prep-system.md](../../../../../docs/prep-system.md) 为准。

核心约定：**围绕同一个问题、同一个例子，用直观、数学和程序三种方式表达模型，并解释它们怎样对应。** 直观图示与数学表达共同描述知识；程序部分进一步解释这些数学对象如何被建模、组织和执行。

## 直观解释与数学表达

- **直观解释：为什么这样设计？**
  - 先说明要解决的问题，以及当前表示或方法有什么不足。
  - 用图解释输入、连接、层与输出各有什么作用，结构怎样回应问题。
  - 讨论改动某个部分会怎样影响模型行为，让图承载设计动机。
- **数学表达：怎样把这些作用说准确？**
  - 明确输入、输出、变量、参数与固定量。
  - 写出运算、函数复合及维度关系，把公式中的量指回图中的对象。
  - 说明哪些性质来自模型结构，哪些需要通过参数学习获得；关键结论交代适用条件。
- 图与公式可以来回对照。
  - 用图建立直观，再用数学澄清图中省略的关系；必要时回到图上解释推导的结果。
  - 保持同一小例子贯穿，帮助学习者辨认三种表达中的同一个对象。

## 程序建模：从数学对象到编程抽象

PyTorch 部分先解释程序建模的思路，再介绍具体抽象、接口与代码。除了“公式对应哪一行”，还要回答程序为什么需要这些对象，以及它们分别承担什么职责。

- **表示什么？**
  - 数据、参数、模型、损失和梯度分别用什么表示？
  - 数学中的向量、矩阵和批量样本怎样对应张量及其形状？
- **管理什么？**
  - 模型对象保存哪些参数与状态，怎样组织子模块？
  - 哪些量参与求导，哪些参数交给优化器更新？
- **执行什么？**
  - 调用模型时发生什么计算，运算依赖如何形成？
  - 框架承担哪些工作，学习者仍须明确哪些计算与更新规则？

以简单神经网络为例，可以建立以下对应：

| 数学中的对象或过程 | 程序中的表达 | 需要讲清的关系 |
| --- | --- | --- |
| 输入向量、矩阵与批量数据 | 张量及其形状 | 每个维度代表什么，批量维度怎样进入计算 |
| 权重、偏置 | 被模型管理的可学习参数 | 参数怎样被登记、用于计算并交给优化器 |
| 参数化函数及其复合 | 模型模块与前向计算 | 模块怎样组织状态与计算，多个模块怎样组合 |
| 损失函数 | 根据预测和目标计算出的标量 | 单样本损失与批量汇总怎样对应 |
| 对指定变量求导 | 自动微分 | 对输入还是参数求导，计算图记录了哪些依赖 |
| 根据梯度改变参数 | 优化器更新 | 求梯度与应用更新规则各自完成什么 |

- 数学对象与程序抽象并非机械的一一配对。
  - 一个模块可以表示一层、一组运算或整个网络。
  - 模块的组织与一次执行形成的计算图应分别解释。
  - 能运行代码之后，还要能判断程序中的对象与执行过程是否符合数学意图。

## 在 section 与 topic 中怎样安排

- **一个 section 对应一次课，用小标题辅助定位。**
  - T01 起以 `Topic → Section` 组织课程，例如 `T01 S5` 指向本专题第 5 次课的内容；section 编号写作 `S1、S2…`。一次课包含的课时数与具体分钟数按实际情况安排。
  - section 内围绕同一个问题连续讲解，必要的小标题可写 `1、2…`，表示讲解环节，不代表课时；不预设标题数量，也不将每个小标题单独做成阅读或暂停单元。
  - 每个 section 末集中列出复习问题、核对要点、保留的记录、教材回看与下一步，避免在短内容之间反复收尾。
  - 需要中途暂停时，记下 section 与具体标题、已讲清的关系和下次接续。组织方式随试学调整，见 [T01 Section 组织稿](t01-section-plan.md)。
- **section 内做局部对应。**
  - 刚讲清一个层或一项运算，就可以说明它在程序中怎样表示。
  - 按当前问题选用图、公式和代码，不强制每个小节套用三份完整模板。
- **topic 末做整体串联。**
  - 把局部对象组合起来，读懂一次完整的前向计算、训练过程或生成过程。
  - 跟踪数据、参数和随机性怎样流动，说明哪些量在何时改变。
- 专题可以跨多次课，内部保留理解检查点。
  - 例如表示能力与参数学习、去噪训练与生成采样，各自需要讲清，再解释彼此联系。
  - 局部知识尚未理解时，回到相应图示、推导或程序对象补足，再继续串联。

## 材料分工与对照阅读

- **《Understanding Deep Learning》提供主线。**
  - 用来确定核心概念、数学关系和主要推导的依据；章节选择随专题问题调整。
- **《动手学深度学习》提供“另一种解释”。**
  - 对同一个知识点，对照两书的例子、图示、符号和推理顺序。
  - 说明两种解释如何对应，哪一种帮助澄清了当前疑问；有差异时核对假设与适用范围。
  - 对照后由学习者重新组织讲解，不另设一套逐章推进的学习进度。
- **PyTorch 官方材料帮助理解和核对程序表达。**
  - 结合张量、模型定义、自动微分与优化循环，解释编程抽象和使用方式。
- **PRML 与原始论文按问题进入。**
  - PRML 用于核对条件期望、回归损失等需要补充的数学关系。
  - 比较与科研阶段逐步引入原始论文，补充教材没有充分展开的内容。

## 费曼式复述与实践出口

- **指着图讲动机**：为什么需要这个结构，每个部分解决什么问题？
- **指着公式讲关系**：每个量是什么，怎样计算，结论依赖什么条件？
- **指着代码讲对象与执行过程**：对象管理什么，计算怎样发生，哪里求导、哪里更新？
- 三种表达对不上时，把具体疑问记下来，再决定补哪一节、换哪一种解释或加入什么材料。

第一轮实践目标仍是读懂、改动、解释和核对小规模 CPU 代码。独立手写的熟练度可另设专题；Python、Jupyter 与运行环境放在以后共同确定的独立目录中。具体讲解先落实到台本，再按用途派生 Slides 与 Guide。
